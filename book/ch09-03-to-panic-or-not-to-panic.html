The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

예제, 프로토 타입 코드 및 테스트

몇 가지 개념을 설명하기 위해 예제를 작성할 때 강력한 오류 처리 코드를 포함하여 예제를 덜 명확하게 만들 수 있습니다. 예에서 unwrap와 같은 메서드에 대한 호출은 응용 프로그램이 오류를 처리하도록 하는 방식의 자리 표시자로 의미되며 나머지 코드가 수행하는 작업에 따라 다를 수 있습니다.

마찬가지로 unwrap 및 expect 메서드는 프로토 타이핑을 할 때 매우 유용하며 오류 처리 방법을 아직 결정할 준비가되지 않았습니다. 프로그램을보다 견고하게 만들 준비가되었을 때 코드에 명확한 마커를 남깁니다.

테스트에서 메소드 호출이 실패하면 테스트에서 기능이 아니더라도 전체 테스트가 실패하기를 원할 것입니다. panic!는 테스트가 실패로 표시되는 방법이므로 unwrap 또는 expect를 호출하면 정확히 발생합니다.

오류 처리 지침

코드가 나쁜 상태로 끝날 수 있을 때 코드 패닉을 갖는 것이 좋습니다. 이러한 맥락에서, 나쁜 상태는 잘못된 값, 모순된 값 또는 누락된 값이 코드에 전달될 때와 같이 일부 가정, 보장, 계약 또는 불변이 깨진 경우와 다음 중 하나 이상이 있는 경우입니다.

  • 나쁜 상태는 사용자가 잘못된 형식으로 데이터를 입력하는 것과 같이 때때로 발생할 수있는 것과는 달리 예기치 않은 것입니다.
  • 이 시점 이후의 코드는 모든 단계에서 문제를 확인하기보다는이 나쁜 상태에 있지 않은 것에 의존해야합니다.
  • 이 정보를 사용하는 유형으로 인코딩 할 수있는 좋은 방법은 없습니다. 우리는 18 장의 “유형 으로 상태 와 행동 을 암호화 함”에서 의미하는 것의 예를 통해 작업 할 것입니다.

만약 누군가가 여러분의 코드를 호출하고 의미가 없는 값을 전달한다면, 라이브러리의 사용자가 그 경우에 무엇을 하고 싶은지 결정할 수 있도록 오류를 반환하는 것이 가장 좋습니다. 그러나, 계속하는 것이 안전하지 않거나 해로울 수 있는 경우, 최선의 선택은 호출하는 것입니다. panic! 라이브러리를 사용하는 사람에게 코드의 버그를 경고하여 개발 중에 해결할 수 있습니다. 비슷하게, panic! 당신이 당신의 통제 밖에있는 외부 코드를 호출하고 당신이 고칠 방법이없는 잘못된 상태를 반환하는 경우에 종종 적절합니다.

그러나 실패가 예상되면 Result를 반환하는 것이 panic! 호출을 만드는 것보다 더 적절합니다. 예를 들어, 파서가 형식이 잘못된 데이터로 제공되거나 HTTP 요청이 속도 제한에 도달했음을 나타내는 상태를 반환하는 경우가 있습니다. 이러한 경우, Result를 반환하면 호출 코드가 처리 방법을 결정해야 할 것으로 예상되는 가능성이 있음을 나타냅니다.

코드가 유효하지 않은 값을 사용하여 호출하는 경우 사용자를 위험에 빠뜨릴 수있는 작업을 수행 할 때 코드는 값이 먼저 유효하고 값이 유효하지 않은 경우 패닉이 있는지 확인해야합니다. 이는 주로 안전상의 이유로 발생합니다. 유효하지 않은 데이터를 작동하려고하면 코드가 취약점에 노출 될 수 있습니다. 이것은 표준 라이브러리가 외부 메모리 액세스를 시도하는 경우 panic!를 호출 할 때 특정 코드 손상이 발생합니다.

하지만, 모든 함수에서 많은 에러 체크를 하는 것은 거침없고 짜증나는 일입니다. 다행스럽게도, 러스트의 타입 시스템(컴파일러에 의해 수행되는 타입 체크)을 사용하여 많은 수의 체크를 할 수 있습니다. 만약 여러분의 함수가 파라미터로서 특정한 타입을 가지고 있다면, 여러분은 컴파일러가 여러분이 유효한 값을 가지고 있다는 것을 이미 확인했다는 것을 알고 코드의 로직을 진행할 수 있습니다. 예를 들어, 만약 여러분이 타입이 있다면 Option당신의 프로그램이 기대되는 것은 뭔가 보다는 없음. 당신의 코드는 다음 두 경우를 처리 할 필요가 없습니다 Some 그리고 None variants: 확실히 값을 가지는 하나의 케이스만 가질 것입니다. 함수에 아무것도 전달하지 않으려는 코드는 컴파일되지 않으므로 함수는 런타임에 해당 케이스를 확인할 필요가 없습니다. 또 다른 예는 서명되지 않은 정수형을 사용하는 것입니다. u32즉, 매개 변수가 절대 음수가 아님을 보장합니다.

요약

러스트의 오류 처리 기능은 더 강력한 코드를 작성하는 데 도움이 되도록 설계되었습니다. panic! 매크로는 프로그램이 처리할 수 없는 상태에 있다는 신호를 보내고 유효하지 않거나 잘못된 값으로 진행하려고 시도하는 대신 프로세스를 중지하도록 지시할 수 있습니다. Result enum은 러스트의 타입 시스템을 사용하여 코드가 복구될 수 있는 방식으로 작업이 실패할 수 있음을 나타냅니다. Result 코드를 호출하는 코드에 잠재적 인 성공 또는 실패를 처리해야한다고 알려줍니다. 사용 panic! 그리고 Result 적절한 상황에서는 피할 수없는 문제에 직면하여 코드를보다 신뢰할 수있게 만듭니다.

이제 표준 라이브러리가 Option 및 Result 열거형과 함께 제네릭을 사용하는 유용한 방법을 보았으므로 제네릭 작동 방식과 코드에서 사용하는 방법에 대해 설명합니다.
