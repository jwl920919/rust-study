The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

단일 스레드 웹 서버 빌드Build a single-threaded web server

우리는 단일 스레드 웹 서버 작업으로 시작합니다. 시작하기 전에 웹 서버 구축과 관련된 프로토콜에 대한 간략한 개요를 살펴 보겠습니다. 이러한 프로토콜의 세부 사항은이 책의 범위를 벗어 났지만 간단한 개요는 필요한 정보를 제공합니다.

웹 서버와 관련된 두 가지 주요 프로토콜은 HTTP (Hypertext Transfer Protocol)와 TCP (Transmission Control Protocol)입니다. 두 프로토콜 모두 요청 응답 프로토콜입니다. 즉, 클라이언트가 요청을 시작하고 서버가 요청을 수신하고 클라이언트에 응답합니다. 이러한 요청 및 응답의 내용은 프로토콜에 의해 정의됩니다.

TCP는 정보가 한 서버에서 다른 서버로 어떻게 전달되는지에 대한 세부 사항을 설명하지만 그 정보가 무엇인지 지정하지는 않는 하위 수준 프로토콜입니다. HTTP는 요청 및 응답의 내용을 정의하여 TCP 위에 구축됩니다. 다른 프로토콜과 함께 HTTP를 사용하는 것은 기술적으로 가능하지만 대부분의 경우 HTTP는 TCP를 통해 데이터를 전송합니다. 우리는 TCP 및 HTTP 요청 및 응답의 원시 바이트로 작업 할 것입니다.

HTTP 요청에서 더 자세히 보기

HTTP는 텍스트 기반 프로토콜이며 요청은 다음 형식을 취합니다.

Method Request-URI HTTP-Version CRLF
headers CRLF
message-body

첫 번째 줄은 클라이언트가 요청하고있는 것에 대한 정보를 담고있는 요청 줄입니다. 요청 줄의 첫 번째 부분은 클라이언트가이 요청을하는 방법을 설명하는 GET 또는 POST와 같이 사용되는 방법을 나타냅니다. 우리 클라이언트는 GET 요청을 사용했습니다. 즉, 정보를 요청하는 것입니다.

요청 라인의 다음 부분은 /이며, 이는 클라이언트가 요청하는 균일 한 리소스 식별자 (URI)를 나타냅니다. URI는 균일 한 리소스 로케이터 (URL)와 거의 동일하지 않습니다. 이 장에서 URI와 URL의 차이는 중요하지 않지만 HTTP 사양은 URI라는 용어를 사용하므로 여기에서 URI에 대한 URL을 정신적으로 대체 할 수 있습니다.

마지막 부분은 클라이언트가 사용하는 HTTP 버전이며 요청 줄은 CRLF 순서로 끝납니다.CRLF에서 스탠드 for 차량 반납 그리고 라인 피드CRLF 시퀀스는 다음과 같이 쓸 수 있습니다. \r\n, 어디서 \r 상기 반송하는 단계는, A carriage return and \n 선 급식은 입니다. CRLF 시퀀스 요청 라인을 나머지 요청 데이터와 분리합니다. CRLF가 인쇄될 때, 새로운 라인이 시작되는 것을 볼 수 있습니다. \r\n.

지금까지 프로그램을 실행하여 얻은 요청 행 데이터를 보면 GET가 메서드이고 /가 요청 URI이며 HTTP/1.1가 버전임을 알 수 있습니다.

요청 줄 다음에 Host:에서 시작하는 나머지 줄은 헤더입니다. GET 요청은 본문이 없습니다.

다른 브라우저에서 요청을 하거나 127.0.0.1:7878/test와 같은 다른 주소를 요청하여 요청 데이터가 어떻게 변경되는지 확인하십시오.

이제 브라우저가 무엇을 요구하는지 알았으니 몇 가지 데이터를 다시 보내주십시오!

응답 작성하기

클라이언트 요청에 대한 응답으로 데이터 전송을 구현합니다. 응답에는 다음과 같은 형식이 있습니다.

HTTP-Version Status-Code Reason-Phrase CRLF
headers CRLF
message-body

첫 번째 줄은 응답에 사용되는 HTTP 버전, 요청의 결과를 요약하는 숫자 상태 코드 및 상태 코드의 텍스트 설명을 제공하는 이유 문구가 포함 된 상태 줄입니다. CRLF 시퀀스가 헤더, 다른 CRLF 시퀀스 및 응답 본문 인 후.

다음은 HTTP 버전 1.1을 사용하고 200의 상태 코드, OK 이유 구문, 헤더 없음 및 본문이없는 예제 응답입니다.

리팩토링

그 순간, The if 그리고 else 블록은 많은 반복을 가지고 있습니다: 그들은 파일을 읽고 파일의 내용을 스트림에 씁니다. 유일한 차이점은 상태 라인과 파일 이름입니다. 그 차이를 분리하여 코드를 더 간결하게 만들어 봅시다. if 그리고 else status line과 filename의 값을 변수에 할당하는 lines; 그런 다음 코드에서 이러한 변수를 무조건적으로 사용하여 파일을 읽고 응답을 작성할 수 있습니다. Listing 21-9는 대형을 대체 한 후 결과 코드를 보여줍니다. if 그리고 else 블록.

이제 if 및 else 블록은 튜플의 상태 라인 및 파일 이름에 대한 적절한 값만 반환합니다. 그런 다음 19장에서 설명한 것처럼 status_line 및 filename 문에서 패턴을 사용하여 이 두 값을 let에 할당하기 위해 구조 조정을 사용합니다.

이전에 중복된 코드는 이제 if 및 else 블록 외부에 있으며 status_line 및 filename 변수를 사용합니다. 이를 통해 두 경우의 차이를 쉽게 볼 수 있으며, 파일 읽기 및 응답 쓰기 작업을 변경하려면 코드를 업데이트할 장소가 하나만 있음을 의미합니다. Listing 2-9의 코드 동작은 동일할 것입니다.
