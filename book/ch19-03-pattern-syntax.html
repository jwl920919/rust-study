The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

패턴 문법

이 섹션에서는 패턴에서 유효한 모든 구문을 모아 각 구문을 사용하는 이유와 시기를 논의합니다.

리터럴 일치

6장에서 보았듯이, 리터럴과 직접 매칭할 수 있습니다. 다음 코드는 몇 가지 예제를 보여줍니다.

fn main() {
    let x = 1;

    match x {
        1 => println!("one"),
        2 => println!("two"),
        3 => println!("three"),
        _ => println!("anything"),
    }
}

이 코드는 one를 출력합니다. x의 값이 1이기 때문입니다. 이 구문은 특정 구체적인 값을 받는 경우 코드가 동작하도록 할 때 유용합니다.

이름 붙인 변수 일치

이름이 붙은 변수는 어떤 값이든 일치하는 반박 불가능 패턴(irrefutable pattern)이며, 이 책에서 여러 번 사용해 왔습니다. 그러나 match, if let, 또는 while let 식에서 이름이 붙은 변수를 사용할 때는 복잡한 문제가 발생합니다. 이러한 종류의 식은 각각 새로운 스코프를 시작하기 때문에, 이러한 식 내부의 패턴으로 선언된 변수는 모든 변수와 마찬가지로 구조체 외부의 같은 이름의 변수를 가립니다. Listing 19-11에서는 값이 Some(5)인 변수 x과 값이 10인 변수 y를 선언합니다. 그런 다음 값 x에 대해 match 식을 생성합니다. match 암의 패턴과 끝의 println!를 살펴보고, 이 코드를 실행하거나 더 읽기 전에 코드가 무엇을 출력할지 추측해 보세요.

match 표현식이 실행될 때 어떤 일이 일어나는지 살펴 보겠습니다. 첫 번째 매치 암의 패턴은 x의 정의된 값과 일치하지 않으므로 코드는 계속 진행됩니다.

두 번째 match 암의 패턴은 Some 값 내부의 어떤 값이든 일치하는 새로운 변수 y를 도입합니다. match 식 내부의 새로운 스코프에 있으므로, 이것은 처음에 값 10로 선언한 y이 아니라 새로운 y 변수입니다. 이 새로운 y 바인딩은 Some 내부의 어떤 값이든 일치하며, x에는 바로 그런 값이 있습니다. 따라서 이 새로운 y는 x의 Some의 내부 값에 바인딩됩니다. 그 값은 5이므로, 해당 암의 식이 실행되어 Matched, y = 5를 출력합니다.

만약 x이 Some(5) 대신 None 값이었다면, 처음 두 암의 패턴은 일치하지 않았을 것이므로, 그 값은 언더스코어에 일치했을 것입니다. 언더스코어 암의 패턴에서 x 변수를 도입하지 않았으므로, 식의 x는 여전히 가려지지 않은 외부의 x입니다. 이 가상의 경우, match는 Default case, x = None를 출력할 것입니다.

match 표현식이 완료되면 그 스코프가 끝나고, 내부 y의 스코프도 함께 끝납니다. 마지막 println!은 at the end: x = Some(5), y = 10을 출력합니다.

를 만들려면 match 외부의 값을 비교하는 표현식 x 그리고 y기존 변수를 그림자로 만드는 새로운 변수를 도입하는 대신, y 변수, 우리는 대신 일치 가드를 사용해야합니다. 나중에에서 일치 가드에 대해 이야기 할 것입니다. “경기 경비대 와 조건 을 더하다” 무시 섹션.

여러 패턴 매칭하기

match 표현식에서는 패턴 또는 연산자인 | 구문을 사용하여 여러 패턴을 매칭할 수 있습니다. 예를 들어, 다음 코드에서 x의 값을 매치 암과 비교합니다. 첫 번째 암에는 '또는' 옵션이 포함되어 있으며, 이는 x의 값이 해당 암의 값 중 하나와 일치하면 그 암의 코드가 실행됨을 의미합니다:

fn main() {
    let x = 1;

    match x {
        1 | 2 => println!("one or two"),
        3 => println!("three"),
        _ => println!("anything"),
    }
}

이 코드는 one or two을 출력합니다.

..=를 사용하여 값의 범위 매칭 ..=

..= 구문을 사용하면 양 끝값을 포함하는 값의 범위와 매칭할 수 있습니다. 다음 코드에서 패턴이 주어진 범위 내의 값과 매칭되면 해당 팔(arm)이 실행됩니다.

fn main() {
    let x = 5;

    match x {
        1..=5 => println!("one through five"),
        _ => println!("something else"),
    }
}

x가 1, 2, 3, 4, 또는 5인 경우 x 있습니다. 1, 2, 3, 4, 또는 5, 첫 번째 팔(arm)이 매칭됩니다. 이 구문은 | 같은 생각을 표현하는 연산자를 사용하는 것보다 여러 매칭 값에 대해 더 편리합니다. |# 명시해야 할 사항 1 | 2 | 3 | 4 | 5범위를 지정하는 것은 훨씬 더 짧으며, 특히 1과 1,000 사이의 숫자를 매칭하고 싶다면 더욱 그렇습니다!

컴파일러는 컴파일 시간에 범위가 비어 있지 않은지 확인합니다. Rust에서 범위가 비어 있는지 아닌지를 알 수 있는 유일한 타입이 char이고 숫자 값이기 때문에, 범위는 숫자 또는 char 값에서만 허용됩니다.

다음은 char 값의 범위를 사용하는 예입니다.

fn main() {
    let x = 'c';

    match x {
        'a'..='j' => println!("early ASCII letter"),
        'k'..='z' => println!("late ASCII letter"),
        _ => println!("something else"),
    }
}

Rust는 'c'가 첫 번째 패턴의 범위 내에 있으며 early ASCII letter를 출력한다는 것을 알 수 있습니다.

값을 분해하여 분리하기

패턴을 사용하여 구조체, 열거형, 튜플을 분해(destructure)하여 이러한 값의 서로 다른 부분을 사용할 수도 있습니다. 각 값을 차례로 살펴보겠습니다.

구조체

Listing 19-12는 Point 구조체와 x 및 y 필드를 보여 주며, let 문으로 패턴을 사용하여 분리할 수 있습니다.

구조체와 튜플

비구조화 패턴을 혼합하고 중첩하여 훨씬 더 복잡한 방식으로 사용할 수 있습니다. 다음 예제는 튜플 안에 구조체와 튜플을 중첩하고, 모든 원시 값을 비구조화하는 복잡한 예를 보여줍니다.

fn main() {
    struct Point {
        x: i32,
        y: i32,
    }

    let ((feet, inches), Point { x, y }) = ((3, 10), Point { x: 3, y: -10 });
}

이 코드를 사용하면 복잡한 타입을 구성 요소로 분리하여 관심 있는 값을 각각 따로 사용할 수 있습니다.

패턴으로 비구조화하는 것은 구조체의 각 필드 값처럼 값의 일부를 서로 분리하여 사용하는 편리한 방법입니다.

패턴에서 값 무시하기

match의 마지막 arm처럼 패턴에서 값을 무시하는 것이 유용한 경우가 있음을 확인했습니다. match, 실제로 아무 동작도 하지 않으면서 나머지 가능한 모든 값을 처리하는 catch-all을 만들 수 있습니다. 패턴에서 전체 값이나 값의 일부를 무시하는 방법은 몇 가지 있습니다. _ 패턴을 사용하는 것(이미 확인했습니다), 다른 패턴 내부에서 _ 패턴을 사용하는 것, 밑줄로 시작하는 이름을 사용하는 것, 또는 ..을 사용하여 값의 나머지 부분을 무시하는 것입니다. 이 각 패턴을 사용하는 방법과 이유를 살펴보겠습니다.

_를 사용한 전체 값_

밑줄은 어떤 값과도 일치하지만 값에 바인딩하지 않는 와일드카드 패턴으로 사용했습니다. 이는 match 표현식의 마지막 arm에서 특히 유용하지만, Listing 19-17에 보여 있듯이 함수 파라미터를 포함한 모든 패턴에서 사용할 수 있습니다.

이 코드는 첫 번째 인수로 전달된 3 값을 완전히 무시하고 This code only uses the y parameter: 4를 출력합니다.

특정 함수 매개변수가 더 이상 필요하지 않은 대부분의 경우, 사용하지 않는 매개변수를 포함하지 않도록 서명을 변경합니다. 예를 들어 트레이트를 구현할 때 특정 타입 서명이 필요하지만 구현의 함수 본문에서 매개변수 중 하나가 필요하지 않은 경우, 함수 매개변수를 무시하는 것이 특히 유용합니다. 이렇게 하면 이름을 사용한 경우처럼 사용되지 않는 함수 매개변수에 대한 컴파일러 경고를 피할 수 있습니다.

중첩된 값의 일부 _

또한 다른 패턴 내부에서 _를 사용하여 값의 일부만 무시할 수 있습니다. 예를 들어 값의 일부만 테스트하려고 하지만 실행하려는 해당 코드에서 나머지 부분은 사용하지 않을 때 유용합니다. 목록 19-18은 설정의 값을 관리하는 코드를 보여줍니다. 비즈니스 요구 사항은 사용자가 설정의 기존 사용자 지정 값을 덮어쓸 수는 없지만, 설정이 현재 해제된 상태라면 설정을 해제하고 값을 지정할 수 있어야 한다는 것입니다.

이 코드는 Can't overwrite an existing customized value를 출력한 다음 setting is Some(5)를 출력합니다. 첫 번째 매치 암에서는 Some 변형 내부의 값을 일치시키거나 사용할 필요가 없지만, setting_value와 new_setting_value가 Some 변형인 경우를 테스트해야 합니다. 이 경우 setting_value를 변경하지 않는 이유를 출력하고, 값은 변경되지 않습니다.

두 번째 암의 setting_value 패턴으로 표현되는 모든 다른 경우(new_setting_value 또는 None가 _인 경우)에는 new_setting_value가 setting_value가 되도록 허용합니다.

특정 값을 무시하기 위해 한 패턴 내의 여러 위치에 밑줄을 사용할 수도 있습니다. Listing 19-19는 5개 항목으로 이루어진 튜플에서 두 번째와 네 번째 값을 무시하는 예를 보여줍니다.

이 코드는 Some numbers: 2, 8, 32을 출력하고, 4 및 16 값은 무시됩니다.

이름 앞에 밑줄을 붙여 사용하지 않는 변수 만들기_

변수를 만들었지만 어디에도 사용하지 않는다면, Rust는 보통 사용하지 않는 변수가 버그일 수 있으므로 경고를 표시합니다. 하지만 프로토타입을 만들거나 프로젝트를 시작하는 단계처럼, 아직 사용하지 않을 변수를 만들어 두는 것이 유용할 때도 있습니다. 이런 상황에서는 변수 이름 앞에 밑줄을 붙여 Rust가 사용하지 않는 변수에 대해 경고하지 않도록 할 수 있습니다. Listing 19-20에서는 두 개의 사용하지 않는 변수를 만들지만, 이 코드를 컴파일하면 그중 하나에 대해서만 경고를 받게 됩니다.

여기서는 y 변수를 사용하지 않는 것에 대한 경고를 받지만, _x를 사용하지 않는 것에 대한 경고는 받지 않습니다.

_만 사용하는 것과 밑줄로 시작하는 이름을 사용하는 것 사이에는 미묘한 차이가 있습니다. _x 구문은 여전히 값을 변수에 바인딩하지만, _는 전혀 바인딩하지 않습니다. 이 차이가 중요한 경우를 보여주기 위해 Listing 19-21은 오류를 발생시킵니다.

s 값이 여전히 _s로 이동되므로 s를 다시 사용할 수 없어 오류가 발생합니다. 그러나 밑줄만 단독으로 사용하면 값에 바인딩되지 않습니다. s가 _로 이동되지 않으므로 Listing 19-22는 오류 없이 컴파일됩니다.

이 코드는 s를 아무것도 바인딩하지 않기 때문에 잘 작동합니다.

..를 사용하여 값의 나머지 부분..

여러 부분으로 구성된 값의 경우, .. 구문을 사용하여 특정 부분만 사용하고 나머지는 무시할 수 있습니다. 이렇게 하면 무시하는 각 값에 대해 밑줄을 나열할 필요가 없습니다. .. 패턴은 나머지 패턴에서 명시적으로 일치하지 않은 값의 모든 부분을 무시합니다. Listing 19-23에서는 3차원 공간의 좌표를 저장하는 Point 구조체를 정의했습니다. match 표현에서는 x 좌표에만 동작하고 y 및 z 필드의 값은 무시합니다.

x 값을 나열한 다음 .. 패턴만 포함하면 됩니다. 이는 y: _와 z: _를 각각 나열하는 것보다 훨씬 간편합니다. 특히 필드가 많은 구조체에서 관련 있는 필드가 하나 또는 두 개뿐인 상황에서 유용합니다.

.. 구문은 필요한 만큼의 값으로 확장됩니다. Listing 19-24에서는 튜플과 함께 ..를 사용하는 방법을 보여줍니다.

이 코드에서 첫 번째 값과 마지막 값은 각각 first과 last에 매칭됩니다. ..는 중간에 있는 모든 값을 매칭하여 무시합니다.

그러나 ..의 사용은 모호하지 않아야 합니다. 어떤 값을 매칭하고 어떤 값을 무시할지 명확하지 않으면 Rust는 오류를 반환합니다. Listing 19-25는 ..를 모호하게 사용하는 예시로, 컴파일되지 않습니다.

이 예제를 컴파일하면 다음과 같은 오류가 발생합니다.

$ cargo run

error: `..` can only be used once per tuple pattern
 --> src/main.rs:5:22
  |
5 |         (.., second, ..) => {
  |          --          ^^ can only be used once per tuple pattern
  |          |
  |          previously used here

Rust는 second에 매칭하기 전에 튜플에서 몇 개의 값을 무시해야 하는지, 그리고 그 이후에 몇 개의 값을 더 무시해야 하는지를 결정할 수 없습니다. 이 코드는 2을 무시하고 second에 4을 바인딩한 후 8, 16, 32을 무시하라는 의미일 수도 있고, 2과 4을 무시하고 second에 8을 바인딩한 후 16과 32을 무시하라는 의미일 수도 있습니다. 이렇듯 여러 해석이 가능합니다. 변수 이름 second은 Rust에게 특별한 의미를 가지지 않으므로, ..를 두 곳에 이렇게 사용하는 것은 모호하기 때문에 컴파일러 오류가 발생합니다.

매치 가드를 이용한 조건 추가

A 경기 가드 추가 사항 if a의 패턴 후에 지정된 조건 match arm은 선택한 arm과 일치해야 합니다. 매치 가드는 패턴만으로 허용되는 것보다 더 복잡한 아이디어를 표현할 때 유용합니다. 하지만, arm은 다음과 같은 경우에만 사용할 수 있습니다. match 표현, NO if let 또는 while let 표현들.

조건은 패턴에서 생성된 변수를 사용할 수 있습니다. Listing 19-26은 match를 보여줍니다. 첫 번째 arm은 Some(x) 패턴을 가지며, if x % 2 == 0라는 매치 가드를 사용합니다. 이 가드는 숫자가 짝수인 경우 true가 됩니다.

이 예제는 The number 4 is even을 출력합니다. num을 첫 번째 팔의 패턴과 비교하면, Some(4)이 Some(x)과 일치하기 때문에 매칭됩니다. 그런 다음, 매치 가드가 x를 2로 나눈 나머지가 0과 같은지 확인합니다.

만약 num 대신 Some(5) 이었다면, 첫 번째 암의 매치 가드는 false 이었을 것입니다. 5를 2로 나눈 나머지가 1이기 때문에 0과 같지 않기 때문입니다. Rust는 두 번째 암으로 진행하며, 두 번째 암은 매치 가드가 없으므로 어떤 Some 변형이든 일치합니다.

패턴 내에서 if x % 2 == 0 조건을 표현할 방법이 없으므로, 매치 가드를 사용하면 이 논리를 표현할 수 있습니다. 매치 가드를 사용할 때의 단점은 컴파일러가 매치 가드 식이 포함된 경우 완전성을 검사하지 않는다는 점입니다.

Listing 19-11을 다룰 때, 패턴 쉐도잉 문제를 해결하기 위해 매치 가드를 사용할 수 있다고 언급했습니다. match 표현식에서 외부 변수를 사용하는 대신 패턴 안에 새로운 변수를 만들었습니다. 이 새로운 변수 때문에 외부 변수의 값으로 조건을 검사할 수 없었습니다. Listing 19-27에서는 이 문제를 매치 가드로 해결하는 방법을 보여줍니다. match

이 코드는 이제 인쇄됩니다. Default case, x = Some(5). 두 번째 매치 암의 패턴은 새로운 변수를 도입하지 않습니다. y 그것은 외부를 그늘지게 할 것입니다. y즉, 우리는 외부를 사용할 수 있습니다. y 일치 가드에서. 패턴을 다음과 같이 지정하는 대신 Some(y)[중고] 그 외의 것을 탐하다 y, 우리는 지정 Some(n). 이것은 새로운 변수를 만듭니다. n 그것은 아무것도 없는 것이 아니기 때문에 아무것도 없는 것이다. n 변수는 외부에 match.

if n == y라는 매치 가드는 패턴이 아니므로 새 변수를 도입하지 않습니다. 여기서 y는 바깥 범위에 있는 변수입니다. 새로운 y를 만들어 기존 변수를 가리는 것이 아닙니다. 따라서 n과 바깥 범위의 y를 비교해 같은 값을 찾습니다.

match 가드에서 or 연산자 또는 |을 사용하여 여러 패턴을 지정할 수도 있습니다. 이 경우 match 가드 조건은 모든 패턴에 적용됩니다. Listing 19-28은 | 매치 가드와 함께 사용할 때의 우선 순위를 보여줍니다. 이 예제의 중요한 부분은 if y 매치 가드 적용 대상 4, 5, 그리고 6라는 점입니다. if y 적용 대상 6처럼 보일 수 있지만, 실제로는 그렇지 않습니다.

일치 조건은 팔이 다음과 같은 경우에만 일치한다는 것을 나타냅니다. x 그것은 평등하다. 4, 5, 또는 6 그리고 만약 y 있습니다. true. 이 코드가 실행되면 첫 번째 팔의 패턴이 일치합니다. x 있습니다. 4#경기 경비대 if y 있습니다. false, 그래서 첫 번째 팔이 선택되지 않습니다. 코드는 일치하는 두 번째 팔로 이동하고이 프로그램은 인쇄합니다. no. 그 이유는 if 조건은 전체 패턴에 적용 4 | 5 | 6마지막 값이 아닌, 6즉, 패턴과 관련하여 매치 가드의 우선 순위는 다음과 같이 동작합니다.

(4 | 5 | 6) if y => ...

다음과 같이 동작하는 것이 아닙니다:

4 | 5 | (6 if y) => ...

코드를 실행하면 우선순위 동작이 명확해집니다. 매치 가드가 | 연산자를 사용하여 지정된 값 목록의 마지막 값에만 적용되었다면 해당 팔이 일치하고 프로그램이 yes를 출력했을 것입니다.

사용 @ 바인딩

at 연산자 는 특정 값이 패턴 매칭 조건을 만족하는지 테스트하는 동시에, 해당 값을 변수에 바인딩할 수 있게 해 줍니다. Listing 19-29에서는 @의 Message::Hello 필드가 id 범위 내에 있는지 확인하고, 해당 값을 변수 3..=7에 바인딩하여 해당 팔(arm)에 연결된 코드에서 사용할 수 있도록 합니다. id

이 예제는 Found an id in range: 5을 출력합니다. 범위 id @ 앞에 3..=7를 지정하면, 해당 범위와 일치하는 값을 변수 id에 캡처하는 동시에 값이 범위 패턴과 일치하는지 확인합니다.

패턴에 지정된 범위만 있는 두 번째 arm에는 arm과 관련된 코드에 실제 값이 포함된 변수가 없습니다. id 필드. The id 필드의 값은 10, 11 또는 12 일 수 있지만 해당 패턴과 함께 제공되는 코드는 해당 패턴을 알지 못합니다. 패턴 코드는 해당 패턴의 값을 사용할 수 없습니다. id 왜냐하면 우리가 구하지 않았기 때문입니다. id 변수에 있는 값입니다.

마지막 arm에서는 범위를 지정하지 않은 변수를 선언했습니다. 이 경우, arm의 코드에서 id라는 이름의 변수로 해당 값을 사용할 수 있습니다. 그 이유는 구조체 필드 축약 구문을 사용했기 때문입니다. 하지만 처음 두 arm에서처럼 이 arm에서는 id 필드의 값에 대한 조건 검사를 수행하지 않았습니다. 따라서 어떤 값이든 이 패턴과 일치합니다.

@를 사용하면 값을 테스트하고, 같은 패턴 내에서 해당 값을 변수에 저장할 수 있습니다.

요약

Rust의 패턴은 서로 다른 종류의 데이터를 구별하는 데 매우 유용합니다. match 표현식에 사용할 때, Rust는 패턴이 가능한 모든 값을 다루도록 보장하며 그렇지 않으면 프로그램이 컴파일되지 않습니다. let 문과 함수 파라미터에서 패턴을 사용하면 이러한 구조가 더 유용해지며, 값을 더 작은 부분으로 분해하여 해당 부분을 변수에 할당할 수 있습니다. 필요에 따라 간단하거나 복잡한 패턴을 만들 수 있습니다.

다음으로, 이 책의倒数第二章에서는 Rust의 다양한 기능 중 고급 측면을 살펴봅니다.
