이름 * match 제어 흐름 구축

러스트는 매우 강력한 제어 흐름 구조를 가지고 있습니다. match 즉, 일련의 패턴에 대해 값을 비교 한 다음 패턴 일치를 기반으로 코드를 실행할 수 있습니다. 패턴은 리터럴 값, 변수 이름, 와일드 카드 및 기타 여러 가지로 구성 될 수 있습니다. 창세기. Chapter 19 무시 본의 모든 다른 종류 및 그들이 하는 무슨을 커버합니다. 의 힘 match 패턴의 표현력과 컴파일러가 모든 가능한 경우를 처리한다는 사실에서 비롯됩니다.

캐치 - 모든 패턴과 _ 위치 지정자

enums를 사용하면 몇 가지 특정 값에 대해 특별한 조치를 취할 수도 있지만 다른 모든 값에는 하나의 기본 조치를 취합니다. 주사위 롤에서 3을 굴리면 플레이어가 움직이지 않고 대신 멋진 새 모자를 얻는 게임을 구현한다고 상상해보십시오. 7을 굴리면 플레이어는 멋진 모자를 잃습니다. 다른 모든 값의 경우 플레이어는 게임 보드의 공백 수를 이동합니다. 여기에 a가 있습니다. match 그 논리를 구현합니다, 주사위 롤의 결과가 아닌 임의 값보다 하드 코딩, 실제로 구현이 예제에 대한 범위를 벗어나 있기 때문에 시체없이 함수로 표현 다른 모든 논리:

fn main() {
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        other => move_player(other),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
    fn move_player(num_spaces: u8) {}
}

처음 두 팔의 경우 패턴은 리터럴 값 3 및 7입니다. 다른 모든 가능한 값을 포함하는 마지막 팔의 경우 패턴은 other라는 이름으로 선택한 변수입니다. other arm에서 실행되는 코드는 변수를 move_player 함수로 전달하여 변수를 사용합니다.

이 코드는 u8가 가질 수있는 모든 가능한 값을 나열하지 않았더라도 컴파일됩니다. 마지막 패턴은 특별히 나열되지 않은 모든 값과 일치하기 때문입니다. 이 캐치 올 패턴은 match가 철저해야한다는 요구 사항을 충족시킵니다. 패턴이 순서대로 평가되기 때문에 캐치 올 암을 마지막에 두어야합니다. 캐치 올 암을 더 일찍 넣으면 다른 암은 결코 경고하지 않을 것입니다!

러스트는 catch-all을 원할 때 사용할 수 있지만 catch-all 패턴에서 값을 사용하고 싶지 않은 패턴을 가지고 있습니다. _는 어떤 값과도 일치하고 그 값에 바인딩되지 않는 특별한 패턴입니다. 이것은 러스트에게 그 값을 사용하지 않을 것임을 알려줍니다. 그래서 러스트는 사용되지 않은 변수에 대해 경고하지 않을 것입니다.

게임의 규칙을 변경합시다. 이제 3 또는 7 이외의 것을 굴리면 다시 굴려야합니다. 더 이상 catch-all 값을 사용할 필요가 없으므로 _라는 변수 대신 other를 사용하도록 코드를 변경할 수 있습니다.

fn main() {
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        _ => reroll(),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
    fn reroll() {}
}

이 예제는 마지막 팔의 다른 모든 값을 명시적으로 무시하기 때문에 철저한 요구 사항을 충족합니다.

마지막으로, 우리는 게임의 규칙을 한 번 더 변경하여 3 또는 7 이외의 다른 것을 굴리는 경우 아무 일도 일어나지 않도록합니다. 우리는 단위 값 (우리가 언급 한 빈 튜플 유형)을 사용하여 표현할 수 있습니다. 튜플 타입(The Tuple Type) 무시 섹션)와 함께 제공되는 코드로 _ 팔:

fn main() {
    let dice_roll = 9;
    match dice_roll {
        3 => add_fancy_hat(),
        7 => remove_fancy_hat(),
        _ => (),
    }

    fn add_fancy_hat() {}
    fn remove_fancy_hat() {}
}

여기서, 우리는 러스트에게 이전 arm의 패턴과 일치하지 않는 다른 값을 사용하지 않을 것이며, 이 경우 어떤 코드도 실행하고 싶지 않다고 명시적으로 말하고 있습니다.
