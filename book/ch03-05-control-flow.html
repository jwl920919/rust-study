The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

제어 흐름

조건이 true인지 여부에 따라 일부 코드를 실행하는 기능과 조건이 true인 동안 일부 코드를 반복적으로 실행하는 기능은 대부분의 프로그래밍 언어의 기본 구성 요소입니다. Rust 코드의 실행 흐름을 제어하는 가장 일반적인 구조는 if 표현식과 루프입니다.

if 표현식

if 표현식을 사용하면 조건에 따라 코드를 분기할 수 있습니다. 조건을 제공하고 “이 조건이 충족되면 이 코드 블록을 실행하십시오. 조건이 충족되지 않으면 이 코드 블록을 실행하지 마십시오.”라고 명시합니다.

projects 디렉토리에 branches라는 새 프로젝트를 만들어 if 표현식을 탐색해 보세요. src/main.rs 파일에 다음 코드를 입력합니다.

파일 이름: src/main.rs

fn main() {
    let number = 3;

    if number < 5 {
        println!("condition was true");
    } else {
        println!("condition was false");
    }
}

모두 if 표현식은 키워드로 시작합니다. if, 조건이 뒤따릅니다. 이 경우, 조건은 변수가 있는지 여부를 검사합니다. number 값이 5보다 작습니다. 우리는 조건이 인 경우에 실행하기 위하여 부호의 구획을 둔다 true curly brackets 안의 조건 바로 뒤에 있습니다. if 가끔 부르는 표현들이 팔마치 내 품에 있는 것처럼 match 우리가 논의한 표현들은 2장 무시 챕터 2.

선택적으로, else 표현식을 포함할 수도 있습니다. 여기서는 조건이 false로 평가될 경우 실행할 대체 코드 블록을 제공하기 위해 이 방식을 선택했습니다. false 표현식을 제공하지 않고 조건이 false인 경우, 프로그램은 else 블록을 건너뛰고 false 다음 코드 조각으로 진행합니다. if

이 코드를 실행해 보세요. 다음 출력을 볼 수 있습니다:

$ cargo run
   Compiling branches v0.1.0 (file:///projects/branches)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/branches`
condition was true

number 값을 조건이 거짓이 되는 값으로 변경하여 어떤 일이 발생하는지 살펴 보겠습니다. false

fn main() {
    let number = 7;

    if number < 5 {
        println!("condition was true");
    } else {
        println!("condition was false");
    }
}

프로그램을 다시 실행하고 출력을 살펴보십시오.

$ cargo run
   Compiling branches v0.1.0 (file:///projects/branches)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/branches`
condition was false

또한 이 코드의 조건은 bool 타입이어야 합니다. 조건이 bool 타입이 아니면 오류가 발생합니다. 예를 들어 다음 코드를 실행해 보세요.

파일 이름: src/main.rs

fn main() {
    let number = 3;

    if number {
        println!("number was three");
    }
}

이번에는 if 조건이 3 값으로 평가되며, Rust는 오류를 발생시킵니다:

$ cargo run
   Compiling branches v0.1.0 (file:///projects/branches)
error[E0308]: mismatched types
 --> src/main.rs:4:8
  |
4 |     if number {
  |        ^^^^^^ expected `bool`, found integer

For more information about this error, try `rustc --explain E0308`.
error: could not compile `branches` (bin "branches") due to 1 previous error

에러는 러스트가 a를 예상했음을 나타냅니다. bool 하지만 정수가 있습니다. Ruby와 JavaScript와 같은 언어와 달리, 러스트는 자동으로 Boolean이 아닌 타입을 Boolean로 변환하려고 하지 않습니다. 반드시 명시적이어야 하며 항상 제공해야 합니다. if Boolean을 그 조건으로 사용합니다. 우리가 원한다면 if 숫자와 같지 않을 때만 실행되는 코드 블록 0예를 들어, 우리는 변경할 수 있습니다. if 다음을 표현:

파일 이름: src/main.rs

fn main() {
    let number = 3;

    if number != 0 {
        println!("number was something other than zero");
    }
}

이 코드를 실행하면 number was something other than zero가 출력됩니다.

else if를 사용한 다중 조건 처리 else if

if와 else를 else if 식에 결합하여 여러 조건을 사용할 수 있습니다. 예를 들어 다음과 같습니다.

파일 이름: src/main.rs

fn main() {
    let number = 6;

    if number % 4 == 0 {
        println!("number is divisible by 4");
    } else if number % 3 == 0 {
        println!("number is divisible by 3");
    } else if number % 2 == 0 {
        println!("number is divisible by 2");
    } else {
        println!("number is not divisible by 4, 3, or 2");
    }
}

이 프로그램에는 취할 수 있는 네 가지 경로가 있습니다. 실행한 후 다음 출력을 볼 수 있습니다.

$ cargo run
   Compiling branches v0.1.0 (file:///projects/branches)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/branches`
number is divisible by 3

이 프로그램이 실행되면 각 if 표현식을 차례로 검사하여 조건이 true로 평가되는 첫 번째 본문을 실행합니다. true. 6은 2로 나누어지지만 number is divisible by 2출력은 보이지 않으며, number is not divisible by 4, 3, or 2 텍스트도 else 블록에서 출력되지 않습니다. 이는 Rust가 첫 번째 true 조건에 해당하는 블록만 실행하고, 해당 조건을 찾으면 나머지 조건을 검사하지 않기 때문입니다. true

너무 많은 else if 표현식을 사용하면 코드가 어수선해질 수 있으므로 하나 이상의 표현식을 사용하는 경우 코드를 리팩터링하는 것이 좋습니다. 6장에서는 이러한 경우에 사용할 수 있는 Rust의 강력한 분기 구조인 match에 대해 설명합니다.

let 문에서 if 사용 iflet

if은 표현식이기 때문에, let 문의 오른쪽에서 Listing 3-2에서처럼 결과를 변수에 할당하기 위해 사용할 수 있습니다.

number 변수는 if 표현식의 결과에 따라 값에 바인딩됩니다. 이 코드를 실행하여 어떤 일이 발생하는지 확인하십시오.

$ cargo run
   Compiling branches v0.1.0 (file:///projects/branches)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.30s
     Running `target/debug/branches`
The value of number is: 5

코드 블록은 마지막 표현식으로 평가되며, 숫자 자체도 표현식이라는 점을 기억하세요. 이 경우, if 전체 표현식의 값은 어떤 코드 블록이 실행되는지에 따라 달라집니다. 이는 if의 각 분기(arm)에서 결과가 될 수 있는 값들이 모두 동일한 타입이어야 함을 의미합니다. 목록 3-2에서 if 분기와 else 분기의 결과는 모두 i32 정수였습니다. 다음 예시처럼 타입이 일치하지 않으면 오류가 발생합니다:

파일 이름: src/main.rs

fn main() {
    let condition = true;

    let number = if condition { 5 } else { "six" };

    println!("The value of number is: {number}");
}

이 코드를 컴파일하려고 하면 오류가 발생합니다. if 및 else 암에는 호환되지 않는 값 유형이 있으며 러스트는 프로그램에서 문제를 찾을 위치를 정확히 나타냅니다.

$ cargo run
   Compiling branches v0.1.0 (file:///projects/branches)
error[E0308]: `if` and `else` have incompatible types
 --> src/main.rs:4:44
  |
4 |     let number = if condition { 5 } else { "six" };
  |                                 -          ^^^^^ expected integer, found `&str`
  |                                 |
  |                                 expected because of this

For more information about this error, try `rustc --explain E0308`.
error: could not compile `branches` (bin "branches") due to 1 previous error

if 블록의 표현식은 정수로 평가되고, else 블록의 표현식은 문자열로 평가됩니다. 이는 작동하지 않습니다. 변수는 단일 타입을 가져야 하며, Rust는 컴파일 시점에 number 변수의 타입을 명확히 알아야 하기 때문입니다. number의 타입을 아는 것은 컴파일러가 number를 사용하는 모든 곳에서 타입이 유효한지 검증할 수 있게 해줍니다. 만약 number의 타입이 런타임에 결정된다면, Rust는 이를 수행할 수 없습니다. 컴파일러가 모든 변수에 대해 여러 가상의 타입을 추적해야 한다면, 컴파일러는 더 복잡해지고 코드에 대해 더 적은 보증을 하게 될 것입니다.

반복문 반복문 반복문

코드 블록을 한 번 이상 실행하는 것은 종종 유용합니다. 이 작업을 위해 Rust는 여러 루프를 제공합니다. 루프는 루프 본문의 코드를 끝까지 실행한 다음 처음부터 즉시 다시 시작합니다. 루프를 실험해 보기 위해 loops라는 이름의 새 프로젝트를 만들어 보겠습니다.

Rust에는 loop, while, for라는 세 가지 종류의 루프가 있습니다. 각각을 시도해 보겠습니다.

loop를 사용하여 코드 반복하기 loop

loop 키워드는 Rust에게 코드 블록을 영원히 또는 명시적으로 중단하라고 지시할 때까지 계속해서 실행하라고 지시합니다.

예를 들어, loops 디렉토리의 src/main.rs 파일을 다음과 같이 변경해 보겠습니다:

파일 이름: src/main.rs

fn main() {
    loop {
        println!("again!");
    }
}

이 프로그램을 실행하면 again!가 프로그램이 수동으로 중지될 때까지 계속 출력됩니다. 대부분의 터미널은 ctrl-C 키보드 단축키를 지원하여 연속 루프에 갇힌 프로그램을 중단할 수 있습니다. 직접 시도해 보세요:

$ cargo run
   Compiling loops v0.1.0 (file:///projects/loops)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.08s
     Running `target/debug/loops`
again!
again!
again!
again!
^Cagain!

기호 ^C는 ctrl-C를 눌렀던 위치를 나타냅니다.

인터럽트 신호를 받았을 때 코드가 루프의 어디에 있었는지에 따라 again!가 ^C 뒤에 출력될 수도 있고, 출력되지 않을 수도 있습니다.

다행히 Rust는 코드를 사용하여 루프를 빠져나가는 방법도 제공합니다. 루프 안에 break 키워드를 배치하면 프로그램에 루프 실행을 중단할 시점을 알릴 수 있습니다. 2장의 “올바른 추측을 한 후 종료” 섹션에서 사용자가 올바른 숫자를 추측하여 게임을 이겼을 때 프로그램을 종료하기 위해 이 방법을 사용했음을 기억하십시오.

우리는 또한 추측 게임에서 continue를 사용했는데, 루프에서 루프의이 반복에서 나머지 코드를 건너 뛰고 다음 반복으로 이동하도록 프로그램에 지시합니다.

루프에서 값 반환

loop의 용도 중 하나는 실패할 수 있는 작업을 재시도하는 것입니다. 예를 들어 스레드가 작업을 완료했는지 확인하는 경우입니다. 또한 해당 작업의 결과를 루프 밖으로 전달하여 나머지 코드에서 사용해야 할 수도 있습니다. 이렇게 하려면 루프를 중단하는 데 사용하는 break 식 뒤에 반환할 값을 추가합니다. 그러면 그 값이 루프에서 반환되어 사용할 수 있게 됩니다. 다음 코드에서 이를 확인할 수 있습니다:

fn main() {
    let mut counter = 0;

    let result = loop {
        counter += 1;

        if counter == 10 {
            break counter * 2;
        }
    };

    println!("The result is {result}");
}

루프 전에 counter이라는 이름의 변수를 선언하고 0로 초기화합니다. 그런 다음 루프에서 반환된 값을 저장할 result라는 이름의 변수를 선언합니다. 루프의 모든 반복에서 1을 counter 변수에 더하고, counter이 10과 같은지 확인합니다. 같으면 break 키워드를 counter * 2 값과 함께 사용합니다. 루프가 끝난 후 세미콜론을 사용하여 result에 값을 할당하는 문장을 종료합니다. 마지막으로 result의 값을 출력합니다. 이 경우 그 값은 20입니다.

루프 내부에서 return을 사용할 수도 있습니다. break은 현재 루프만 종료하지만, return은 항상 현재 함수를 종료합니다.

루프 레이블로 의미 구분

중첩된 루프가 있는 경우, break과 continue은 해당 시점에서 가장 안쪽 루프에 적용됩니다. 루프에 선택적으로 루프 레이블을 지정할 수 있으며, 이 레이블을 break 또는 continue와 함께 사용하여 해당 키워드가 가장 안쪽 루프가 아닌 레이블이 지정된 루프에 적용되도록 할 수 있습니다. 루프 레이블은 반드시 한 개의 따옴표(')로 시작해야 합니다. 두 개의 중첩된 루프를 사용한 예시는 다음과 같습니다.

fn main() {
    let mut count = 0;
    'counting_up: loop {
        println!("count = {count}");
        let mut remaining = 10;

        loop {
            println!("remaining = {remaining}");
            if remaining == 9 {
                break;
            }
            if count == 2 {
                break 'counting_up;
            }
            remaining -= 1;
        }

        count += 1;
    }
    println!("End count = {count}");
}

외부 루프에는 'counting_up 레이블이 있으며 0에서 2까지 증가합니다. 레이블이 없는 내부 루프는 10에서 9까지 감소합니다. 레이블을 지정하지 않은 첫 번째 break은 내부 루프만 종료합니다. break 'counting_up; 문장은 외부 루프를 종료합니다. 이 코드는 다음과 같이 출력합니다.

     Running `target/debug/loops`

count = 1
remaining = 10
remaining = 9

remaining = 10
End count = 2

while을 사용한 조건부 루프 간소화

프로그램은 종종 루프 내에서 조건을 평가해야 합니다. 조건이 true인 동안 루프가 실행됩니다. 조건이 더 이상 true이 아니게 되면 프로그램은 break을 호출하여 루프를 중지합니다. loop, if, else, break을 조합하여 이러한 동작을 구현할 수도 있으며, 원한다면 지금 바로 프로그램에서 시도해 볼 수 있습니다. 그러나 이 패턴은 매우 일반적이므로 Rust에는 이를 위한 내장 언어 구조인 while 루프가 있습니다. Listing 3-3에서는 while을 사용하여 프로그램을 세 번 반복하고, 매번 카운트다운을 수행한 후, 루프가 종료되면 메시지를 출력하고 종료합니다.

이 구조는 loop, if, else, break을 사용할 경우 필요한 많은 중첩을 제거하므로 더 명확합니다. 조건이 true로 평가되는 동안 코드가 실행되고, 그렇지 않으면 루프를 종료합니다.

for를 사용하여 컬렉션 반복 for

while 구문을 사용하여 배열과 같은 컬렉션의 요소를 반복할 수 있습니다. 예를 들어, Listing 3-4의 루프는 배열 a의 각 요소를 출력합니다.

여기서 코드는 배열의 요소를 순서대로 카운트합니다. 인덱스 0에서 시작하여 배열의 마지막 인덱스에 도달할 때까지 루프를 실행합니다(즉, index < 5가 더 이상 true이 아닌 경우). 이 코드를 실행하면 배열의 모든 요소가 출력됩니다.

$ cargo run
   Compiling loops v0.1.0 (file:///projects/loops)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.32s
     Running `target/debug/loops`
the value is: 10
the value is: 20
the value is: 30
the value is: 40
the value is: 50

예상대로 5개의 배열 값이 모두 터미널에 나타납니다. index가 어느 시점에서 5의 값에 도달하더라도, 루프는 배열에서 여섯 번째 값을 가져오기 전에 실행을 중단합니다.

그러나 이 방법은 오류가 발생하기 쉽습니다. 인덱스 값이나 조건이 올바르지 않으면 프로그램이 패닉(panic)에 빠질 수 있습니다. 예를 들어, a 배열의 정의를 4개의 요소로 변경했지만 조건을 while index < 4로 업데이트하는 것을 잊었다면 코드가 패닉에 빠집니다. 또한 컴파일러가 루프의 모든 반복에서 인덱스가 배열의 범위를 벗어나지 않는지 확인하기 위해 런타임 코드를 추가하므로 속도가 느립니다.

좀 더 간결한 대안으로 for 루프를 사용하여 컬렉션의 각 항목에 대해 코드를 실행할 수 있습니다. for 루프는 목록 3-5의 코드와 같습니다.

이 코드를 실행하면 목록 3-4와 동일한 출력을 볼 수 있습니다. 더 중요한 것은, 이제 코드의 안전성을 높이고 배열의 끝을 넘거나 충분히 진행하지 않아 일부 항목을 놓칠 수 있는 버그의 가능성을 제거했다는 점입니다. for 루프에서 생성된 기계 코드는 인덱스가 모든 반복에서 배열의 길이와 비교될 필요가 없기 때문에 더 효율적일 수도 있습니다.

for 루프를 사용하면, 목록 3-4에서 사용된 방법과 달리 배열의 값 수를 변경할 때 다른 코드를 수정할 필요가 없습니다.

안전성과 간결성 for 루프는 러스트에서 가장 일반적으로 사용되는 루프 구조체를 만듭니다. 심지어 어떤 코드를 특정 횟수만큼 실행하려는 상황에서도, while Listing 3-3에서, 대부분의 러스트aceans는 for 루프. 그것을하는 방법은 a를 사용하는 것입니다. Range, 표준 라이브러리에서 제공하는 이 라이브러리는 한 숫자에서 시작하여 다른 숫자로 끝나는 모든 숫자를 순차적으로 생성합니다.

다음은 for 루프와 아직 다루지 않은 rev 메서드를 사용해 범위를 역순으로 변경했을 때의 카운트다운 모습입니다.

파일 이름: src/main.rs

fn main() {
    for number in (1..4).rev() {
        println!("{number}!");
    }
    println!("LIFTOFF!!!");
}
