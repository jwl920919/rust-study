The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

구조체를 사용한 예제 프로그램

구조체를 언제 사용해야 하는지 이해하기 위해 직사각형의 면적을 계산하는 프로그램을 작성해 보겠습니다. 먼저 단일 변수를 사용해서 시작하고, 이후 구조체를 사용하도록 프로그램을 리팩터링하겠습니다.

Cargo를 사용해 픽셀 단위로 지정된 직사각형의 너비와 높이를 받아 면적을 계산하는 새로운 바이너리 프로젝트인 rectangles를 만들어 보겠습니다. Listing 5-8은 프로젝트의 src/main.rs 파일에 이 작업을 수행하는 방법 중 하나를 보여주는 짧은 프로그램입니다.

이제 cargo run을 사용해 이 프로그램을 실행해 보세요.

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.42s
     Running `target/debug/rectangles`
The area of the rectangle is 1500 square pixels.

이 코드는 각 차원을 인수로 전달하여 area 함수를 호출함으로써 직사각형의 면적을 계산하는 데 성공합니다. 하지만 이 코드를 더 명확하고 읽기 쉽게 만들 수 있는 방법이 더 있습니다.

이 코드의 문제는 area의 시그니처에서 분명히 드러납니다.

fn main() {
    let width1 = 30;
    let height1 = 50;

    println!(
        "The area of the rectangle is {} square pixels.",
        area(width1, height1)
    );
}

fn area(width: u32, height: u32) -> u32 {
    width * height
}

area 함수는 한 직사각형의 면적을 계산하는 것이 목적이지만, 작성한 함수에는 두 개의 매개변수가 있으며 프로그램 어디에서도 이 매개변수들이 서로 관련되어 있다는 것을 알 수 없습니다. 너비와 높이를 함께 묶으면 가독성과 관리성이 모두 좋아집니다. 이미 3장의 '튜플 타입' 섹션에서 튜플 타입을 사용하여 이 문제를 해결할 수 있는 한 가지 방법에 대해 논의했습니다.

튜플을 이용한 리팩토링

Listing 5-9는 튜플을 사용하는 프로그램의 다른 버전을 보여줍니다.

어떤 면에서는 이 프로그램이 더 좋습니다. 튜플을 사용하면 약간의 구조를 추가할 수 있고, 이제 인자 하나만 전달하면 됩니다. 하지만 다른 면에서는 이 버전이 덜 명확합니다. 튜플은 요소의 이름을 지정하지 않으므로 튜플의 각 부분에 인덱스를 지정해야 하며, 이로 인해 계산이 덜 명확해집니다.

너비와 높이를 섞는 것은 면적 계산에는 중요하지 않지만 화면에 사각형을 그리려면 중요합니다! 우리는 width가 튜플 인덱스 0이고 height가 튜플 인덱스 1이기 때문에 다른 사람이 코드를 더 쉽게 이해할 수 있기 때문에 더 어려울 것입니다.

구조체를 이용한 리팩토링

구조체를 사용하면 데이터에 라벨을 붙여 의미를 부여할 수 있습니다. Listing 5-10에 표시된 것처럼, 현재 사용하고 있는 튜플을 전체 이름과 각 부분의 이름을 가진 구조체로 변환할 수 있습니다.

여기서, 우리는 struct를 정의하고 이름을 붙였습니다. Rectangle. 중괄호 안에, 우리는 필드를 다음과 같이 정의했다. width 그리고 height둘 다 유형이 있습니다. u32. 그런 다음, in main그리고 우리는 특정한 경우를 Rectangle 넓이가 넓으니 30 한 높이의 50.

이제 area 함수는 rectangle이라는 이름의 하나의 파라미터로 정의됩니다. 이 파라미터의 타입은 Rectangle 구조체 인스턴스의 불변 빌림입니다. 4장에서 언급했듯이, 구조체를 소유하는 대신 빌리고 싶습니다. 이렇게 하면 main이 소유권을 유지하면서 rect1을 계속 사용할 수 있습니다. 이것이 함수 서명과 함수 호출 부분에 &를 사용하는 이유입니다.

area 함수는 Rectangle 인스턴스의 width과 height 필드에 접근합니다. 구조체 인스턴스를 빌려 온 경우 필드에 접근해도 필드 값의 소유권이 이동하지 않습니다. 그래서 구조체를 빌려 쓰는 경우가 많습니다. 이제 area 함수 시그니처는 의도를 정확히 표현합니다. Rectangle의 width과 height 필드를 사용해 면적을 계산한다는 뜻입니다. 너비와 높이가 서로 관련된 값이라는 점도 드러납니다. 튜플 인덱스인 0과 1 대신 각 값의 의미를 나타내는 이름을 사용하므로 더 명확합니다.

파생 트레이트를 통한 기능 추가

프로그램을 디버깅하는 동안 Rectangle의 인스턴스를 출력하고 모든 필드의 값을 확인하는 것이 유용할 것입니다. Listing 5-11에서는 이전 장에서 사용했던 것처럼 println! 매크로를 사용하려고 시도합니다. 하지만 이렇게 하면 작동하지 않습니다.

이 코드를 컴파일하면 다음과 같은 핵심 메시지가 포함된 오류가 발생합니다:

error[E0277]: `Rectangle` doesn't implement `std::fmt::Display`

println! 매크로는 다양한 종류의 포맷팅을 수행할 수 있으며, 기본적으로 중괄호는 println!이 Display로 알려진 포맷팅을 사용하도록 지시합니다: 최종 사용자에게 직접 제공하기 위한 출력입니다. 지금까지 살펴본 원시 타입은 1나 다른 원시 타입을 사용자에게 보여줄 방법이 하나뿐이므로 기본적으로 Display을 구현합니다. 하지만 구조체의 경우, println!가 출력을 포맷팅해야 하는 방식이 명확하지 않습니다. 왜냐하면 더 많은 표시 가능성이 있기 때문입니다: 쉼표를 사용할까요? 중괄호를 출력할까요? 모든 필드를 보여줄까요? 이러한 모호성 때문에 Rust는 우리가 원하는 것을 추측하려 하지 않으며, 구조체는 println!과 {} 플레이스홀더와 함께 사용할 Display의 제공된 구현이 없습니다.

오류를 계속 읽다 보면 다음과 같은 유용한 주석을 발견할 수 있습니다.

help: the trait `std::fmt::Display` is not implemented for `Rectangle`
  --> src/main.rs:1:1

한번 시도해 보겠습니다! println! 매크로 호출은 이제 println!("rect1 is {rect1:?}");처럼 보일 것입니다. 중괄호 안에 :? 지정자를 넣으면 println!에 Debug라는 출력 형식을 사용하라고 알려주는 것입니다. Debug 트레이트는 개발자가 디버깅 중 구조체의 값을 확인할 수 있도록 유용한 방식으로 구조체를 출력할 수 있게 해줍니다.

이 변경 사항을 적용하여 코드를 컴파일해 보겠습니다. 아! 여전히 오류가 발생합니다:

error[E0277]: `Rectangle` doesn't implement `Debug`

다시 한번, 컴파일러가 유용한 주석을 제공합니다:

   |                        required by this formatting parameter
   |

Rust에는 디버깅 정보를 출력하는 기능이 포함되어 있지만, 이 기능을 구조체에 사용할 수 있도록 명시적으로 선택해야 합니다. 이를 위해 Listing 5-12에 표시된 것처럼 구조체 정의 바로 앞에 외부 속성 #[derive(Debug)]를 추가합니다.

이제 프로그램을 실행하면 오류가 발생하지 않으며 다음 출력을 볼 수 있습니다:

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.48s
     Running `target/debug/rectangles`
rect1 is Rectangle { width: 30, height: 50 }

좋은! 그것은 예쁜 출력이 아니다, 하지만이 인스턴스의 모든 필드의 값을 보여줍니다, 이는 확실히 디버깅하는 동안 도움이 될 것입니다. 우리는 더 큰 구조체가있을 때, 그것은 조금 읽기 쉬운 출력을하는 것이 유용합니다; 이러한 경우에, 우리는 사용할 수 있습니다 {:#?} 대신 {:?} 다음에서 println! string. 이 예제에서, {:#?} 스타일은 다음을 출력합니다.

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.48s
     Running `target/debug/rectangles`
rect1 is Rectangle {
    width: 30,
    height: 50,
}

Debug 형식을 사용하여 값을 인쇄하는 또 다른 방법은 표현식의 소유권을 갖는 dbg! 매크로를 사용하는 것입니다(참조를 받는 println!와는 반대로), dbg! 매크로 호출이 코드에서 해당 표현식의 결과값과 함께 발생하고 값의 소유권을 반환하는 파일 및 라인 번호를 인쇄합니다.

참고: dbg! 매크로를 호출하면 표준 오류 콘솔 스트림(stderr)에 출력됩니다. 이는 표준 출력 콘솔 스트림(println!)에 출력하는 stdout과 다릅니다. stderr와 stdout에 대해서는 12장의 "표준 오류로 오류 리디렉션" 섹션에서 더 자세히 다룹니다.

다음은 width 필드에 할당되는 값과 rect1 구조체 전체의 값에 관심이 있는 예입니다.

#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}

fn main() {
    let scale = 2;
    let rect1 = Rectangle {
        width: dbg!(30 * scale),
        height: 50,
    };

    dbg!(&rect1);
}

dbg! 표현식 주위에 30 * scale를 사용할 수 있습니다. dbg!는 표현식의 값에 대한 소유권을 반환하므로, width 필드는 dbg! 호출이 없는 경우와 동일한 값을 갖게 됩니다. dbg!가 rect1의 소유권을 가져가지 않도록 하려면, 다음 호출에서 rect1에 대한 참조를 사용합니다. 이 예제의 출력은 다음과 같습니다.

$ cargo run
   Compiling rectangles v0.1.0 (file:///projects/rectangles)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.61s
     Running `target/debug/rectangles`
[src/main.rs:10:16] 30 * scale = 60
[src/main.rs:14:5] &rect1 = Rectangle {
    width: 60,
    height: 50,
}

첫 번째 출력 부분이 src/main.rs의 10번째 줄에서 30 * scale 식을 디버깅하는 것에서 왔음을 볼 수 있으며, 그 결과 값은 60입니다(정수에 대해 구현된 Debug 포맷팅은 값만 출력하는 것입니다). src/main.rs의 14번째 줄의 dbg! 호출은 &rect1의 값을 출력하며, 이는 Rectangle 구조체입니다. 이 출력은 Rectangle 타입의 pretty Debug 포맷팅을 사용합니다. dbg! 매크로는 코드가 무엇을 하고 있는지 파악하려고 할 때 매우 유용할 수 있습니다!

Debug 트레이트 외에도, Rust는 derive 속성과 함께 사용하여 사용자 정의 타입에 유용한 동작을 추가할 수 있는 여러 트레이트를 제공합니다. 이러한 트레이트와 그 동작은 부록 C에 나열되어 있습니다. 10장에서 이러한 트레이트를 사용자 정의 동작으로 구현하는 방법과 자체 트레이트를 만드는 방법에 대해 다룰 것입니다. derive 외에도 많은 속성이 있습니다. 자세한 내용은 Rust Reference의 “Attributes” 섹션을 참조하십시오.

우리의 area 함수는 매우 구체적입니다. 직사각형의 면적만 계산할 뿐입니다. 이 동작을 Rectangle 구조체와 더 밀접하게 연결하는 것이 도움이 될 것입니다. 다른 타입에서는 동작하지 않기 때문입니다. area 함수를 area 메서드로 바꾸어 Rectangle 타입에 정의함으로써 이 코드를 계속 리팩토링하는 방법을 살펴보겠습니다.
