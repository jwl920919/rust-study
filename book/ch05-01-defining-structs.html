The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

구조체 정의 및 인스턴스화

구조체는 튜플 타입 섹션에서 다룬 튜플과 유사합니다. 두 구조 모두 여러 관련 값을 포함할 수 있습니다. 튜플과 마찬가지로 구조체의 각 요소는 서로 다른 타입일 수 있습니다. 그러나 튜플과 달리 구조체에서는 각 데이터에 이름을 붙여 값의 의미를 명확히 할 수 있습니다. 이러한 이름을 통해 구조체는 튜플보다 유연해집니다. 인스턴스의 값을 지정하거나 접근할 때 데이터의 순서에 의존할 필요가 없기 때문입니다.

구조체를 정의하려면 struct 키워드를 입력하고 구조체 전체에 이름을 부여합니다. 구조체의 이름은 함께 묶인 데이터 요소들의 의미를 설명해야 합니다. 그런 다음 중괄호 안에서 필드라고 불리는 데이터 요소들의 이름과 타입을 정의합니다. 예를 들어, Listing 5-1은 사용자 계정에 대한 정보를 저장하는 구조체를 보여줍니다.

struct를 정의한 후 struct를 사용하려면 각 필드에 대한 구체적인 값을 지정하여 해당 struct의 인스턴스를 만듭니다. struct의 이름을 명시한 다음 struct를 포함하는 중괄호를 추가하여 인스턴스를 만듭니다. key: value 쌍, 키는 필드의 이름이고 값은 해당 필드에 저장하려는 특정 데이터입니다. 우리는 같은 순서로 필드를 지정할 필요가 없습니다.

구조체에서 특정 값을 가져오려면 점 표기법(dot notation)을 사용합니다. 예를 들어, 이 사용자의 이메일 주소에 접근하려면 user1.email을 사용합니다. 인스턴스가 가변(mutable)인 경우, 점 표기법을 사용하여 특정 필드에 값을 할당함으로써 값을 변경할 수 있습니다. Listing 5-3은 가변한 User 인스턴스의 email 필드 값을 변경하는 방법을 보여줍니다. email 가변 필드 User 예.

전체 인스턴스가 mutable이어야 합니다. Rust는 특정 필드만 mutable로 표시하도록 허용하지 않습니다. 다른 표현식과 마찬가지로, 함수 본문의 마지막 표현식으로 구조체의 새로운 인스턴스를 생성하면 그 인스턴스를 암시적으로 반환할 수 있습니다.

Listing 5-4는 주어진 이메일과 사용자 이름으로 build_user 인스턴스를 반환하는 User 함수를 보여줍니다. active 필드는 true 값을, sign_in_count 필드는 1 값을 갖습니다.

구조체 필드와 동일한 이름을 함수 매개변수로 사용하는 것이 합리적입니다. 하지만 email와 username처럼 필드 이름과 변수 이름을 반복해야 하는 것은 다소 번거롭습니다. 구조체에 필드가 더 많다면 각 이름을 반복하는 일은 더욱 귀찮아질 것입니다. 다행히도 편리한 약어 문법이 있습니다!

필드 초기화 약어 사용

Listing 5-4에서 매개변수 이름과 구조체 필드 이름이 정확히 동일하므로, 필드 초기화 약어 문법을 사용하여 build_user 함수를 다시 작성할 수 있습니다. 이렇게 하면 동작은 정확히 동일하지만, Listing 5-5에 보인 것처럼 username과 email를 반복하지 않아도 됩니다.

여기서 User 구조체의 새로운 인스턴스를 생성합니다. 이 구조체에는 email이라는 이름의 필드가 있습니다. email 함수의 email 매개변수 값으로 build_user 필드의 값을 설정하려고 합니다. email 필드와 email 매개변수의 이름이 같으므로, email 대신에 email: email만 작성하면 됩니다.

구조체 업데이트 구문을 사용하여 인스턴스 만들기

같은 타입의 다른 인스턴스에서 대부분의 값을 가져오되 일부만 변경하여 새 인스턴스를 만드는 경우가 자주 있습니다. 이를 위해 구조체 업데이트 구문을 사용할 수 있습니다.

먼저 Listing 5-6에서는 업데이트 구문 없이 일반적인 방법으로 User에 새로운 user2 인스턴스를 만드는 방법을 보여줍니다. email에는 새로운 값을 설정하고, 그 외에는 Listing 5-2에서 생성한 user1의 값을 그대로 사용합니다.

구조체 업데이트 구문을 사용하면 Listing 5-7에 나와 있듯이 더 적은 코드로 동일한 효과를 얻을 수 있습니다. .. 구문은 명시적으로 설정하지 않은 나머지 필드가 주어진 인스턴스의 필드와 동일한 값을 가져야 함을 지정합니다.

Listing 5-7의 코드는 또한 user2에 email 값이 다르지만 username, active, sign_in_count 필드는 user1와 동일한 값을 가진 인스턴스를 생성합니다. ..user1는 반드시 마지막에 위치해야 하며, 이는 나머지 필드가 user1의 해당 필드에서 값을 가져옴을 지정하기 위함입니다. 하지만 구조체 정의에서 필드가 선언된 순서와 무관하게 원하는 필드에 값을 지정할 수 있으며, 그 순서도 자유롭게 선택할 수 있습니다.

struct 업데이트 문법이 할당처럼 =를 사용한다는 점에 유의하세요. 이는 '움직임과 상호 작용하는 변수 및 데이터'변수와 데이터의 상호작용: 이동 섹션에서 살펴본 것처럼 데이터를 이동하기 때문입니다. 이 예제에서는 user1를 만든 후 user2를 더 이상 사용할 수 없습니다. String의 username 필드에서 user1이 user2로 이동되었기 때문입니다. 만약 user2에 String과 email 모두에 새로운 username 값을 부여하여 active의 sign_in_count와 user1 값만 사용했다면, user1를 만든 후에도 user2는 여전히 유효할 것입니다. active과 sign_in_count는 모두 Copy 트레이트를 구현하는 타입이므로, '스택 전용 데이터: 복사'스택에만 저장되는 데이터: Copy 섹션에서 논의한 동작이 적용됩니다. 또한 이 예제에서는 user1.email의 값이 user1에서 이동되지 않았으므로 여전히 사용할 수 있습니다.

튜플 구조체로 다양한 타입 만들기

Rust는 튜플과 유사한 형태인 튜플 구조체(tuple struct)도 지원합니다. 튜플 구조체는 필드 이름이 없지만 구조체 이름이 제공하는 의미를 가집니다. 즉, 필드에는 이름 대신 타입만 존재합니다. 튜플 구조체는 튜플 전체에 이름을 부여하여 다른 튜플과 구별되는 새로운 타입으로 만들고 싶을 때, 또는 일반 구조체처럼 각 필드에 이름을 붙이는 것이 번거롭거나 중복될 때 유용합니다.

튜플 구조체를 정의하려면 struct 키워드와 구조체 이름, 그리고 튜플에 포함된 타입 순서대로 작성합니다. 예를 들어, 여기에서는 Color과 Point라는 두 개의 튜플 구조체를 정의하고 사용합니다.

black과 origin 값은 서로 다른 튜플 구조체의 인스턴스이므로 서로 다른 타입입니다. 구조체 내부의 필드가 동일한 타입을 가질 수 있더라도, 정의한 각 구조체는 고유한 타입입니다. 예를 들어, Color 타입의 매개변수를 받는 함수는 Point을 인수로 받을 수 없습니다. 두 타입 모두 세 개의 i32 값으로 구성되어 있지만, 타입이 다르기 때문입니다. 이 점을 제외하면 튜플 구조체 인스턴스는 튜플과 유사하게 개별 요소로 분해할 수 있으며, . 뒤에 인덱스를 붙여 개별 값에 접근할 수 있습니다. 튜플과 달리 튜플 구조체를 분해할 때는 구조체 이름을 명시해야 합니다. 예를 들어, let Point(x, y, z) = origin;라고 작성하면 origin 값들을 x, y, z이라는 변수에 분해할 수 있습니다.

유닛 구조체 정의

필드가 전혀 없는 구조체를 정의할 수도 있습니다. 이러한 구조체는 단위형 구조체(unit-like struct)라고 불리며, '튜플 타입' 섹션에서 언급한 단위 타입인 ()과 유사하게 동작하기 때문입니다. 단위형 구조체는 특정 타입에 트레이트를 구현해야 하지만 타입 자체에 저장할 데이터가 없을 때 유용합니다. 트레이트에 대한 내용은 10장에서 다룹니다. 다음은 AlwaysEqual이라는 이름의 단위 구조체를 선언하고 인스턴스화하는 예시입니다. ()튜플 타입AlwaysEqual

AlwaysEqual을 정의하려면 struct 키워드, 원하는 이름, 그리고 세미콜론을 사용합니다. 중괄호나 괄호는 필요하지 않습니다! 그런 다음, 중괄호나 괄호 없이 정의한 이름만 사용하여 AlwaysEqual 변수에 subject 인스턴스를 할당할 수 있습니다. 나중에 이 타입에 대해 모든 AlwaysEqual 인스턴스가 다른 모든 타입의 인스턴스와 항상 같다는 동작을 구현한다고 상상해 보세요. 이는 테스트 목적으로 알려진 결과를 얻기 위한 것일 수 있습니다. 이러한 동작을 구현하는 데에는 데이터가 필요하지 않습니다! 10장에서 유닛 구조체를 포함한 모든 타입에 트레이트를 정의하고 구현하는 방법을 확인할 수 있습니다.

구조체 데이터의 소유권

다음에서 User Listing 5-1의 struct definition에서, 우리는 owned를 사용했습니다 String 유형 보다는 오히려 &str string slice type. 이 구조체의 각 인스턴스가 모든 데이터를 소유하고 전체 구조체가 유효한 한 데이터가 유효하기를 원하기 때문에 신중한 선택입니다.

구조체는 다른 대상이 소유한 데이터에 대한 참조를 저장할 수도 있습니다. 하지만 그렇게 하려면 10장에서 다룰 Rust의 기능인 라이프타임(lifetimes)을 사용해야 합니다. 라이프타임은 구조체가 참조하는 데이터가 구조체가 유효한 동안 유효하도록 보장합니다. src/main.rs에서 다음과 같이 라이프타임을 지정하지 않고 구조체에 참조를 저장하려고 하면, 다음과 같은 코드는 동작하지 않습니다:
