The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

패키지, 크레이트 및 모듈

대규모 프로그램을 작성할수록 코드를 조직화하는 것이 점점 더 중요해집니다. 관련 기능을 그룹화하고 서로 다른 기능을 가진 코드를 분리하면, 특정 기능을 구현하는 코드가 어디에 있는지와 해당 기능의 동작 방식을 변경하려면 어디를 수정해야 하는지 명확해집니다.

지금까지 작성한 프로그램은 하나의 파일에 있는 하나의 모듈로 이루어져 있습니다. 프로젝트가 커지면 코드를 여러 모듈로 나누고, 다시 여러 파일로 분리하여 구성해야 합니다. 하나의 패키지는 여러 바이너리 크레이트와 선택적으로 하나의 라이브러리 크레이트를 포함할 수 있습니다. 패키지가 커지면 일부 코드를 별도의 크레이트로 추출하여 외부 종속성으로 사용할 수 있습니다. 이 장에서는 이러한 모든 기법을 다룹니다. 함께 발전하는 서로 관련 있는 패키지 집합으로 구성된 매우 큰 프로젝트의 경우, Cargo는 워크스페이스를 제공하며, 이는 14장의 “Cargo Workspaces”에서 다룹니다. Cargo 작업 공간

또한 구현 세부 사항을 캡슐화하는 것에 대해서도 논의합니다. 이를 통해 더 높은 수준에서 코드를 재사용할 수 있습니다. 한 번 작업을 구현하면, 다른 코드는 구현이 어떻게 작동하는지 알 필요 없이 공개 인터페이스를 통해 해당 코드를 호출할 수 있습니다. 코드를 작성하는 방식은 다른 코드가 사용할 수 있는 공개 부분과 변경할 권리를 보유하는 비공개 구현 세부 사항을 정의합니다. 이는 머릿속에 기억해야 할 세부 사항의 양을 줄이는 또 다른 방법입니다.

관련된 개념은 스코프입니다. 코드가 작성된 중첩된 컨텍스트에는 '스코프 내'로 정의된 이름의 집합이 있습니다. 코드를 읽고, 쓰고, 컴파일할 때 프로그래머와 컴파일러는 특정 위치의 특정 이름이 변수, 함수, 구조체, 열거형, 모듈, 상수 또는 기타 항목을 가리키는지, 그리고 그 항목이 무엇을 의미하는지 알아야 합니다. 스코프를 생성하고 스코프 내외의 이름을 변경할 수 있습니다. 동일한 스코프 내에 동일한 이름을 가진 두 항목을 가질 수 없으며, 이름 충돌을 해결하기 위한 도구가 제공됩니다.

Rust에는 코드의 조직화를 관리하는 여러 기능이 있습니다. 여기에는 어떤 세부 사항이 노출되는지, 어떤 세부 사항이 비공개인지, 그리고 프로그램의 각 스코프에 어떤 이름이 포함되는지가 포함됩니다. 이러한 기능들은 때때로 모듈 시스템(module system)이라고도 불립니다. 여기에는 다음이 포함됩니다:

  • 패키지: 크레이트를 빌드, 테스트 및 공유할 수 있도록 하는 Cargo 기능
  • 크레이트: 라이브러리 또는 실행 파일을 생성하는 모듈 트리
  • 모듈과 use: 경로의 조직, 범위, 프라이버시를 제어할 수 있게 해 줍니다
  • 경로: 구조체, 함수, 모듈과 같은 항목에 이름을 붙이는 방법

이 장에서는 이러한 모든 기능을 다루고, 이들이 어떻게 상호작용하는지 논의하며, 범위를 관리하는 데 이들을 어떻게 사용하는지 설명합니다. 이 장을 마치면 모듈 시스템에 대해 탄탄한 이해를 갖추게 되며, 전문가처럼 범위를 다룰 수 있게 됩니다!
