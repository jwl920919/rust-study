The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

슬라이스 타입

슬라이스를 사용하면 모음집에서 연속된 요소를 참조할 수 있습니다. 슬라이스는 일종의 참조이므로 소유권이 없습니다.

다음은 작은 프로그래밍 문제입니다. 공백으로 구분된 단어의 문자열을 받아 해당 문자열에서 찾은 첫 번째 단어를 반환하는 함수를 작성해 보세요. 함수가 문자열에서 공백을 찾지 못하면, 전체 문자열이 하나의 단어이므로 전체 문자열을 반환해야 합니다.

참고: 슬라이스를 소개하기 위해 이 섹션에서는 ASCII만 가정합니다. UTF-8 처리에 대한 더 자세한 논의는 8장의 "문자열로 UTF-8 인코딩된 텍스트 저장" 섹션에 있습니다.

슬라이스를 사용하지 않고 이 함수의 시그니처를 작성하는 방법을 살펴봄으로써, 슬라이스가 해결할 문제를 이해해 보겠습니다.

fn first_word(s: &String) -> ?

first_word 함수는 &String 타입의 인수를 가집니다. 소유권이 필요하지 않으므로 이렇게 하는 것은 괜찮습니다. (아이디오매틱한 Rust에서는 함수가 필요하지 않는 한 인수의 소유권을 가져오지 않으며, 그 이유는 계속 진행하면서 명확해질 것입니다.) 하지만 무엇을 반환해야 할까요? 문자열의 일부에 대해 표현할 방법이 실제로 없습니다. 그러나 공백으로 표시된 단어의 끝 인덱스를 반환할 수는 있습니다. Listing 4-7에 표시된 것처럼 이 방법을 시도해 보겠습니다.

String 요소를 하나씩 살펴보고 값이 공백인지 확인해야 하므로, String 메서드를 사용하여 as_bytes를 바이트 배열로 변환합니다.

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }

    s.len()
}

fn main() {}

다음으로, iter 메소드를 사용하여 바이트 배열에 대한 반복자를 생성합니다:

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }

    s.len()
}

fn main() {}

제13장에서 반복자에 대해 더 자세히 다룹니다. 지금은 iter이 컬렉션의 각 요소를 반환하는 메소드이며, enumerate은 iter의 결과를 감싸서 각 요소를 튜플의 일부로 반환한다는 점만 알면 됩니다. enumerate에서 반환되는 튜플의 첫 번째 요소는 인덱스이고, 두 번째 요소는 해당 요소에 대한 참조입니다. 이는 인덱스를 직접 계산하는 것보다 조금 더 편리합니다.

enumerate 메서드가 튜플을 반환하므로, 패턴을 사용해 해당 튜플을 분해할 수 있습니다. 패턴에 대해 6장에서 더 자세히 다룹니다. for 루프에서는 튜플의 인덱스에 i, 튜플의 단일 바이트에 &item을(를) 갖는 패턴을 지정합니다. .iter().enumerate()에서 요소에 대한 참조를 얻으므로, 패턴에서 &을(를) 사용합니다.

for 루프 안에서 바이트 리터럴 구문을 사용하여 공백을 나타내는 바이트를 찾습니다. 공백을 찾으면 해당 위치를 반환합니다. 그렇지 않으면 s.len()을 사용하여 문자열의 길이를 반환합니다.

fn first_word(s: &String) -> usize {
    let bytes = s.as_bytes();

    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return i;
        }
    }

    s.len()
}

fn main() {}

이제 문자열에서 첫 번째 단어의 끝 인덱스를 찾을 수 있는 방법이 있지만 문제가 있습니다. 우리는 usize만 반환하는데, 이 값은 &String의 맥락 안에서만 의미 있는 숫자입니다. 다시 말해, 이 값은 String와 별개의 값이므로, 미래에도 여전히 유효할 것이라는 보장이 없습니다. Listing 4-7의 first_word 함수를 사용하는 Listing 4-8의 프로그램을 살펴보세요.

이 프로그램은 오류 없이 컴파일되며, word 호출 후에도 s.clear()를 사용한다면 마찬가지입니다. word는 s의 상태와 전혀 연결되어 있지 않기 때문에, word는 여전히 값 5를 포함합니다. 5. 우리는 그 값 5를 사용하여 변수 5와 함께 첫 번째 단어를 추출하려고 할 수 있지만, 이는 버그가 될 것입니다. s에 5를 저장한 후 s의 내용이 변경되었기 때문입니다. 5 word.

word의 인덱스가 s의 데이터와 동기화되지 않을까 걱정해야 하는 것은 지루하고 오류가 발생하기 쉽습니다! second_word 함수를 작성한다면 인덱스 관리는 더욱 취약해집니다. 그 서명은 다음과 같아야 합니다:

fn second_word(s: &String) -> (usize, usize) {

이제 시작 인덱스와 끝 인덱스를 추적하고 있으며, 특정 상태의 데이터에서 계산되었지만 해당 상태와 전혀 관련이 없는 값이 더 많이 존재합니다. 동기화를 유지해야 하는 서로 무관한 세 가지 변수가 떠다니고 있습니다.

다행히도 Rust에는 이 문제를 해결하는 방법이 있습니다. 바로 문자열 슬라이스입니다.

문자열 슬라이스

문자열 슬라이스는 String 요소의 연속된 시퀀스에 대한 참조이며, 다음과 같은 형태를 가집니다:

fn main() {
    let s = String::from("hello world");

    let hello = &s[0..5];
    let world = &s[6..11];
}

String 전체에 대한 참조가 아니라, hello은(는) String의 일부에 대한 참조이며, 이는 추가된 [0..5] 비트로 지정됩니다. 우리는 [starting_index..ending_index]을(를) 지정하여 대괄호 안의 범위를 사용해 슬라이스를 생성합니다. 여기서 starting_index은 슬라이스의 첫 번째 위치이고, ending_index은 슬라이스의 마지막 위치보다 1 큰 값입니다. 내부적으로, 슬라이스 데이터 구조는 시작 위치와 슬라이스의 길이를 저장하며, 이는 ending_index에서 starting_index을(를) 뺀 값에 해당합니다. 따라서 let world = &s[6..11];의 경우, world은(는) s의 인덱스 6에 있는 바이트를 가리키는 포인터와 길이 값 5을(를) 포함하는 슬라이스가 됩니다.

그림 4-7은 이를 다이어그램으로 보여줍니다.

그림 4-7: String의 일부를 참조하는 문자열 슬라이스

Rust의 .. 범위 구문을 사용하면 인덱스 0에서 시작하려는 경우 두 점 앞의 값을 생략할 수 있습니다. 즉, 다음 두 표현은 동일합니다:

#![allow(unused)]
fn main() {
let s = String::from("hello");

let slice = &s[0..2];
let slice = &s[..2];
}

마찬가지로, 슬라이스에 String의 마지막 바이트가 포함되어 있다면 끝 번호를 생략할 수 있습니다. 즉, 다음 두 표현은 동일합니다.

#![allow(unused)]
fn main() {
let s = String::from("hello");

let len = s.len();

let slice = &s[3..len];
let slice = &s[3..];
}

또한 두 값을 모두 생략하여 문자열 전체의 슬라이스를 가져올 수도 있습니다. 따라서 다음 두 표현은 동일합니다:

#![allow(unused)]
fn main() {
let s = String::from("hello");

let len = s.len();

let slice = &s[0..len];
let slice = &s[..];
}

참고: 문자열 슬라이스의 범위 인덱스는 유효한 UTF-8 문자 경계에 위치해야 합니다. 멀티바이트 문자 중간에서 문자열 슬라이스를 생성하려고 하면 프로그램이 오류와 함께 종료됩니다.

Listing 4-7에서 했던 것과 동일한 방법으로, 공백의 첫 번째 발생 위치를 찾아 단어 끝 인덱스를 구합니다. 공백을 찾으면 문자열의 시작 위치와 공백의 인덱스를 각각 시작 인덱스와 끝 인덱스로 사용하여 문자열 슬라이스를 반환합니다.

이제 first_word을 호출하면 기반 데이터에 연결된 단일 값이 반환됩니다. 이 값은 슬라이스의 시작 지점을 가리키는 참조와 슬라이스의 요소 수로 구성됩니다.

슬라이스를 반환하는 방식은 second_word 함수에서도 동일하게 적용됩니다:

이제 컴파일러가 String에 대한 참조가 유효한 상태를 유지하도록 보장하므로, 실수하기 훨씬 어려운 직관적인 API를 갖추게 되었습니다. Listing 4-8의 프로그램에서 첫 번째 단어의 끝 인덱스를 구한 후 문자열을 비워 인덱스가 유효하지 않게 된 버그를 기억하시나요? 그 코드는 논리적으로 올바르지 않았지만 즉각적인 오류는 발생하지 않았습니다. 비어 있는 문자열로 첫 번째 단어 인덱스를 계속 사용하려고 하면 나중에 문제가 드러났을 것입니다. 슬라이스는 이러한 버그를 불가능하게 만들며, 코드에 문제가 있음을 훨씬 일찍 알려줍니다. 슬라이스 버전의 first_word을 사용하면 컴파일 타임 오류가 발생합니다:

차용 규칙에서 살펴본 바와 같이, 어떤 대상에 불변 참조를 가지고 있다면 동시에 가변 참조를 가져갈 수 없습니다. clear은 String을 잘라내야 하므로 가변 참조를 얻어야 합니다. clear 호출 이후의 println!는 word의 참조를 사용하므로, 그 시점에 불변 참조가 여전히 활성 상태여야 합니다. Rust는 clear의 가변 참조와 word의 불변 참조가 동시에 존재하는 것을 허용하지 않으며, 컴파일은 실패합니다. Rust는 우리의 API를 더 쉽게 사용할 수 있게 할 뿐만 아니라, 컴파일 시점에 오류의 한 유형을 완전히 제거했습니다!

슬라이스로서의 문자열 리터럴

문자열 리터럴이 바이너리 안에 저장된다는 내용을 앞서 이야기했습니다. 이제 슬라이스에 대해 알았으므로, 문자열 리터럴을 제대로 이해할 수 있습니다:

#![allow(unused)]
fn main() {
let s = "Hello, world!";
}

여기서 s의 타입은 &str입니다. 이는 바이너리의 특정 지점을 가리키는 슬라이스입니다. 이것이 또한 문자열 리터럴이 불변인 이유입니다. &str는 불변 참조이므로요.

fn first_word(s: &String) -> &str {

경험이 많은 Rustacean이라면 &String 값과 &str 값 모두에서 동일한 함수를 사용할 수 있기 때문에 Listing 4-9에 표시된 서명을 대신 작성할 것입니다.

문자열 슬라이스가 있으면 이를 직접 전달할 수 있습니다. String가 있으면 String의 슬라이스나 String에 대한 참조를 전달할 수 있습니다. 이러한 유연성은 디리프 강제 변환(deref coercions)이라는 기능을 활용하며, 이 기능은 15장의 “함수와 메서드에서 디리프 강제 변환 사용” 섹션에서 다룹니다.

String에 대한 참조 대신 문자열 슬라이스를 받는 함수를 정의하면, 기능을 잃지 않으면서 API를 더 일반적이고 유용하게 만들 수 있습니다.

다른 슬라이스

문자열 슬라이스는 문자열에 특화되어 있습니다. 하지만 더 일반적인 슬라이스 타입도 있습니다. 다음 배열을 생각해 보세요:

#![allow(unused)]
fn main() {
let a = [1, 2, 3, 4, 5];
}

문자열의 일부를 참조하듯이, 배열의 일부를 참조하고 싶을 수 있습니다. 이렇게 하면 됩니다:

#![allow(unused)]
fn main() {
let a = [1, 2, 3, 4, 5];

let slice = &a[1..3];

assert_eq!(slice, &[2, 3]);
}

이 슬라이스의 타입은 &[i32]입니다. 첫 번째 요소에 대한 참조와 길이를 저장하여 문자열 슬라이스와 동일한 방식으로 작동합니다. 이 유형의 슬라이스는 다양한 다른 컬렉션에 사용됩니다. 이러한 컬렉션은 8장에서 벡터를 다룰 때 자세히 설명합니다.

요약

소유권, 빌림, 슬라이스의 개념은 Rust 프로그램에서 컴파일 시간에 메모리 안전을 보장합니다. Rust 언어는 다른 시스템 프로그래밍 언어와 동일한 방식으로 메모리 사용에 대한 제어권을 제공합니다. 하지만 데이터 소유자가 스코프를 벗어날 때 해당 데이터가 자동으로 정리되므로, 이러한 제어를 위해 추가 코드를 작성하고 디버깅할 필요가 없습니다.

소유권은 Rust의 다른 많은 부분에 영향을 미치므로, 이 책의 나머지 부분에서 이러한 개념을 계속 다룹니다. 이제 5장으로 넘어가서 struct에서 데이터를 어떻게 그룹화하는지 살펴봅시다.
