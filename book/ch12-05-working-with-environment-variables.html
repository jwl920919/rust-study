The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

환경 변수로 작업하기

minigrep 바이너리에 사용자가 환경 변수를 통해 활성화할 수 있는 대소문자 구분 없이 검색하는 기능을 추가하여 개선하겠습니다. 이 기능을 명령줄 옵션으로 만들어 사용자가 적용할 때마다 매번 입력하도록 할 수도 있지만, 대신 환경 변수를 사용하면 사용자가 환경 변수를 한 번만 설정해도 해당 터미널 세션에서 모든 검색이 대소문자를 구분하지 않도록 할 수 있습니다.

대소문자 구분 없이 검색하는 기능에 대한 실패 테스트 작성하기

먼저 minigrep 라이브러리에 search_case_insensitive 함수를 추가합니다. 이 함수는 minigrep 환경 변수가 값을 가질 때 호출됩니다. TDD 프로세스를 계속 따르므로 첫 번째 단계는 다시 실패하는 테스트를 작성하는 것입니다. search_case_insensitive 함수에 대한 새 테스트를 추가하고, 두 테스트의 차이를 명확히 하기 위해 기존 테스트 이름을 one_result에서 case_sensitive로 변경합니다. Listing 12-20을 참고하세요.

기존 테스트의 contents도 수정했음을 유의하세요. 대문자 D를 사용한 "Duct tape."라는 새로운 줄을 추가했습니다. 이는 대소문자를 구분하는 방식으로 검색할 때 쿼리 "duct"와 일치하지 않아야 합니다. 기존 테스트를 이렇게 수정하면 이미 구현한 대소문자 구분 검색 기능이 우연히 깨지지 않도록 하는 데 도움이 됩니다. 이 테스트는 이제 통과해야 하며, 대소문자 구분하지 않는 검색을 작업하는 동안에도 계속 통과해야 합니다.

상기 구현 The implementing search_case_insensitive 기능

Listing 12-21에 표시된 search_case_insensitive 함수는 search 함수와 거의 동일합니다. 유일한 차이점은 query와 각 line를 소문자로 변환한다는 점입니다. 이렇게 하면 입력 인수의 대소문자와 관계없이, 해당 행에 쿼리가 포함되어 있는지 확인할 때 동일한 대소문자 기준으로 비교할 수 있습니다.

먼저, query 문자열을 소문자로 변환하여 같은 이름의 새 변수에 저장합니다. 이를 통해 원본 query을 그림자 처리(shadowing)합니다. to_lowercase를 호출하는 이유는 사용자의 쿼리가 "rust", "RUST", "Rust", 또는 "rUsT"인 경우와 관계없이, 쿼리를 항상 "rust"인 것처럼 처리하여 대소문자를 구분하지 않기 위해서입니다. to_lowercase은 기본 유니코드를 처리하지만 100% 정확하지는 않습니다. 실제 애플리케이션을 작성한다면 여기서 더 많은 작업을 수행해야 하지만, 이 섹션은 유니코드가 아닌 환경 변수에 관한 것이므로 여기서는 이 정도로 마무리하겠습니다.

참고로, query은 이제 문자열 슬라이스가 아니라 String입니다. to_lowercase를 호출하면 기존 데이터를 참조하는 대신 새 데이터를 생성하기 때문입니다. 예를 들어 쿼리가 "rUsT"라고 가정해 보겠습니다. 이 문자열 슬라이스에는 우리가 사용할 수 있는 소문자 u 또는 t가 포함되어 있지 않으므로, String을 포함하는 새로운 "rust"을 할당해야 합니다. 이제 query을 인수로 contains 메서드에 전달할 때, contains 메서드의 시그니처가 문자열 슬라이스를 받도록 정의되어 있으므로 앰퍼샌드(&)를 추가해야 합니다.

다음으로 to_lowercase를 각 line에 호출하여 모든 문자를 소문자로 만듭니다. 이제 line 및 query를 소문자로 변환 했으므로 쿼리의 경우와 상관없이 일치하는 항목을 찾을 수 있습니다.

파일 이름: src/main.rs

use std::env;
use std::error::Error;
use std::fs;
use std::process;

use minigrep::{search, search_case_insensitive};

// --snip--


fn main() {
    let args: Vec<String> = env::args().collect();

    let config = Config::build(&args).unwrap_or_else(|err| {
        println!("Problem parsing arguments: {err}");
        process::exit(1);
    });

    if let Err(e) = run(config) {
        println!("Application error: {e}");
        process::exit(1);
    }
}

pub struct Config {
    pub query: String,
    pub file_path: String,
    pub ignore_case: bool,
}

impl Config {
    fn build(args: &[String]) -> Result<Config, &'static str> {
        if args.len() < 3 {
            return Err("not enough arguments");
        }

        let query = args[1].clone();
        let file_path = args[2].clone();

        Ok(Config { query, file_path })
    }
}

fn run(config: Config) -> Result<(), Box<dyn Error>> {
    let contents = fs::read_to_string(config.file_path)?;

    let results = if config.ignore_case {
        search_case_insensitive(&config.query, &contents)
    } else {
        search(&config.query, &contents)
    };

    for line in results {
        println!("{line}");
    }

    Ok(())
}

Boolean 타입의 ignore_case 필드를 추가했습니다. 다음으로, run 함수에서 ignore_case 필드의 값을 확인하여 search 함수를 호출할지, 아니면 search_case_insensitive 함수를 호출할지 결정해야 합니다. Listing 12-22에 이를 보여 드립니다. 이 코드는 아직 컴파일되지 않습니다.

마지막으로, 환경 변수를 확인해야 합니다. 환경 변수를 다루는 함수는 다음과 같습니다. env module은 표준 라이브러리에 포함되어 있으며, 이 라이브러리는 이미 맨 위에 있습니다. 한국어 (ko). 우리는 사용할 것입니다 var 에서 기능 env module : 이름이 지정된 환경변수에 어떤 값이 설정되었는지 확인한다. IGNORE_CASEListing 12-23에 나와 있는 내용입니다.

여기서 새로운 변수인 ignore_case을(를) 생성합니다. 값을 설정하기 위해 env::var 함수를 호출하고, IGNORE_CASE 환경 변수의 이름을 인수로 전달합니다. env::var 함수는 Result를 반환합니다. 환경 변수가 어떤 값으로든 설정되어 있다면, 해당 환경 변수의 값을 포함하는 성공적인 Ok 변형을 반환합니다. 환경 변수가 설정되지 않은 경우에는 Err 변형을 반환합니다.

is_ok의 Result 메서드를 사용하여 환경 변수가 설정되었는지 확인합니다. 환경 변수가 설정되어 있으면 프로그램은 대소문자를 구분하지 않는 검색을 수행해야 합니다. IGNORE_CASE 환경 변수가 아무 값으로도 설정되지 않았다면, is_ok은 false를 반환하고 프로그램은 대소문자를 구분하는 검색을 수행합니다. 값 자체보다는 환경 변수가 설정되었는지 여부만 중요하므로, is_ok을 확인하는 방식을 사용합니다. unwrap, expect 또는 Result에서 확인한 다른 메서드를 사용하는 것보다 이 방식이 적합합니다.

ignore_case 변수의 값을 Config 인스턴스에 전달하면, run 함수가 해당 값을 읽어 search_case_insensitive 또는 search 중 어느 것을 호출할지 결정할 수 있습니다. 이는 12-22 목록에서 구현한 내용과 같습니다.

먼저 환경 변수를 설정하지 않고 쿼리를 to로 지정해 프로그램을 실행해 보겠습니다. 이 쿼리는 소문자 to가 포함된 모든 줄과 일치해야 합니다:

PowerShell을 사용하는 경우, 환경 변수를 설정하고 프로그램을 실행하는 것을 별도의 명령으로 나누어 실행해야 합니다:

PS> $Env:IGNORE_CASE=1; cargo run -- to poem.txt

이렇게 하면 IGNORE_CASE이 현재 쉘 세션이 종료될 때까지 유지됩니다. Remove-Item cmdlet을 사용하여 이 변수를 해제할 수 있습니다:

PS> Remove-Item Env:IGNORE_CASE

일부 프로그램은 동일한 설정에 대해 인수와 환경 변수를 모두 허용합니다. 이러한 경우 프로그램은 둘 중 하나가 우선하도록 결정합니다. 스스로 연습해 볼 수 있는 또 다른 과제로, 명령줄 인수 또는 환경 변수를 통해 대소문자 구분을 제어해 보세요. 프로그램이 한쪽은 대소문자를 구분하도록, 다른 한쪽은 대소문자를 무시하도록 설정된 상태로 실행될 때, 명령줄 인수가 우선해야 하는지 환경 변수가 우선해야 하는지 결정해 보세요.

std::env 모듈에는 환경 변수를 다루기 위한 더 많은 유용한 기능이 포함되어 있습니다. 사용 가능한 기능을 확인하려면 해당 모듈의 문서를 살펴보세요.
