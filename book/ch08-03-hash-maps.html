The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

해시 맵에 키와 연관된 값 저장

공통 컬렉션의 마지막은 해시 맵입니다. HashMap<K, V> 타입의 키의 맵핑 저장 K 타입의 값 V 사용 A 해싱 함수이러한 키와 값을 메모리에 배치하는 방법을 결정합니다. 많은 프로그래밍 언어는 이러한 종류의 데이터 구조를 지원하지만 종종 다음과 같은 다른 이름을 사용합니다. 해시, 지도, 객체, 해시 테이블, 사전, 또는 연관 배열그냥 몇 가지 이름을합니다.

해시 맵은 벡터처럼 인덱스를 사용하여 데이터를 조회하는 대신, 어떤 타입이든 될 수 있는 키를 사용하여 데이터를 조회할 때 유용합니다. 예를 들어 게임에서 각 키가 팀 이름이고 값이 해당 팀의 점수인 해시 맵을 사용하여 각 팀의 점수를 추적할 수 있습니다. 팀 이름을 주면 해당 점수를 가져올 수 있습니다.

이 섹션에서는 해시 맵의 기본 API를 살펴보겠습니다. 하지만 표준 라이브러리가 HashMap<K, V>에 정의한 함수에는 더 많은 유용한 기능이 숨어 있습니다. 항상 그렇듯이, 더 자세한 정보는 표준 라이브러리 문서를 확인하십시오.

새로운 해시 맵 만들기

빈 해시 맵을 만드는 한 가지 방법은 new을 사용하고 insert로 요소를 추가하는 것입니다. Listing 8-20에서는 Blue와 Yellow라는 이름을 가진 두 팀의 점수를 추적하고 있습니다. Blue 팀은 10점으로 시작하고, Yellow 팀은 50점으로 시작합니다.

표준 라이브러리의 컬렉션 부분에서 useHashMapHashMap을 먼저 사용해야 한다는 점에 유의하세요. 세 가지 일반적인 컬렉션 중 이 컬렉션은 가장 덜 사용되므로, 프렐류드에서 자동으로 스코프에 가져오는 기능에 포함되지 않습니다. 또한 해시 맵은 표준 라이브러리에서 제공하는 지원도 적습니다. 예를 들어, 해시 맵을 생성하기 위한 내장 매크로는 없습니다.

벡터와 마찬가지로 해시 맵은 데이터를 힙에 저장합니다. 이 HashMap에는 String 유형의 키와 i32 유형의 값이 있습니다. 벡터와 마찬가지로 해시 맵은 균질합니다. 모든 키는 동일한 유형을 가져야 하며, 모든 값도 동일한 유형을 가져야 합니다.

해시 맵에서 값 접근

Listing 8-21과 같이 get 메서드에 키를 전달하여 해시 맵에서 값을 가져올 수 있습니다.

여기서 score은 Blue 팀과 연관된 값을 가지며, 그 결과는 10입니다. get 메서드는 Option<&V>을 반환합니다. 해시 맵에 해당 키에 대한 값이 없다면, get을 반환합니다. None. 이 프로그램은 Option을 호출하여 copied 대신 Option<i32>을 얻은 후, Option<&i32>을 호출하여 unwrap_or에 score이 없으면 scores을 0으로 설정합니다.

for 루프를 사용하여 벡터와 유사한 방식으로 해시 맵의 각 키-값 쌍을 반복할 수 있습니다.

fn main() {
    use std::collections::HashMap;

    let mut scores = HashMap::new();

    scores.insert(String::from("Blue"), 10);
    scores.insert(String::from("Yellow"), 50);

    for (key, value) in &scores {
        println!("{key}: {value}");
    }
}

이 코드는 각 쌍을 임의의 순서로 출력합니다:

Yellow: 50
Blue: 10

해시 맵에서 소유권 관리

Copy 트레잇을 구현하는 타입의 경우, i32와 같은 값은 해시 맵에 복사됩니다. String와 같은 소유권 값을 넣는 경우, 값이 이동되며 해시 맵이 해당 값의 소유자가 됩니다. 이 동작은 Listing 8-22에서 확인할 수 있습니다.

field_name와 field_value 변수는 insert 호출을 통해 해시 맵으로 소유권이 이동한 후에는 사용할 수 없습니다.

해시 맵에 값에 대한 참조를 삽입하면, 값은 해시 맵으로 이동되지 않습니다. 참조가 가리키는 값은 해시 맵이 유효한 기간 동안 적어도 유효해야 합니다. 이러한 문제에 대해서는 10장의 “라이프타임으로 참조 검증하기”에서 자세히 다루겠습니다.

해시 맵 업데이트

키와 값 쌍의 수는 증가할 수 있지만, 각 고유 키는 한 번에 하나의 값만 가질 수 있습니다(예: Blue 팀과 Yellow 팀은 모두 10에 저장된 값을 scores 해시 맵에 가질 수 있음).

해시 맵의 데이터를 변경하려면 키에 이미 값이 할당된 경우를 어떻게 처리할지 결정해야 합니다. 이전 값을 무시하고 새 값으로 대체할 수도 있고, 이전 값을 유지하고 새 값을 무시할 수도 있습니다. 이 경우 키에 이미 값이 없는 경우에만 새 값을 추가합니다. 또는 이전 값과 새 값을 결합할 수도 있습니다. 각각의 방법을 살펴보겠습니다!

이 코드는 {"Blue": 25}를 인쇄합니다. 10의 원래 값을 덮어 씁니다.

키가 없는 경우에만 키와 값 추가

해시 맵에 특정 키가 이미 값과 함께 존재하는지 확인한 후 다음 작업을 수행하는 것이 일반적입니다. 키가 해시 맵에 존재하는 경우 기존 값은 그대로 유지해야 하고, 존재하지 않는 경우 해당 키와 값을 삽입해야 합니다.

Hash map은 이것을 위한 특별한 API를 가지고 있습니다. entry 파라미터로 확인하려는 키를 가져옵니다. 반환값은 다음과 같습니다. entry 메서드는 호출된 열거형입니다. Entry 이는 존재할 수도 있고 존재하지 않을 수도 있는 값을 나타냅니다. Yellow 팀의 키가 그것과 관련된 값을 가지고 있는지 확인하고 싶다고 가정해 봅시다. 그렇지 않다면, 우리는 그 값을 삽입하고 싶습니다. 50블루팀도 마찬가지입니다. 블루팀도 마찬가지입니다. entry API, 코드는 Listing 8-24와 같습니다.

Entry의 or_insert 메서드는 해당 Entry 키가 존재하는 경우 해당 값에 대한 가변 참조를 반환하도록 정의되어 있습니다. 해당 키가 존재하지 않는 경우, 매개변수를 이 키의 새로운 값으로 삽입하고 새로운 값에 대한 가변 참조를 반환합니다. 이 기법은 우리가 직접 로직을 작성하는 것보다 훨씬 깔끔하며, 추가로 빌로우 체커와도 더 잘 동작합니다.

Listing 8-24에서 코드를 실행하면 인쇄됩니다 {"Yellow": 50, "Blue": 10}. 첫 번째 호출 entry 값을 가진 Yellow 팀의 키를 삽입합니다. 50 왜냐하면 Yellow 팀은 이미 가치가 없기 때문입니다. 두 번째 호출 entry 블루 팀은 이미 값을 가지고 있기 때문에 해시 맵을 변경하지 않습니다. 10.

이전 값에 기반하여 값 업데이트

해시 맵의 또 다른 일반적인 사용 사례는 키의 값을 조회한 후 이전 값에 기반하여 값을 업데이트하는 것입니다. 예를 들어, Listing 8-25는 특정 텍스트에서 각 단어가 몇 번 나타나는지 세는 코드를 보여줍니다. 우리는 단어를 키로 사용하는 해시 맵을 통해 값을 증가시켜 해당 단어를 몇 번 확인했는지 추적합니다. 단어를 처음 확인하는 경우, 먼저 값 0을 삽입합니다. 0

split_whitespace 메서드는 text의 값을 공백으로 구분된 부분 슬라이스로 반복하는 반복자를 반환합니다. or_insert 메서드는 지정된 키의 값에 대한 가변 참조(&mut V)를 반환합니다. 여기서는 그 가변 참조를 count 변수에 저장하므로, 해당 값에 할당하려면 먼저 별표(*)를 사용하여 count를 디리퍼런싱해야 합니다. 가변 참조는 for 루프의 끝에서 스코프를 벗어나므로, 이러한 모든 변경은 빌로우 규칙에 의해 안전하고 허용됩니다.

해싱 함수

기본적으로 HashMap은 SipHash라는 해시 함수를 사용합니다. 이 함수는 해시 테이블을 이용한 서비스 거부(DoS) 공격에 대한 저항성을 제공할 수 있습니다1. 이는 사용할 수 있는 가장 빠른 해시 알고리즘은 아니지만, 성능 저하를 감수하더라도 더 나은 보안을 얻는 것이 가치가 있습니다. 코드를 프로파일링한 결과 기본 해시 함수가 목적에 비해 너무 느리다고 판단되면, 다른 해셔를 지정하여 다른 함수로 전환할 수 있습니다. 해셔는 BuildHasher 트레이트를 구현하는 타입입니다. 트레이트와 그 구현 방법은 10장에서 다룹니다. 반드시 처음부터 자체 해셔를 구현할 필요는 없습니다. crates.io에는 다른 Rust 사용자가 공유한 라이브러리가 있으며, 이 라이브러리들은 많은 일반적인 해시 알고리즘을 구현하는 해셔를 제공합니다.

요약

벡터, 문자열, 해시 맵은 데이터를 저장하고, 접근하며, 수정할 때 프로그램에 필요한 다양한 기능을 제공합니다. 이제 다음과 같은 연습 문제를 해결할 수 있어야 합니다:

  1. 정수 목록이 주어졌을 때, 벡터를 사용하여 목록의 중앙값(정렬했을 때 중간 위치의 값)과 최빈값(가장 자주 나타나는 값. 여기서는 해시 맵이 도움이 됩니다)을 반환하세요.
  2. 문자열을 Pig Latin으로 변환하세요. 각 단어의 첫 자음은 단어의 끝으로 이동하고 'ay'가 추가되므로, 'first'는 'irst-fay'가 됩니다. 모음으로 시작하는 단어는 대신 끝에 'hay'를 추가합니다(예: 'apple'은 'apple-hay'가 됩니다). UTF-8 인코딩에 대한 세부 사항을 주의하세요!
  3. 해시 맵과 벡터를 사용하여, 사용자가 회사의 부서로 직원 이름을 추가할 수 있는 텍스트 인터페이스를 만드세요. 예를 들어, “Sally를 Engineering에 추가” 또는 “Amir를 Sales에 추가”와 같습니다. 그런 다음, 사용자가 부서별 또는 회사 전체의 모든 사람을 알파벳 순서로 정렬된 목록으로 검색할 수 있도록 하세요.
