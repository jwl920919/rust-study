The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

비동기 프로그래밍의 기본 사항 : 비동기, 대기, 미래 및 스트림

우리가 컴퓨터에게 하라고 요청하는 많은 연산들은 시간이 좀 걸릴 수 있습니다. 장기간 실행되는 프로세스가 완료되기를 기다리는 동안 다른 일을 할 수 있다면 좋을 것입니다. 현대 컴퓨터는 한 번에 두 개 이상의 연산을 수행하는 두 가지 기술을 제공합니다. 병렬 처리와 동시 처리입니다. 그러나 우리 프로그램의 로직은 대부분 선형 방식으로 작성됩니다. 우리는 프로그램이 수행해야 하는 연산을 지정하고 각 함수가 실행되어야 하는 부분을 지정하고 싶습니다.

이 장은 러스트의 미래, 스트림, async 및 await 구문과 같이 코드를 작성하기 위한 대안적인 접근 방식을 도입하여 병렬 처리 및 동시성을 위한 스레드를 사용하는 제16장과 비동기식 런타임을 구현하는 타사 크레이트를 기반으로 합니다: 비동기식 작업의 실행을 관리하고 조정하는 코드.

예를 들어, 가족 축하 행사로 만든 비디오를 몇 분에서 몇 시간 정도 소요될 수 있는 작업으로 내보내고 있다고 가정해 보겠습니다. 비디오 내보내기는 가능한 한 많은 CPU 및 GPU 전력을 사용합니다. CPU 코어가 하나뿐이고 운영 체제가 완료될 때까지 내보내기를 일시 중지하지 않은 경우, 즉 동시에 내보내기를 실행하면 컴퓨터에서 다른 작업을 수행할 수 없습니다.

이제 다른 사람이 공유 한 비디오를 다운로드한다고 가정 해 봅시다.이 비디오는 시간이 걸릴 수 있지만 CPU 시간이 많이 걸리지 않습니다. 이 경우 CPU는 네트워크에서 데이터가 도착할 때까지 기다려야합니다. 모든 작업이 시작되면 다른 데이터를 읽기 시작할 수 있지만 모든 프로그램이 나타나기까지 시간이 걸릴 수 있습니다. 데이터가 모두 존재하더라도 비디오가 매우 크면 적어도 두 번째 또는 두 번째 대기 시간이 걸릴 수 있습니다.

비디오 내보내기는 CPU 바인딩 또는 컴퓨팅 바인딩 작업의 예입니다. CPU 또는 GPU 내에서 컴퓨터의 잠재적 데이터 처리 속도 및 작업에 바칠 수있는 속도에 의해 제한됩니다. 비디오 다운로드는 컴퓨터의 입력 및 출력 속도에 의해 제한되기 때문에 I / O 바인딩 작업의 예입니다. 데이터를 네트워크 전체로 보낼 수있는만큼 빠르게 이동할 수 있습니다.

이 두 가지 예에서 운영 체제의 보이지 않는 인터럽트는 동시성 형태를 제공합니다. 이러한 동시성은 전체 프로그램의 수준에서만 발생합니다. 운영 체제는 한 프로그램을 중단하여 다른 프로그램이 작업을 수행하도록합니다. 많은 경우 운영 체제보다 훨씬 세분화 된 수준에서 프로그램을 이해하기 때문에 운영 체제가 볼 수없는 동시성 기회를 발견 할 수 있습니다.

예를 들어, 파일 다운로드를 관리하는 도구를 빌드하는 경우, 하나의 다운로드를 시작하면 UI가 잠기지 않고 사용자가 동시에 여러 다운로드를 시작할 수 있도록 프로그램을 작성할 수 있어야 합니다. 하지만 네트워크와 상호 작용하기 위한 많은 운영 체제 API가 차단됩니다. 즉, 처리 중인 데이터가 완전히 준비될 때까지 프로그램의 진행 상황을 차단합니다.

참고 : 이것은 대부분의 함수 호출이 작동하는 방식입니다. 생각해 보면. 그러나 차단이라는 용어는 일반적으로 파일, 네트워크 또는 컴퓨터의 다른 리소스와 상호 작용하는 함수 호출을 위해 예약되어 있습니다. 개별 프로그램이 차단되지 않는 작업에서 이익을 얻는 경우가 있기 때문입니다.

각 파일을 다운로드 할 전용 스레드를 생성하여 기본 스레드를 차단하지 않을 수 있습니다. 그러나 이러한 스레드에서 사용되는 시스템 리소스의 오버 헤드는 결국 문제가 될 것입니다. 호출이 처음부터 차단되지 않으면 바람직 할 것이며 대신 프로그램이 완료하고 런타임이 실행 가능한 최상의 순서와 방식을 선택할 수 있도록 원하는 여러 작업을 정의 할 수 있습니다.

이것이 바로 러스트의 비동기 추상화(비동기)가 주는 것입니다. 이 장에서는 다음 주제를 다룰 때 비동기에 대한 모든 것을 배울 것입니다:

  • 러스트의 async 및 await 구문을 사용하고 런타임으로 비동기 함수를 실행하는 방법
  • 비동기 모델을 사용하여 16장에서 살펴본 것과 동일한 문제를 해결하는 방법
  • 멀티 스레딩 및 비동기가 많은 경우에 결합 할 수있는 보완 솔루션을 제공하는 방법

그러나 비동기가 실제로 어떻게 작동하는지보기 전에, 우리는 평행주의와 동시성의 차이점을 논의하기 위해 잠시 우회 할 필요가 있습니다.

병렬 및 동시성

우리는 지금까지 병렬 처리와 동시성을 대부분 상호 교환 가능한 것으로 취급했습니다. 이제 우리는 그 차이를 더 정확하게 구별해야합니다. 왜냐하면 우리가 일하기 시작하면 그 차이가 나타날 것이기 때문입니다.

팀이 소프트웨어 프로젝트에서 작업을 분할 할 수있는 다양한 방법을 고려하십시오. 단일 멤버에게 여러 작업을 할당하거나 각 멤버에게 하나의 작업을 할당하거나 두 가지 접근 방식을 혼합 할 수 있습니다.

한 사람이 여러 가지 다른 작업을 완료하기 전에 작업 할 때, 이것은 동시성입니다. 동시성을 구현하는 한 가지 방법은 컴퓨터에서 두 개의 다른 프로젝트를 체크 아웃하는 것과 유사하며, 한 프로젝트에서 지루하거나 붙어있을 때 다른 프로젝트로 전환합니다. 당신은 한 사람 일 뿐이므로 두 작업을 동시에 진행할 수는 없지만 멀티 태스킹을 할 수 있습니다. 17을 전환하여 한 번에 하나씩 진행하십시오 (그림 1 참조).

팀이 각 구성원에게 한 가지 작업을 수행하도록하여 작업 그룹을 분할하고 혼자 작업 할 때, 이것은 평행입니다. 팀의 각 사람은 정확히 같은 시간에 진전을 보일 수 있습니다 (그림 17-2 참조).

이 두 가지 작업 흐름 모두에서 서로 다른 작업간에 조정해야 할 수도 있습니다. 한 사람에게 할당 된 작업은 다른 사람의 작업과 완전히 독립적이라고 생각했을 수도 있지만 실제로는 다른 사람이 먼저 작업을 완료해야합니다. 작업 중 일부는 병렬로 수행 할 수 있지만 일부는 실제로 직렬화되었습니다. 그림 17-3과 같이 일련의 작업 후에 한 작업 만 수행 할 수 있습니다.

이와 마찬가지 로, 자신 의 일 중 하나 가 다른 일 에 달려 있다는 것 을 알게 될 것 이다. 이제 동시 에 하는 일 역시 연속적 인 일 이 되었다.

Parallelism과 Concurrency도 서로 교차 할 수 있습니다. 작업을 완료 할 때까지 동료가 붙어 있다는 것을 알게되면 동료를 "차단 해제"하기 위해 모든 노력을 기울일 것입니다. 당신과 당신의 동료는 더 이상 병렬로 작업 할 수 없으며 더 이상 자신의 작업에서 동시에 작업 할 수 없습니다.

동일한 기본 역학이 소프트웨어 및 하드웨어와 함께 작동합니다. 단일 CPU 코어를 가진 시스템에서 CPU는 한 번에 하나의 작업 만 수행 할 수 있지만 동시에 작동 할 수 있습니다. 스레드, 프로세스 및 비동기와 같은 도구를 사용하여 컴퓨터는 하나의 활동을 일시 중지하고 다른 활동으로 전환 한 다음 결국 첫 번째 활동으로 다시 순환 할 수 있습니다. 여러 CPU 코어가있는 시스템에서는 동시에 작업을 수행 할 수도 있습니다. 하나의 코어는 실제로 하나의 작업을 수행 할 수 있으며 다른 작업은 실제로 수행 할 수 있습니다.

러스트에서 비동기 코드를 실행하는 것은 일반적으로 동시에 발생합니다. 하드웨어, 운영 체제 및 우리가 사용하는 비동기 런타임에 따라 (더 많은 비동기 런타임), 그 동시성은 또한 후드 아래에서 병렬 처리를 사용할 수 있습니다.

이제 러스트에서 비동기 프로그래밍이 실제로 어떻게 작동하는지 살펴 보겠습니다.
