이 장의 앞부분에서 앞으로 일련의 대기 지점이 상태 머신으로 컴파일되고 컴파일러는 상태 머신이 차입 및 소유권을 포함한 안전에 관한 러스트의 일반적인 규칙을 모두 따르도록 합니다. 러스트는 대기 지점과 다음 대기 지점 또는 비동기 블록의 끝 사이에 어떤 데이터가 필요한지 살펴봅니다. 그런 다음 컴파일된 상태 머신에서 해당 변형을 생성합니다. 각 변형은 해당 데이터에 대한 접근이 필요한지 아니면 해당 데이터가 사용되는지 여부를 확인합니다.

지금까지는 좋았습니다. 주어진 비동기 블록의 소유권이나 참조에 대해 잘못된 점이 있으면 차용 검사기가 알려줍니다. 해당 블록에 해당하는 미래로 이동하려면 Vec로 이동하여 join_all로 전달하면 더 까다로워집니다.

join_all로 이터레이터로 사용하기 위해 데이터 구조로 밀어넣거나 함수에서 반환할 때, 러스트가 생성한 상태 머신을 이동시키는 것을 의미합니다. 그리고 러스트에서 대부분의 다른 타입과는 달리, 러스트는 비동기 블록을 생성하여 그림 17-4의 단순화된 그림과 같이 주어진 변형의 필드에서 자신을 참조할 수 있습니다.

그러나 기본적으로 자신에 대한 참조가 있는 모든 객체는 이동하기에 안전하지 않습니다. 참조는 항상 참조하는 대상의 실제 메모리 주소를 가리키기 때문입니다(그림 17-5 참조). 데이터 구조 자체를 이동하면 이러한 내부 참조는 이전 위치를 가리키게 됩니다. 그러나 해당 메모리 위치는 이제 유효하지 않습니다. 한 가지에 대해서는 데이터 구조를 변경할 때 값이 업데이트되지 않습니다. 더 중요한 것은 나중에 데이터를 다시 사용할 수 있다는 것입니다.
