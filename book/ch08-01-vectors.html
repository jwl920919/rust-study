The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

벡터로 값 목록 저장하기

우리가 살펴볼 첫 번째 컬렉션 유형은 벡터라고도 하는 Vec<T>입니다. 벡터를 사용하면 메모리에서 모든 값을 인접하게 배치하는 단일 데이터 구조에 하나 이상의 값을 저장할 수 있습니다. 벡터는 동일한 타입의 값만 저장할 수 있습니다. 파일의 텍스트 줄이나 장바구니의 항목 가격과 같은 항목 목록을 다룰 때 유용합니다.

새 벡터 만들기

비어 있는 새로운 벡터를 생성하려면 Listing 8-1에 나와 있듯이 Vec::new 함수를 호출합니다.

여기서 타입 주석을 추가했습니다. 이 벡터에 값을 삽입하지 않았기 때문에 Rust는 어떤 종류의 요소를 저장할지 알 수 없습니다. 이는 중요한 포인트입니다. 벡터는 제네릭을 사용하여 구현됩니다. 제네릭을 사용자 정의 타입과 함께 사용하는 방법은 10장에서 다룹니다. 지금은 표준 라이브러리가 제공하는 Vec<T> 타입이 어떤 타입도 담을 수 있다는 점을 알아두면 됩니다. 특정 타입을 담을 벡터를 생성할 때 각 괄호 안에 타입을 지정할 수 있습니다. Listing 8-1에서 Vec<T>에 있는 v은 i32 타입의 요소를 담을 것이라고 Rust에 알려주었습니다.

더 자주, 당신은 하나를 만들 것입니다. Vec<T> 초기값으로, 러스트는 여러분이 저장하고자 하는 값의 타입을 추론할 것입니다, 그래서 여러분은 이 타입 주석을 거의 할 필요가 없습니다. 러스트는 편리하게 vec! macro는 여러분이 주는 값을 가지는 새로운 벡터를 만듭니다. Listing 8-2는 새로운 벡터를 만듭니다. Vec<i32> 그 가치를 담다 1, 2, 그리고 3. 정수형은 다음과 같습니다. i32 왜냐하면 이것이 우리가 위에서 논의한 것처럼 기본 정수 타입이기 때문입니다. “데이터 유형” 무시 챕터 3.

초기 i32 값을 제공했기 때문에, Rust는 v의 타입이 Vec<i32>임을 추론할 수 있으며 타입 주석이 필요하지 않습니다. 다음으로 벡터를 수정하는 방법을 살펴보겠습니다.

Listing 8-4는 인덱싱 구문과 get 메서드를 사용하여 벡터의 값에 접근하는 두 가지 방법을 보여줍니다.

여기에 몇 가지 세부 사항을 주목하십시오. 우리는 인덱스 값을 사용합니다. 2 벡터가 숫자로 인덱싱되기 때문에 세 번째 요소를 얻으려면 0에서 시작합니다. & 그리고 [] 인덱스 값에 있는 요소에 대한 참조를 제공합니다. get 인수로 전달 된 인덱스를 가진 메서드, 우리는 얻을 Option<&T> 사용할 수 있는 match.

Rust는 기존 요소의 범위 밖의 인덱스 값을 사용할 때 프로그램이 어떻게 동작하는지 선택할 수 있도록 요소를 참조하는 두 가지 방법을 제공합니다. 예를 들어, 5개의 요소를 가진 벡터가 있을 때 각 기법으로 인덱스 100의 요소에 접근하려고 하면 어떤 일이 일어나는지 Listing 8-5에서 확인해 보겠습니다.

이 코드를 실행하면 첫 번째 [] 메서드가 존재하지 않는 요소를 참조하기 때문에 프로그램이 패닉(panic)을 일으킵니다. 이 메서드는 벡터의 끝을 지나 요소에 접근하려는 시도가 있을 때 프로그램이 충돌하도록 하고 싶을 때 가장 적합합니다.

get 메서드에 벡터 범위를 벗어난 인덱스가 전달되면 패닉 없이 None를 반환합니다. 정상적인 상황에서 벡터 범위를 벗어난 요소에 접근하는 일이 가끔 발생할 수 있다면 이 메서드를 사용해야 합니다. 그러면 코드는 6장에서 논의했듯이 Some(&element) 또는 None 중 하나를 처리하는 로직을 갖게 됩니다. 예를 들어, 인덱스가 사용자가 입력한 숫자에서 온다고 가정해 보겠습니다. 사용자가 실수로 너무 큰 숫자를 입력하여 프로그램이 None 값을 받는 경우, 현재 벡터에 몇 개의 항목이 있는지 사용자에게 알려주고 유효한 값을 다시 입력할 기회를 줄 수 있습니다. 이는 오타로 인해 프로그램을 충돌시키는 것보다 훨씬 사용자 친화적입니다!

프로그램이 유효한 참조를 가지고 있을 때, 빌림 검사기는 소유권과 빌림 규칙(4장에서 다룸)을 강제하여 이 참조와 벡터의 내용을 가리키는 다른 모든 참조가 유효한 상태를 유지하도록 보장합니다. 같은 스코프에서 가변 참조와 불변 참조를 동시에 가질 수 없다는 규칙을 떠올려 보십시오. 이 규칙은 Listing 8-6에 적용되며, 여기서는 벡터의 첫 번째 요소에 대한 불변 참조를 유지하면서 벡터 끝에 요소를 추가하려고 합니다. 만약 함수의 후반부에서 해당 요소를 참조하려고 한다면 이 프로그램은 동작하지 않습니다.

이 코드를 컴파일하면 다음과 같은 오류가 발생합니다.

Listing 8-6의 코드는 작동할 것 같아 보일 수 있습니다. 왜 첫 번째 요소에 대한 참조가 벡터 끝의 변경 사항에 신경 써야 할까요? 이 오류는 벡터의 작동 방식 때문입니다. 벡터는 메모리에서 값을 서로 인접하게 배치합니다. 따라서 벡터 끝에 새 요소를 추가할 때, 현재 벡터가 저장된 위치에 모든 요소를 인접하게 배치할 공간이 충분하지 않으면 새 메모리를 할당하고 기존 요소를 새 공간으로 복사해야 할 수 있습니다. 이 경우 첫 번째 요소에 대한 참조는 해제된 메모리를 가리키게 됩니다. 빌림 규칙은 프로그램이 이러한 상황에 빠지는 것을 방지합니다.

벡터의 값 반복

벡터의 각 요소를 순서대로 접근하려면 인덱스를 사용하여 한 번에 하나씩 접근하는 대신 모든 요소를 반복해야 합니다. Listing 8-7은 for 루프를 사용하여 i32 값의 벡터에서 각 요소에 대한 불변 참조를 얻어 출력하는 방법을 보여줍니다.

또한 가변 벡터의 각 요소에 대한 가변 참조를 반복하여 모든 요소를 변경할 수 있습니다. Listing 8-8의 for 루프는 각 요소에 50를 더합니다.

가변 참조가 가리키는 값을 변경하려면, * 역참조 연산자를 사용해 i의 값에 접근한 후에야 += 연산자를 사용할 수 있습니다. 역참조 연산자에 대해서는 15장의 “참조를 따라 값으로 이동” 섹션에서 더 자세히 다루겠습니다.

불변이든 가변이든 벡터를 반복하는 것은 빌림 검사기의 규칙 덕분에 안전합니다. Listing 8-7과 Listing 8-8의 for 루프 본문에서 항목을 삽입하거나 제거하려고 하면, Listing 8-6의 코드에서 발생했던 것과 유사한 컴파일러 오류가 발생합니다. for 루프가 유지하는 벡터에 대한 참조는 벡터 전체의 동시 수정을 방지합니다.

열거형을 사용해 여러 타입 저장하기

벡터는 같은 타입의 값만 저장할 수 있습니다. 이는 불편할 수 있습니다. 서로 다른 타입의 항목 목록을 저장해야 하는 경우가 분명히 존재하기 때문입니다. 다행히도 열거형의 변형은 동일한 열거형 타입 아래에서 정의되므로, 서로 다른 타입의 요소를 하나의 타입으로 표현해야 할 때 열거형을 정의하고 사용할 수 있습니다!

예를 들어, 스프레드시트의 한 행에서 값을 가져오고 싶다고 가정해 보겠습니다. 이 행의 일부 열에는 정수가, 일부에는 부동 소수점 숫자가, 또 일부에는 문자열이 포함되어 있다고 합시다. 서로 다른 값 타입을 가진 변형을 가진 열거형을 정의할 수 있으며, 모든 열거형 변형은 열거형의 타입으로 간주됩니다. 그러면 이 열거형을 저장하는 벡터를 만들 수 있고, 궁극적으로 서로 다른 타입을 저장할 수 있게 됩니다. Listing 8-9에서 이를 시연했습니다.

Rust는 컴파일 타임에 벡터에 어떤 타입이 들어갈지 알아야 합니다. 이를 통해 각 요소를 저장하는 데 힙에서 정확히 얼마나 많은 메모리가 필요한지 알 수 있습니다. 또한 이 벡터에 어떤 타입이 허용되는지 명시적으로 지정해야 합니다. Rust가 벡터에 어떤 타입이든 저장할 수 있도록 허용했다면, 하나 이상의 타입이 벡터 요소에 수행되는 연산으로 인해 오류를 일으킬 가능성이 생깁니다. enum과 match 표현식을 사용하면 6장에서 논의했듯이, Rust가 컴파일 타임에 모든 가능한 케이스가 처리되도록 보장합니다. match

프로그램이 런타임에 벡터에 저장할 타입의 전체 집합을 알 수 없는 경우, 열거형 기법은 작동하지 않습니다. 대신 18장에서 다룰 트레이트 객체를 사용할 수 있습니다.

이제 벡터를 사용하는 가장 일반적인 방법 중 일부를 논의 했으므로 반드시 검토하십시오. API 문서 무시 에 정의 된 많은 유용한 방법의 모든 Vec<T> 표준 라이브러리에 의해. 예를 들어, 이외에 push, a pop 메서드는 마지막 요소를 제거하고 반환합니다.

벡터를 드롭하면 그 요소도 함께 드롭됩니다

다른 struct와 마찬가지로, 벡터는 스코프 밖으로 나가면 해제됩니다. Listing 8-10에 이를 주석으로 표시했습니다.
