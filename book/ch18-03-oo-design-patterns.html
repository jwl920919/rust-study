한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

객체 지향 디자인 패턴 구현

상태 패턴은 객체 지향 디자인 패턴입니다. 패턴의 핵심은 값이 내부적으로 가질 수있는 상태 집합을 정의한다는 것입니다. 상태는 상태 객체 세트로 표현되며, 값의 동작은 상태에 따라 변경됩니다. 우리는 "draft", "review"또는 "published"세트의 상태 객체가 될 필드를 가진 블로그 포스트 구조체의 예를 통해 작업 할 것입니다.

상태 객체는 기능을 공유합니다: 물론, 러스트에서는 객체와 상속이 아닌 구조체와 특성을 사용합니다. 각 상태 객체는 자신의 행동과 다른 상태로 변경해야 할 때의 지배에 대한 책임이 있습니다. 상태 객체를 보유하는 값은 상태의 다른 행동이나 상태 간의 전환시기에 대해 아무것도 모릅니다.

상태 패턴을 사용하는 이점은 프로그램의 비즈니스 요구 사항이 변경되면 상태를 유지하는 값의 코드 또는 값을 사용하는 코드를 변경할 필요가 없다는 것입니다. 규칙을 변경하거나 더 많은 상태 객체를 추가하기 위해 상태 객체 중 하나의 코드 만 업데이트하면됩니다.

먼저, 좀 더 전통적인 객체 지향적인 방식으로 상태 패턴을 구현할 것입니다. 그런 다음 러스트에서 좀 더 자연스러운 접근 방식을 사용할 것입니다. 상태 패턴을 사용하여 블로그 게시물 작업 흐름을 점진적으로 구현해 보겠습니다.

최종 기능은 다음과 같습니다.

  1. 블로그 게시물은 빈 초안으로 시작합니다.
  2. 초안이 완료되면 게시물에 대한 검토가 요청됩니다.
  3. 포스팅이 승인되면, 공개됩니다.
  4. 게시된 블로그 게시물만 콘텐츠를 인쇄하여 승인되지 않은 게시물을 실수로 게시할 수 없도록 합니다.

게시물에서 시도한 다른 변경 사항은 아무런 영향을 미치지 않습니다. 예를 들어 리뷰를 요청하기 전에 블로그 게시물 초안을 승인하려고하면 게시되지 않은 초안으로 남아 있어야합니다.
