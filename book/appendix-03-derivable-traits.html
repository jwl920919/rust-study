The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

부록 C: 파생 가능한 트레이트

이 책의 여러 곳에서 struct 또는 enum 정의에 적용할 수 있는 derive 속성에 대해 설명했습니다. derive 속성은 derive 구문을 사용하여 주석을 달은 타입에 대해, 해당 트레이트의 기본 구현으로 코드를 생성합니다.

이 부록에서는 derive와 함께 사용할 수 있는 표준 라이브러리의 모든 트레이트에 대한 참고 자료를 제공합니다. 각 섹션은 다음 내용을 다룹니다.

  • 이 트레이트를 파생하면 사용할 수 있게 되는 연산자와 메서드
  • derive가 제공하는 트레이트 구현이 수행하는 작업
  • 트레이트를 구현하는 것이 타입에 대해 의미하는 바
  • 트레이트 구현이 허용되거나 허용되지 않는 조건
  • 트레이트가 필요한 작업의 예

derive 속성이 제공하는 동작과 다른 동작을 원한다면, 표준 라이브러리 문서에서 각 트레이트를 수동으로 구현하는 방법에 대한 자세한 내용을 확인하십시오.

여기에 나열된 트레이트는 derive를 사용하여 사용자 정의 타입에 구현할 수 있는 표준 라이브러리에서 정의된 유일한 트레이트입니다. 표준 라이브러리에 정의된 다른 트레이트에는 합리적인 기본 동작이 없으므로, 사용자가 달성하려는 목적에 맞게 직접 구현해야 합니다.

파생(derive)할 수 없는 트레이트의 예로 Display가 있습니다. 이 트레이트는 최종 사용자를 위한 서식을 처리합니다. 최종 사용자에게 타입을 표시하는 적절한 방법을 항상 고려해야 합니다. 최종 사용자에게 타입의 어떤 부분을 보여줄 수 있을까요? 어떤 부분이 관련이 있을까요? 어떤 형식의 데이터가 가장 유용할까요? Rust 컴파일러에는 이러한 통찰력이 없으므로, 적절한 기본 동작을 제공할 수 없습니다.

이 부록에 제시된 파생 가능한 트레이트 목록은 완전하지 않습니다. 라이브러리는 자체 트레이트에 대해 derive를 구현할 수 있으므로, derive을 사용할 수 있는 트레이트 목록은 실제로 무한정 확장 가능합니다. derive 구현에는 절차적 매크로가 사용되며, 이는 20장의 “커스텀 derive 매크로” 섹션에서 다룹니다.

Debug: 프로그래머 출력을 위한

Debug 트레이트는 포맷 문자열에서 디버그 포맷팅을 가능하게 합니다. :? 자리표시자 안에 {}를 추가하여 이를 지정합니다.

Debug 트레이트를 사용하면 디버깅 목적으로 타입의 인스턴스를 출력할 수 있습니다. 이를 통해 사용자와 해당 타입을 사용하는 다른 프로그래머가 프로그램 실행 중 특정 시점의 인스턴스를 검사할 수 있습니다.

예를 들어, Debug 특성은 assert_eq! 매크로를 사용할 때 필요합니다. 이 매크로는 동등성 검증이 실패하면 인수로 전달된 인스턴스의 값을 출력하여, 프로그래머가 두 인스턴스가 왜 같지 않은지 확인할 수 있도록 합니다.

PartialEq과 Eq을 통한 동등성 비교

PartialEq 트레잇을 구현하면 타입의 인스턴스를 비교하여 동등성을 확인할 수 있으며, == 및 != 연산자를 사용할 수 있습니다.

PartialEq를 파생하면 eq 메서드가 구현됩니다. 구조체에 PartialEq를 파생한 경우, 모든 필드가 동일한 경우에만 두 인스턴스가 동일하며, 하나라도 필드가 다르면 동일하지 않습니다. 열거형에 파생한 경우, 각 변형은 자신과만 동일하며 다른 변형과는 동일하지 않습니다.

예를 들어, PartialEq 매크로는 두 인스턴스가 동등한지 비교할 수 있어야 하므로 assert_eq! 트레이트가 필요합니다.

Eq 트레이트에는 메서드가 없습니다. 이 트레이트의 목적은 주석된 타입의 모든 값에 대해, 해당 값이 자기 자신과 같다는 것을 나타내는 것입니다. Eq 트레이트는 PartialEq를 구현하는 타입에만 적용할 수 있지만, PartialEq를 구현하는 모든 타입이 Eq를 구현할 수 있는 것은 아닙니다. 그 예로 부동소수점 숫자 타입이 있습니다. 부동소수점 숫자의 구현에서는 숫자가 아닌 값(not-a-number, NaN)의 두 인스턴스가 서로 같지 않다고 정의합니다.

Eq이 필요한 경우의 예로, HashMap<K, V>의 키에서 HashMap<K, V>가 두 키가 동일한지 판별할 수 있도록 하는 것이 있습니다.

PartialOrd과 Ord을 통한 순서 비교

PartialOrd 트레이트를 사용하면 정렬 목적으로 타입의 인스턴스를 비교할 수 있습니다. PartialOrd를 구현하는 타입은 <, >, <=, >= 연산자와 함께 사용할 수 있습니다. PartialOrd 트레이트는 PartialEq를 구현하는 타입에만 적용할 수 있습니다.

파생 PartialOrd는 partial_cmp 메서드를 구현합니다. 이 메서드는 Option<Ordering>를 반환하며, 주어진 값의 순서를 정할 수 없으면 None이 됩니다. 대부분의 값을 비교할 수 있는 타입에서도 순서를 정할 수 없는 값이 있을 수 있습니다. 부동 소수점 값인 NaN가 그 예입니다. 부동 소수점 수와 NaN를 partial_cmp로 비교하면 None이 반환됩니다.

구조체에 파생된 경우, PartialOrd는 구조체 정의에서 필드가 나타나는 순서대로 각 필드의 값을 비교하여 두 인스턴스를 비교합니다. 열거형에 파생된 경우, 열거형 정의에서 앞에 선언된 변형은 뒤에 나열된 변형보다 작다고 간주됩니다.

PartialOrd 트레이트는 예를 들어, gen_range 메서드에서 필요합니다. 이 메서드는 rand 크레이트에 포함되어 있으며, 범위 표현식으로 지정된 범위에서 임의의 값을 생성합니다.

Ord 트레이트는 주석된 타입의 임의의 두 값에 대해 유효한 순서가 존재한다는 것을 보장합니다. Ord 트레이트는 cmp 메서드를 구현하며, 유효한 순서가 항상 가능하기 때문에 Option<Ordering> 대신 Ordering를 반환합니다. Ord 트레이트는 PartialOrd과 Eq(그리고 Eq은 PartialEq를 요구합니다)를 구현하는 타입에만 적용할 수 있습니다. 구조체와 열거형에서 파생될 때, cmp은 partial_cmp의 파생 구현이 PartialOrd와 함께 동작하는 방식과 동일하게 동작합니다.

Ord이 필요한 경우의 예로, 값의 정렬 순서에 따라 데이터를 저장하는 데이터 구조인 BTreeSet<T>에 값을 저장하는 경우가 있습니다.

Clone과 Copy를 사용하여 값을 복제하기

Clone 트레이트를 사용하면 값의 깊은 복사를 명시적으로 생성할 수 있습니다. 이 복제 과정에서는 임의의 코드가 실행되고 힙 데이터가 복사될 수 있습니다. "Clone과 상호 작용하는 변수 및 데이터" 섹션에서 Clone에 대한 자세한 내용을 확인할 수 있습니다.

Clone을(를) 파생하면 clone 메서드가 구현됩니다. 이 메서드는 해당 형식 전체에 대해 구현될 때, 형식의 각 부분에 대해 clone을(를) 호출합니다. 따라서 Clone을(를) 파생하려면, 해당 형식의 모든 필드나 값도 Clone을(를) 구현해야 합니다.

Clone이 필요한 예시로, 슬라이스에서 to_vec 메서드를 호출하는 경우가 있습니다. 슬라이스는 포함하는 타입 인스턴스를 소유하지 않지만, to_vec에서 반환되는 벡터는 자신의 인스턴스를 소유해야 하므로, to_vec은 각 항목에 대해 clone을 호출합니다. 따라서 슬라이스에 저장된 타입은 Clone을 구현해야 합니다.

Copy 트레잇을 사용하면 스택에 저장된 비트만 복사하여 값을 복제할 수 있으며, 임의의 코드가 필요하지 않습니다. 스택에만 저장되는 데이터: Copy 섹션에서 Copy에 대한 자세한 내용을 확인할 수 있습니다.

Copy 특성은 프로그래머가 메서드를 오버로드하여 임의의 코드가 실행되지 않는다는 가정을 위반하는 것을 방지하기 위해 어떤 메서드도 정의하지 않습니다. 이를 통해 모든 프로그래머는 값을 복사하는 작업이 매우 빠르다고 가정할 수 있습니다.

모든 구성 요소가 Copy을(를) 구현하는 타입이라면, Copy을(를) derive할 수 있습니다. Copy을(를) 구현하는 타입은 Clone도 반드시 구현해야 합니다. Copy을(를) 구현하는 타입은 Clone의 단순한 구현을 가지며, 이는 Copy과(와) 동일한 작업을 수행하기 때문입니다.

Copy 트레잇은 거의 필요하지 않습니다. Copy를 구현하는 타입은 최적화가 가능하므로, clone를 호출할 필요가 없으며 코드가 더 간결해집니다.

Copy로 할 수 있는 모든 작업은 Clone로도 수행할 수 있지만, 코드가 느려지거나 특정 위치에서 clone를 사용해야 할 수 있습니다.

Hash 고정 크기의 값으로 값을 매핑하는 해시

Hash 트레잇을 사용하면 임의의 크기를 가진 타입의 인스턴스를 받아, 해시 함수를 사용해 고정된 크기의 값으로 매핑할 수 있습니다. Hash을 파생하면 hash 메서드가 구현됩니다. 파생된 hash 메서드 구현은 타입의 각 부분(모든 필드 또는 값)에 대해 hash를 호출한 결과를 결합합니다. 따라서 Hash를 파생하려면 모든 필드 또는 값도 Hash을 구현해야 합니다.

Hash이 필요한 경우의 예로, HashMap<K, V>에 키를 저장하여 데이터를 효율적으로 관리하는 것이 있습니다.

Default 기본값에 대해

Default 트레이트는 타입에 대해 기본 값을 생성할 수 있게 합니다. Default을 파생하면 default 함수를 구현합니다. default 함수의 파생 구현은 타입의 각 부분에 대해 default 함수를 호출하므로, Default을 파생하려면 타입의 모든 필드나 값도 Default를 구현해야 합니다.

Default::default 함수는 5장의 “구조체 업데이트 구문을 사용하여 다른 인스턴스에서 인스턴스 만들기” 섹션에서 설명된 구조체 업데이트 구문과 함께 자주 사용됩니다. 구조체의 일부 필드를 사용자 지정하고 ..Default::default()를 사용하여 나머지 필드에 기본값을 설정하고 사용할 수 있습니다.

예를 들어, Default 인스턴스에서 unwrap_or_default 메서드를 사용할 때 Option<T> 트레이트가 필요합니다. Option<T>가 None인 경우, unwrap_or_default 메서드는 Default::default에 저장된 T 타입의 Option<T> 결과를 반환합니다.
