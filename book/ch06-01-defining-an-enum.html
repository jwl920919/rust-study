한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

구조체는 관련 필드와 데이터를 함께 그룹화하는 방법을 제공합니다. Rectangle 그와 함께 width 그리고 height, 열거형은 값이 가능한 값 집합 중 하나라고 말하는 방법을 제공합니다. 예를 들어 다음과 같이 말할 수 있습니다. Rectangle 다음을 포함하는 일련의 가능한 도형들 중 하나입니다. Circle 그리고 Triangle이를 위해 러스트는 이러한 가능성을 열거형으로 인코딩할 수 있습니다.

코드에서 표현하고 싶은 상황을 살펴보고이 경우 enums가 구조체보다 유용하고 더 적합한 이유를 살펴 보겠습니다. IP 주소로 작업해야한다고 가정 해 봅시다. 현재 두 가지 주요 표준이 IP 주소에 사용됩니다. 버전 4와 버전 6입니다. 이것들이 프로그램이 발생할 IP 주소의 유일한 가능성이기 때문에 가능한 모든 변형을 열거 할 수 있습니다.

모든 IP 주소는 버전 4 또는 버전 6 주소 중 하나 일 수 있지만 동시에 둘 다는 아닙니다. IP 주소의 속성은 열거형 값이 변형 중 하나 일 수 있기 때문에 열거형 데이터 구조를 적절히 만듭니다. 버전 4 및 버전 6 주소는 모두 기본적으로 IP 주소이므로 코드가 모든 종류의 IP 주소에 적용되는 상황을 처리 할 때 동일한 유형으로 취급되어야합니다.

우리는 IpAddrKind 열거를 정의하고 IP 주소가 될 수있는 가능한 종류, V4 및 V6를 나열하여 코드에서이 개념을 표현할 수 있습니다. 다음은 열거의 변형입니다.

enum IpAddrKind {
    V4,
    V6,
}

fn main() {
    let four = IpAddrKind::V4;
    let six = IpAddrKind::V6;

    route(IpAddrKind::V4);
    route(IpAddrKind::V6);
}

fn route(ip_kind: IpAddrKind) {}

IpAddrKind는 이제 코드의 다른 곳에서 사용할 수있는 사용자 정의 데이터 유형입니다.

enums를 사용하면 훨씬 더 많은 이점이 있습니다. IP 주소 유형에 대해 더 많이 생각하면 현재 실제 IP 주소 데이터를 저장할 방법이 없습니다. 우리는 그것이 어떤 종류인지 만 알고 있습니다. 5 장에서 구조체에 대해 배웠다는 점을 감안할 때, Listing 6-1과 같이이 문제를 구조체로 해결하려는 유혹을받을 수 있습니다.

여기서, 우리는 구조체를 정의했습니다. IpAddr 두 개의 필드가 있습니다: a kind 타입의 필드 That is type IpAddrKind (우리가 이전에 정의한 enum) address 타입의 필드 String. 우리는이 구조체의 두 가지 인스턴스를 가지고 있습니다. 첫 번째는 home그리고 그것은 가치를 가지고있다. 그러나 enum을 사용하여 동일한 개념을 나타내는 것이 더 간결합니다. 구조체 내부의 열거형이 아니라 각 열거형 변형에 직접 데이터를 넣을 수 있습니다. IpAddr 열거형의 새로운 정의에 따르면 V4 및 V6 변형 모두 String 값과 관련이 있습니다.

fn main() {
    enum IpAddr {
        V4(String),
        V6(String),
    }

    let home = IpAddr::V4(String::from("127.0.0.1"));

    let loopback = IpAddr::V6(String::from("::1"));
}

우리는 enum의 각 변형에 직접 데이터를 첨부하므로 추가 struct가 필요하지 않습니다. 여기서 enums가 어떻게 작동하는지에 대한 또 다른 세부 사항을 보는 것도 더 쉽습니다. 우리가 정의하는 각 enum 변형의 이름은 또한 enum의 인스턴스를 구성하는 함수가됩니다. 즉, IpAddr::V4() 함수 호출은 다음과 같습니다. String 인수를 반환하고 인스턴스를 반환합니다.Argument and return an instance of the IpAddr type. 이 생성자 함수는 열거형을 정의한 결과로 정의됩니다.

구조체가 아닌 열거형을 사용하는 것의 또 다른 장점이 있습니다. 각 변형은 서로 다른 유형과 관련 데이터 양을 가질 수 있습니다. 버전 4 IP 주소에는 항상 0과 255 사이의 값을 갖는 4 개의 숫자 구성 요소가 있습니다. 우리가 저장하고 싶다면 V4 주소 4 u8 가치가 있지만 여전히 표현 V6 주소 as one String value, 구조체로는 할 수 없습니다. Enums는 이 경우를 쉽게 처리합니다:

fn main() {
    enum IpAddr {
        V4(u8, u8, u8, u8),
        V6(String),
    }

    let home = IpAddr::V4(127, 0, 0, 1);

    let loopback = IpAddr::V6(String::from("::1"));
}

우리는 버전 4와 버전 6 IP 주소를 저장하기 위해 데이터 구조를 정의하는 몇 가지 다른 방법을 보여주었습니다. 그러나 IP 주소를 저장하고 어떤 종류의 IP 주소를 인코딩하기를 원하기 때문에 표준 라이브러리에는 우리가 사용할 수 있는 정의가 있습니다! 표준 라이브러리가 IpAddr를 정의하는 방법을 살펴 보겠습니다. 우리가 정의하고 사용했던 정확한 열거형과 변형이 있지만 변형의 각 주소 데이터를 다른 형태로 포함시킵니다.

#![allow(unused)]
fn main() {
struct Ipv4Addr {
    // --snip--
}

struct Ipv6Addr {
    // --snip--
}

enum IpAddr {
    V4(Ipv4Addr),
    V6(Ipv6Addr),
}
}

이 코드는 예를 들어 문자열, 숫자 유형 또는 구조체와 같은 열거형 변형에 모든 종류의 데이터를 넣을 수 있음을 보여줍니다. 다른 열거형을 포함 할 수도 있습니다! 또한 표준 라이브러리 유형은 종종 생각해 낼 수있는 것보다 훨씬 복잡하지 않습니다.

표준 라이브러리에는 IpAddr에 대한 정의가 포함되어 있지만 표준 라이브러리의 정의를 범위에 가져 오지 않았기 때문에 충돌없이 자체 정의를 만들고 사용할 수 있습니다. 7 장에서 유형을 범위로 가져 오는 방법에 대해 자세히 설명합니다.

매우 일반적이고 유용한 표준 라이브러리의 또 다른 열거형을 살펴 보겠습니다: Option.

이름 * Option 에눔은

이 섹션에서는 표준 라이브러리에서 정의한 또 다른 열거형인 Option에 대한 사례 연구를 살펴봅니다. Option 유형은 값이 무언가일 수 있거나 아무것도 아닐 수 있는 매우 일반적인 시나리오를 인코딩합니다.

예를 들어, 비어 있지 않은 목록에서 첫 번째 항목을 요청하면 값을 얻을 수 있습니다. 빈 목록에서 첫 번째 항목을 요청하면 아무 것도 얻지 못합니다. 이 개념을 유형 시스템 측면에서 표현하면 컴파일러가 처리해야하는 모든 경우를 처리했는지 여부를 확인할 수 있습니다. 이 기능은 다른 프로그래밍 언어에서 매우 일반적인 버그를 방지 할 수 있습니다.

프로그래밍 언어 설계는 어떤 기능을 포함해야 하는지에 대해 종종 고려되지만, 여러분이 제외하는 기능도 중요합니다. 러스트는 다른 많은 언어들이 가지고 있는 null 기능을 가지고 있지 않습니다. Null은 값이 없다는 것을 의미하는 값입니다. null이 있는 언어에서 변수는 항상 null 또는 not-null의 두 가지 상태 중 하나에 있을 수 있습니다.

그의 2009 년 프리젠 테이션 "Null References : 10 억 달러의 실수"에서 Null의 발명가 인 Tony Hoare는 다음과 같이 말했습니다.

저는 이것을 10억 달러짜리 실수라고 부릅니다. 그 당시, 저는 객체 지향 언어에서 참조를 위한 최초의 포괄적인 타입 시스템을 설계하고 있었습니다. 저의 목표는 컴파일러에 의해 자동으로 수행되는 검사와 함께 참조의 모든 사용이 절대적으로 안전하도록 하는 것이었습니다. 그러나 저는 null 참조를 적용하려는 유혹에 저항할 수 없었습니다. 구현이 매우 쉬웠기 때문입니다. 이로 인해 수많은 오류, 취약성 및 시스템 충돌이 발생하여 아마도 40억 달러의 피해를 입혔을 것입니다.

null 값의 문제점은 null 값을 null이 아닌 값으로 사용하려고 하면 어떤 종류의 오류가 발생한다는 것입니다. 이 null 또는 not-null 속성이 널리 퍼져 있기 때문에 이러한 종류의 오류를 만드는 것은 매우 쉽습니다.

그러나 null이 표현하려고 하는 개념은 여전히 유용한 개념입니다: null은 어떤 이유로 현재 유효하지 않거나 없는 값입니다.

문제는 컨셉이 아니라 특정 구현에 있습니다. 따라서 러스트에는 null이 없지만 값이 존재하거나 존재하지 않는 개념을 인코딩 할 수있는 열거형이 있습니다. 이 열거형은 Option<T>이며 다음과 같이 표준 라이브러리 Standard Library입니다.

#![allow(unused)]
fn main() {
enum Option<T> {
    None,
    Some(T),
}
}

이름 * Option<T> enum은 너무 유용해서 prelude에 포함되어 있기도 합니다. 이를 명시적으로 scope로 가져올 필요는 없습니다. 그 변형은 prelude에도 포함되어 있습니다. Some 그리고 None 직접 없이 Option:: 접두사. Option<T> enum은 여전히 정규 enum일 뿐이며, Some(T) 그리고 None 그들은 여전히 종류의 변종입니다. Option<T>.

이름 * <T> 문법은 우리가 아직 이야기하지 않은 러스트의 기능입니다. 이것은 제네릭 타입 파라미터이며, 10장에서 제네릭에 대해 더 자세히 다룰 것입니다. 지금은 여러분이 알아야 할 것은 <T> 상기 단계는 It said the Some 모델명 The Option enum은 어떤 타입의 데이터도 저장할 수 있고, 그 대신에 사용되는 각각의 콘크리트 타입은 T make the 전체 Option<T> 다른 유형을 타자를 치십시오. 사용의 몇몇 보기는 여기 있다 Option 숫자 타입과 char 타입을 저장할 값:

fn main() {
    let some_number = Some(5);
    let some_char = Some('e');

    let absent_number: Option<i32> = None;
}

의 종류 some_number 있습니다. Option<i32>. 의 종류 some_char 있습니다. Option<char>, 이것은 다른 타입입니다. 러스트는 이 타입들을 추론할 수 있습니다. 왜냐하면 우리는 그 안에 값을 지정했기 때문입니다. Some 변형. 를 위해 absent_number, 러스트는 우리가 전체적으로 주석을 달기를 요구합니다.
