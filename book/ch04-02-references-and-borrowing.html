The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

참고 문헌 및 대출

Listing 4-5에서 튜플 코드의 문제는 우리가 반환해야 한다는 것입니다. String 호출 함수를 사용하여 호출할 수 있도록 합니다. String 전화 통화 후 calculate_length왜냐하면, The String 로 이동된 calculate_length. 대신, 우리는에 대한 참조를 제공 할 수 String value. 참조는 해당 주소에 저장된 데이터에 액세스하기 위해 따라갈 수있는 주소라는 점에서 포인터와 같습니다. 데이터는 다른 변수가 소유합니다. 포인터와 달리 참조는 해당 참조의 수명 동안 특정 유형의 유효한 값을 가리 키도록 보장됩니다.

값을 소유하는 대신 객체를 매개 변수로 참조하는 calculate_length 함수를 정의하고 사용하는 방법은 다음과 같습니다.

첫째, 변수 선언과 함수 반환 값의 모든 튜플 코드가 사라 것을 알 수 있습니다. 둘째, 우리가 통과주의 &s1 다음으로 calculate_length 그리고, 그것의 정의에서, 우리는 &String 보다는 String. 이 앰퍼샌드는 참조를 나타내며 소유권을 취하지 않고 어떤 값을 참조 할 수 있습니다. 그림 4-6은이 개념을 묘사합니다.

그림 4-6 : 다이어그램 &String s 포인팅 String s1

참고 : &를 사용하여 참조하는 반대는 역참조 연산자 *로 수행되는 역참조입니다. 우리는 8 장에서 역참조 연산자를 사용하고 15 장에서 역참조의 세부 사항을 논의 할 것입니다.

여기서 함수 호출을 자세히 살펴보겠습니다.Let's take a closer look at the function call here:

fn main() {
    let s1 = String::from("hello");

    let len = calculate_length(&s1);

    println!("The length of '{s1}' is {len}.");
}

fn calculate_length(s: &String) -> usize {
    s.len()
}

&s1 구문을 사용하면 s1의 값을 참조하지만 소유하고 있지 않은 참조를 만들 수 있습니다. 참조가 소유하지 않기 때문에 참조가 사용되지 않을 때 참조가 가리키는 값은 삭제되지 않습니다.

마찬가지로 함수의 서명은 &를 사용하여 매개 변수 s의 유형이 참조임을 나타냅니다. 몇 가지 설명 주석을 추가해 보겠습니다.

fn main() {
    let s1 = String::from("hello");

    let len = calculate_length(&s1);

    println!("The length of '{s1}' is {len}.");
}

fn calculate_length(s: &String) -> usize { // s is a reference to a String
    s.len()
} // Here, s goes out of scope. But because s does not have ownership of what
  // it refers to, the String is not dropped.

변수 s가 유효한 범위는 모든 함수 매개 변수의 범위와 동일하지만 s가 사용되지 않을 때 참조가 가리키는 값은 삭제되지 않습니다. s는 소유권이 없기 때문입니다. 함수가 실제 값 대신 매개 변수로 참조를 사용하는 경우 소유권을 돌려주기 위해 값을 반환 할 필요가 없습니다.

우리는 참조 차용을 만드는 행동을 호출합니다. 실생활에서와 마찬가지로, 사람이 무언가를 소유하고 있다면, 당신은 그들로부터 그것을 빌릴 수 있습니다. 당신이 끝나면, 당신은 그것을 돌려 주어야합니다. 당신은 그것을 소유하지 않습니다.

가변 참조

우리는 Listing 4-6에서 빌린 값을 수정할 수 있도록 코드를 수정할 수 있습니다. 대신, 가변 참조를 사용하는 몇 가지 작은 조정으로 말이죠.

먼저 s를 mut로 변경합니다. 그런 다음 &mut s로 가변 참조를 생성하여 change 함수를 호출하고 기능 서명을 업데이트하여 some_string: &mut String로 가변 참조를 수락합니다. 이로 인해 change 함수가 값을 변경한다는 것이 매우 분명합니다.

가변 참조에는 하나의 큰 제한이 있습니다. 값에 대한 가변 참조가 있는 경우 해당 값에 대한 다른 참조를 가질 수 없습니다. s에 대한 두 개의 가변 참조를 만들려고 시도하는 이 코드는 실패합니다.

오류는 다음과 같습니다.

$ cargo run
   Compiling ownership v0.1.0 (file:///projects/ownership)
error[E0499]: cannot borrow `s` as mutable more than once at a time

  |              ^^^^^^ second mutable borrow occurs here

이 오류는 우리가 빌릴 수 없기 때문에이 코드가 유효하지 않다고 말합니다. s 한번에 한 번 이상 가변으로. 첫번째 가변 차용은 안으로 있습니다 r1 그리고 그것이 사용될 때까지 지속되어야 한다. println!그러나, 그 가변 참조의 생성과 그 사용 사이에, 우리는 또 다른 가변 참조를 만들려고 노력했다. r2 즉, 다음과 같은 데이터를 빌린다. r1.

동시에 동일한 데이터에 대한 다중 가변 참조를 방지하는 제한은 매우 통제 된 방식으로 돌연변이를 허용합니다. 대부분의 언어가 원할 때마다 돌연변이를 허용하기 때문에 새로운 러스트aceans가 어려움을 겪고 있습니다. 이 제한을 갖는 이점은 러스트가 컴파일 타임에 데이터 레이스를 방지 할 수 있다는 것입니다. 데이터 레이스는 인종 조건과 유사하며 다음과 같은 세 가지 행동이 발생할 때 발생합니다.

  • 두 개 이상의 포인터가 동시에 동일한 데이터에 액세스합니다.
  • 적어도 하나의 포인터가 데이터에 쓰기 위해 사용되고 있다.
  • 데이터에 대한 액세스를 동기화하는 데 사용되는 메커니즘은 없습니다.There is no mechanism being used to synchronize access to the data.

데이터 레이스는 정의되지 않은 행동을 유발하며 런타임에 추적하려고 할 때 진단 및 수정이 어려울 수 있습니다; 러스트는 데이터 레이스로 코드를 컴파일하는 것을 거부함으로써 이 문제를 방지합니다!

언제나처럼, 우리는 중괄호를 사용하여 새로운 범위를 만들 수 있습니다, 여러 개의 가변 참조를 허용, 단지 동시 것들:

fn main() {
    let mut s = String::from("hello");

    {
        let r1 = &mut s;
    } // r1 goes out of scope here, so we can make a new reference with no problems.

    let r2 = &mut s;
}

러스트는 mutable과 immutable 참조를 결합할 때 비슷한 규칙을 적용합니다. 이 코드는 에러를 발생시킵니다:

fn main() {
    let mut s = String::from("hello");

    let r1 = &s; // no problem
    let r2 = &s; // no problem
    let r3 = &mut s; // BIG PROBLEM

    println!("{r1}, {r2}, and {r3}");
}

휴! 우리는 같은 값에 대한 불변의 참조를 가지고 있는 동안에는 가변 참조를 가질 수 없습니다.

변경 불가능한 참조의 사용자는 그 값이 갑자기 변경 될 것으로 기대하지 않습니다! 그러나 데이터를 읽는 사람 중 누구도 다른 사람의 데이터 읽기에 영향을 줄 수 없기 때문에 여러 변경 불가능한 참조가 허용됩니다.

레퍼런스의 범위는 레퍼런스가 사용된 마지막 시간을 통해 도입되고 계속됩니다. 예를 들어, 이 코드는 변경 가능한 레퍼런스의 마지막 사용이 println!에 있기 때문에, 변경 가능한 레퍼런스가 도입되기 전에 컴파일됩니다.

fn main() {
    let mut s = String::from("hello");

    let r1 = &s; // no problem
    let r2 = &s; // no problem
    println!("{r1} and {r2}");
    // Variables r1 and r2 will not be used after this point.

    let r3 = &mut s; // no problem
    println!("{r3}");
}

불변 참조의 범위 r1 그리고 r2 종료 후 println! 그들이 마지막으로 사용되는 곳, 즉 가변 참조 전에 r3 생성됩니다. 이러한 스코프는 겹치지 않으므로이 코드는 허용됩니다. 컴파일러는 스코프가 끝나기 전에 참조가 더 이상 사용되지 않는다고 말할 수 있습니다.

때때로 에러를 빌리는 것이 좌절스러울 수 있지만, 러스트 컴파일러는 잠재적인 버그를 조기에 지적하고 (실행 시간이 아닌 컴파일 시간에) 문제가 정확히 어디에 있는지를 보여줍니다. 그런 다음, 왜 여러분의 데이터가 여러분이 생각했던 것이 아닌지를 추적할 필요가 없습니다.

참고 문헌을

포인터가 있는 언어에서는, 매달려 있는 포인터(다른 사람에게 주어졌을 수도 있는 메모리의 위치를 참조하는 포인터)를 만드는 것은 쉽습니다. 반대로, 러스트에서는, 컴파일러는 참조가 결코 참조가 되지 않을 것임을 보증합니다: 만약 당신이 어떤 데이터에 대한 참조를 가지고 있다면, 컴파일러는 데이터가 데이터에 대한 참조 이전에 범위를 벗어나지 않도록 할 것입니다.

러스트가 어떻게 컴파일 타임 에러로 그것들을 방지하는지 보기 위해 매달린 참조를 생성해 봅시다:

dangle 코드의 각 단계에서 정확히 무슨 일이 일어나고 있는지 자세히 살펴 보겠습니다.

여기서 해결 방법은 String를 직접 반환하는 것입니다.

fn main() {
    let string = no_dangle();
}

fn no_dangle() -> String {
    let s = String::from("hello");

    s
}

이것은 문제없이 작동합니다. 소유권이 이동되고 아무 것도 할당 해제되지 않습니다.
