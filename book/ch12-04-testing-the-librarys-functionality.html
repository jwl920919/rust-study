The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

테스트 주도 개발을 통한 기능 추가

이제 src/lib.rs의 검색 로직을 main 함수와 분리했기 때문에 코드의 핵심 기능에 대한 테스트를 작성하는 것이 훨씬 쉬워졌습니다. 다양한 인수로 함수를 직접 호출하고, 명령줄에서 바이너리를 실행하지 않아도 반환 값을 확인할 수 있습니다.

이 섹션에서는 다음 단계를 따라 테스트 주도 개발(TDD) 프로세스를 사용하여 minigrep 프로그램에 검색 로직을 추가합니다.

  1. 실패하는 테스트를 작성하고 실행하여, 예상한 이유로 실패하는지 확인합니다.
  2. 새 테스트를 통과시키기에 충분한 코드만 작성하거나 수정합니다.
  3. 방금 추가하거나 변경한 코드를 리팩토링하고, 테스트가 계속 통과하는지 확인합니다.
  4. 1단계부터 반복합니다!

TDD는 소프트웨어를 작성하는 여러 방법 중 하나일 뿐이지만, 코드 설계를 주도하는 데 도움이 될 수 있습니다. 테스트를 통과시키는 코드를 작성하기 전에 테스트를 작성하면, 개발 과정 전반에 걸쳐 높은 테스트 커버리지를 유지하는 데 도움이 됩니다.

실제로 파일 내용에서 쿼리 문자열을 검색하고 쿼리와 일치하는 줄 목록을 생성하는 기능의 구현을 테스트해 보겠습니다. 이 기능을 search라는 함수에 추가합니다.

실패하는 테스트 작성

src/lib.rs 파일에 tests 모듈과 테스트 함수를 추가하겠습니다. 11장에서 했던 것과 같습니다. 이 테스트 함수는 search 함수가 가져야 할 동작을 정의합니다. 즉, 쿼리와 검색할 텍스트를 인자로 받아, 텍스트에서 쿼리를 포함하는 줄만 반환해야 합니다. 12-15번 목록에 이 테스트가 나와 있습니다.

이 테스트는 "duct" 문자열을 검색합니다. 검색 대상 텍스트는 3줄이며, 그중 1줄만 "duct"을 포함합니다(열린 이중 따옴표 뒤에 있는 백슬래시는 Rust에게 이 문자열 리터럴 내용의 시작 부분에 줄바꿈 문자를 넣지 말라고 지시합니다). search 함수에서 반환된 값이 우리가 예상하는 줄만 포함한다고 주장합니다.

이 테스트를 실행하면 현재 실패합니다. unimplemented! 매크로가 "not implemented"라는 메시지와 함께 패닉하기 때문입니다. TDD 원칙에 따라, search 함수를 항상 빈 벡터를 반환하도록 정의하여 함수 호출 시 테스트가 패닉하지 않도록 충분한 코드를 추가하는 작은 단계를 취합니다. 12-16 목록에 이 코드가 나와 있습니다. 그러면 빈 벡터가 "safe, fast, productive." 줄을 포함하는 벡터와 일치하지 않기 때문에 테스트는 컴파일은 되지만 실패해야 합니다.

이제 왜 우리가 명백한 평생을 정의해야하는지 논의 해 봅시다. 'a 상기 서명하는 단계는, In the signature, search [중고] 그 시절을 활용하라 contents 인수 및 반환 값입니다. 제 10 장 무시 lifetime 매개 변수는 반환 값의 수명과 연결된 인수 수명을 지정합니다. 이 경우 반환 된 벡터에는 인수의 슬라이스를 참조하는 문자열 조각이 포함되어야 함을 나타냅니다. contents (논란이 아닌 경우) query).

다시 말해, search 함수에 contents 인수로 전달된 데이터가 존재하는 동안 search 함수가 반환하는 데이터도 존재한다고 Rust에 알려주는 것입니다. 이 점은 매우 중요합니다! 슬라이스가 참조하는 데이터가 유효해야 참조도 유효합니다. 컴파일러가 contents 대신 query에 대한 문자열 슬라이스를 만드는 것으로 오해하면, 안전성 검사를 올바르게 수행하지 못합니다. search search contents query contents

라이프타임 주석을 생략하고 이 함수를 컴파일하려고 하면 다음과 같은 오류가 발생합니다:

Rust는 출력에 두 매개변수 중 어느 것이 필요한지 알 수 없으므로 명시적으로 알려주어야 합니다. 도움말 텍스트는 모든 매개변수와 반환 타입에 동일한 라이프타임 매개변수를 지정할 것을 제안하지만, 이는 잘못된 것입니다! contents는 모든 텍스트를 포함하는 매개변수이며, 해당 텍스트 중 일치하는 부분을 반환하려고 하므로 contents는 라이프타임 문법을 사용하여 반환 값과 연결해야 하는 유일한 매개변수입니다.

다른 프로그래밍 언어에서는 서명에서 인수를 반환 값과 연결할 필요가 없지만, 시간이 지나면 이 관행이 더 쉬워질 것입니다. 이 예제를 10장의 “라이프타임으로 참조 검증하기” 섹션의 예제와 비교해 보기를 권합니다.

테스트를 통과하는 코드 작성하기

현재 테스트가 실패하는 이유는 항상 빈 벡터를 반환하기 때문입니다. 이를 수정하고 search를 구현하려면 프로그램은 다음 단계를 따라야 합니다.

  1. contents의 각 줄을 반복합니다.
  2. 해당 줄에 쿼리 문자열이 포함되어 있는지 확인합니다.
  3. 그렇다면 반환할 값 목록에 추가합니다.
  4. 그렇지 않다면 아무것도 하지 않습니다.
  5. 일치하는 결과 목록을 반환합니다.

라인을 반복하는 것부터 시작하여 각 단계를 차례대로 살펴보겠습니다.

lines 메서드로 줄을 반복하기

Rust에는 문자열을 라인별로 반복 처리하는 데 도움이 되는 lines라는 메서드가 있습니다. 이 메서드는 Listing 12-17과 같이 동작합니다. 참고로 이 코드는 아직 컴파일되지 않습니다.

lines 메서드는 반복자를 반환합니다. 제 13 장에서 반복자에 대해 자세히 설명하겠습니다. 그러나 목록 3-5에서 반복자를 사용하는이 방법을 보았다는 것을 기억하십시오. 여기서 for 루프를 반복기와 함께 사용하여 컬렉션의 각 항목에 대한 코드를 실행합니다.

각 줄에서 쿼리 검색

다음으로, 현재 줄에 쿼리 문자열이 포함되어 있는지 확인합니다. 다행히도 문자열에는 이 작업을 수행하는 데 유용한 contains 메서드가 있습니다! Listing 12-18에 표시된 것처럼 contains 함수에 search 메서드 호출을 추가하세요. 아직 이 코드는 컴파일되지 않습니다.

현재 우리는 기능을 구축하고 있습니다. 코드를 컴파일하려면, 함수 서명에서 명시했듯이 함수 본문에서 값을 반환해야 합니다.

일치하는 줄 저장

이 함수를 완성하려면, 반환하고자 하는 일치하는 줄을 저장하는 방법이 필요합니다. 이를 위해 for 루프 전에 가변 벡터를 만들고, push 메서드를 호출하여 line를 벡터에 저장합니다. for 루프가 끝난 후, Listing 12-19에 표시된 것처럼 벡터를 반환합니다.
