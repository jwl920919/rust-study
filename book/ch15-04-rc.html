The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

Rc<T>참조 개수 스마트 포인터Reference-Counted Smart Pointer

대부분의 경우 소유권은 명확합니다. 어떤 변수가 특정 값을 소유하고 있는지 정확히 알 수 있습니다. 그러나 단일 값이 여러 소유자를 가질 수있는 경우가 있습니다. 예를 들어 그래프 데이터 구조에서 여러 가장자리가 동일한 노드를 가리킬 수 있으며 해당 노드는 해당 노드를 가리키는 모든 가장자리에 의해 개념적으로 소유됩니다. 노드에는 가장자리가 없으므로 소유자가없는 한 노드를 정리해서는 안됩니다.

참조 카운트의 약자인 러스트 유형 Rc<T>를 사용하여 명시 적으로 여러 소유권을 활성화해야합니다. Rc<T> 유형은 값에 대한 참조 수를 추적하여 값이 아직 사용 중인지 여부를 결정합니다. 값에 대한 참조가 제로 인 경우 아무런 참조없이 값을 정리할 수 있습니다.

Rc<T>를 가족 방에서 TV로 상상해보십시오. 한 사람이 TV를 시청하기 위해 들어가면 TV를 ⁇ 니다. 다른 사람들은 방에 들어가서 TV를 볼 수 있습니다. 마지막 사람이 방을 나가면 더 이상 사용되지 않기 때문에 TV를 끕니다. 다른 사람들이 여전히 시청하는 동안 누군가가 TV를 끄면 나머지 TV 시청자의 소란이있을 것입니다!

Rc<T> 타입은 프로그램의 여러 부분에 대해 힙에 데이터를 할당하고자 할 때 사용하며, 컴파일 시에 어느 부분이 마지막에 데이터를 사용할지 결정할 수 없습니다. 만약 어떤 부분이 마지막으로 끝날지 알고 있다면, 우리는 그 부분을 데이터의 소유자로 만들 수 있습니다.

Rc<T>는 단일 스레드 시나리오에서만 사용할 수 있습니다. 16 장에서 동시성을 논의 할 때 다중 스레드 프로그램에서 참조 카운트를 수행하는 방법을 다룰 것입니다.

참조 수를 늘리기 위한 복제

Listing 15-18의 작업 예제를 변경하여 참조 카운트가 다음과 같은 참조를 생성하고 드롭할 때 변경되는 것을 볼 수 있습니다. Rc<List> 에서 a.

Listing 15-19에서는 main를 변경하여 c 목록 주위에 내부 스코프가 있도록 할 것입니다; 그러면 c가 스코프 밖으로 나갈 때 참조 카운트가 어떻게 변하는지 볼 수 있습니다.

참조 카운트가 변경되는 프로그램의 각 지점에서 우리는 참조 카운트를 인쇄합니다. Rc::strong_count 이 함수의 이름은 다음과 같습니다. strong_count 보다는 count 왜냐하면 The Rc<T> 종류는 또한 A weak_count우리는 무엇을 보게 될 것입니다. weak_count 를 위해 사용됩니다 "참조주기 방지 Weak<T>” 무시 .

우리는 이것을 볼 수 있습니다. Rc<List> 에서 a 1의 초기 참조 카운트를 갖는다; 그리고 우리가 호출할 때마다 clone, 카운트가 1만큼 증가합니다. c 범위를 벗어나면 카운트가 1만큼 내려갑니다. 호출해야하는 것처럼 참조 카운트를 줄이기 위해 함수를 호출 할 필요가 없습니다. Rc::clone 참조 카운트를 증가시키기 위해: Drop 특성은 때 참조 카운트를 자동으로 감소 Rc<T> 값은 범위를 벗어납니다.

이 예에서 볼 수 없는 것은 b와 a가 main의 끝에서 범위를 벗어나면 카운트가 0이고 Rc<List>가 완전히 정리된다는 것입니다. Rc<T>를 사용하면 단일 값이 여러 소유자를 가질 수 있으며 카운트는 값이 여전히 유효한 상태로 유지됩니다.
