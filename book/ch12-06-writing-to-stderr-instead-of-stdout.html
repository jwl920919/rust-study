The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

오류를 표준 오류로 바꾸기Redirecting Errors to Standard Error

현재 println! 매크로를 사용하여 모든 출력을 터미널에 쓰고 있습니다. 대부분의 터미널에는 일반 정보의 표준 출력 (stdout)과 오류 메시지의 표준 오류 (stderr)의 두 가지 출력이 있습니다. 이 구별을 통해 사용자는 프로그램의 성공적인 출력을 파일로 지시하고 화면에 오류 메시지를 인쇄 할 수 있습니다.

println! 매크로는 표준 출력으로만 인쇄할 수 있으므로 표준 오류로 인쇄하려면 다른 것을 사용해야 합니다.

오류가 기록되는 위치 확인

먼저, minigrep가 인쇄한 콘텐츠가 현재 표준 출력에 어떻게 기록되고 있는지 살펴보겠습니다. 표준 오류에 대해 기록하려는 오류 메시지를 포함합니다. 의도적으로 오류를 발생시키는 동안 표준 출력 스트림을 파일로 리디렉션하여 이 작업을 수행합니다. 표준 오류 스트림을 리디렉션하지 않으므로 표준 오류로 전송된 콘텐츠는 화면에 계속 표시됩니다.

명령 줄 프로그램은 표준 출력 스트림을 파일로 리디렉션하더라도 화면에 오류 메시지를 계속 볼 수 있도록 표준 오류 스트림에 오류 메시지를 보낼 것으로 예상됩니다. 우리의 프로그램은 현재 잘 동작하지 않습니다. 대신 오류 메시지 출력을 파일에 저장하는 것을 보게 될 것입니다!

이 동작을 보여주기 위해 >와 파일 경로, output.txt를 사용하여 표준 출력 스트림을 리디렉션 할 것입니다. 우리는 오류를 일으키는 인수를 전달하지 않습니다.

$ cargo run > output.txt

> 구문은 쉘이 화면 대신 output.txt에 표준 출력의 내용을 작성하도록 지시합니다. 화면에 인쇄할 때 예상했던 오류 메시지가 표시되지 않았기 때문에 파일에 저장되어 있어야 합니다. 이것이 output.txt가 포함하는 내용입니다.

Problem parsing arguments: not enough arguments

예, 오류 메시지가 표준 출력으로 인쇄되고 있습니다. 성공적인 실행의 데이터 만 파일에 저장되도록 이와 같은 오류 메시지가 표준 오류로 인쇄되는 것이 훨씬 더 유용합니다. 우리는 그것을 바꿀 것입니다.

표준 오류에 대한 인쇄 오류

Listing 12-24의 코드를 사용하여 오류 메시지가 인쇄되는 방법을 변경합니다. 이 장의 앞부분에서 했던 리팩토링 때문에 오류 메시지를 인쇄하는 모든 코드는 하나의 함수에 있습니다. main. 표준 라이브러리는 eprintln! 표준 오류 스트림에 인쇄하는 매크로, 그래서 우리가 호출 한 두 장소를 변경하자 println! 사용할 오류를 인쇄하려면 eprintln! 대신.

이제 인수 없이 >를 사용하여 표준 출력을 리디렉션하지 않고 같은 방식으로 프로그램을 다시 실행해 보겠습니다.

$ cargo run > output.txt
Problem parsing arguments: not enough arguments

이제 화면에 오류가 표시되고 output.txt에는 명령줄 프로그램에서 기대하는 동작이 아무것도 포함되어 있지 않습니다.

오류를 일으키지 않지만 여전히 표준 출력을 파일로 리디렉션하는 인수를 사용하여 프로그램을 다시 실행해 보겠습니다.Let's run the program again with arguments that don't cause an error but still redirect standard output to a file, like so:

$ cargo run -- to poem.txt > output.txt

우리는 터미널에 어떤 출력도 보지 않을 것이고, output.txt는 우리의 결과를 포함할 것입니다:

파일명: output.txt

Are you nobody, too?
How dreary to be somebody!

이는 이제 성공적인 출력을 위해 표준 출력을 사용하고 적절한 오류 출력을 위해 표준 오류를 사용하고 있음을 보여줍니다.

요약

이 장에서는 지금까지 배운 주요 개념 중 일부를 다시 살펴보고 러스트에서 일반적인 I/O 작업을 수행하는 방법을 다루었습니다. 명령줄 인수, 파일, 환경 변수 및 eprintln! 매크로를 사용하여 오류를 인쇄할 수 있으므로 이제 명령줄 응용 프로그램을 작성할 준비가 되었습니다. 이전 장의 개념과 결합하여 코드가 잘 정리되고, 적절한 데이터 구조에 효과적으로 데이터를 저장하며, 오류를 잘 처리하고, 테스트를 잘 수행할 수 있습니다.
