The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

매크로

이 책에서는 println!와 같은 매크로를 사용해 왔지만, 매크로가 무엇이고 어떻게 작동하는지 완전히 다루지는 않았습니다. 매크로라는 용어는 Rust의 기능 집합을 가리키며, macro_rules!을 사용하는 선언적 매크로와 세 가지 종류의 절차적 매크로를 포함합니다.

  • struct와 enum에 사용되는 derive 속성으로, 추가할 코드를 지정하는 사용자 정의 #[derive] 매크로입니다. derive
  • 모든 항목에 사용할 수 있는 사용자 정의 속성을 정의하는 속성형 매크로
  • 함수 호출처럼 보이지만 인수로 지정된 토큰을 조작하는 함수형 매크로

이 각각에 대해 차례로 설명하겠습니다. 먼저, 이미 함수가 있는 상황에서 왜 매크로가 필요한지 살펴 보겠습니다.

매크로와 함수의 차이점

기본적으로 매크로는 다른 코드를 작성하는 코드를 작성하는 방법이며, 이를 메타프로그래밍이라고 합니다. 부록 C에서는 다양한 트레이트의 구현을 생성해 주는 derive 속성에 대해 논의합니다. 또한 이 책 전체에서 println! 및 vec! 매크로를 사용해 왔습니다. 이러한 모든 매크로는 사용자가 수동으로 작성한 코드보다 더 많은 코드를 생성하도록 확장됩니다.

메타 프로그래밍은 작성하고 유지보수해야 하는 코드의 양을 줄이는 데 유용하며, 이는 함수의 역할 중 하나이기도 합니다. 그러나 매크로는 함수가 갖지 않는 몇 가지 추가 기능을 제공합니다.

함수 서명에는 함수가 가진 매개변수의 수와 타입을 선언해야 합니다. 반면 매크로는 가변 수의 매개변수를 받을 수 있습니다. 예를 들어, 하나의 인수로 println!("hello")를 호출하거나 두 개의 인수로 println!("hello {}", name)를 호출할 수 있습니다. 또한 매크로는 컴파일러가 코드의 의미를 해석하기 전에 확장되므로, 주어진 타입에 대해 트레이트를 구현할 수 있습니다. 함수는 런타임에 호출되므로 컴파일 타임에 트레이트를 구현해야 하는 요구사항을 충족할 수 없습니다.

함수 대신 매크로를 구현하는 단점은 매크로 정의가 함수 정의보다 복잡하다는 것입니다. 이는 Rust 코드를 작성하는 Rust 코드를 작성하기 때문입니다. 이러한 간접성으로 인해 매크로 정의는 일반적으로 함수 정의보다 읽기, 이해, 유지보수가 더 어렵습니다.

매크로와 함수의 또 다른 중요한 차이점은, 함수는 어디서든 정의하고 어디서든 호출할 수 있는 반면, 매크로는 파일 내에서 호출하기 전에 정의하거나 스코프에 가져와야 한다는 것입니다.

일반 메타 프로그래밍을 위한 선언적 매크로

러스트에서 가장 널리 사용되는 매크로 형태는 다음과 같습니다. 선언적 매크로. 이들은 또한 때때로 "예에 의해 매크로"라고합니다.macro_rules! 매크로(macros), 혹은 그냥 "매크로(macros)"라고 말할 수 있습니다. 선언적인 매크로를 사용하면 러스트와 비슷한 것을 작성할 수 있습니다. match 표현. 6 장에서 논의 한 바와 같이, match 표현식은 표현식을 받아들이고, 표현식의 결과 값을 패턴과 비교한 다음, 일치하는 패턴과 관련된 코드를 실행하는 제어 구조입니다. 매크로는 또한 특정 코드와 관련된 패턴과 값을 비교합니다. 이 경우, 값은 매크로에 전달된 문자 그대로의 러스트 소스 코드입니다; 패턴은 해당 소스 코드의 구조와 비교됩니다. 그리고 각 패턴과 일치하는 코드는 매크로에 전달된 코드를 대체합니다.

매크로를 정의하려면 macro_rules! 구조를 사용합니다. macro_rules!의 사용 방법을 vec! 매크로의 정의를 살펴봄으로써 알아보겠습니다. 8장에서는 vec! 매크로를 사용하여 특정 값을 가진 새로운 벡터를 생성하는 방법에 대해 다루었습니다. 예를 들어, 다음 매크로는 세 개의 정수를 포함하는 새로운 벡터를 생성합니다:

#![allow(unused)]
fn main() {
let v: Vec<u32> = vec![1, 2, 3];
}

vec! 매크로를 사용하여 두 개의 정수로 이루어진 벡터나 다섯 개의 문자열 슬라이스로 이루어진 벡터를 만들 수도 있습니다. 함수로는 동일한 작업을 수행할 수 없는데, 이는 사전에 값의 수나 타입을 알 수 없기 때문입니다.

참고: 표준 라이브러리의 vec! 매크로 실제 정의에는 필요한 메모리 양을 미리 할당하는 코드가 포함되어 있습니다. 이 코드는 예제를 더 간단하게 만들기 위해 여기에는 포함하지 않은 최적화입니다.

#[macro_export] 주석은 매크로가 정의된 크레이트가 스코프에 들어올 때마다 해당 매크로를 사용할 수 있어야 함을 나타냅니다. 이 주석이 없으면 매크로를 스코프에 가져올 수 없습니다.

그런 다음 macro_rules!로 매크로 정의를 시작하고, 느낌표를 제외한 정의하려는 매크로의 이름을 붙입니다. 이 경우 vec이라는 이름 뒤에 매크로 정의의 본문을 나타내는 중괄호가 따라옵니다.

vec! 본문의 구조는 match 식의 구조와 유사합니다. 여기에는 ( $( $x:expr ),* ) 패턴을 가진 팔(arm)이 하나 있고, => 뒤에 이 패턴과 연관된 코드 블록이 있습니다. 패턴이 일치하면 연관된 코드 블록이 출력됩니다. 이 매크로에는 이 패턴이 유일하므로 유효한 매칭 방식은 하나뿐이며, 다른 패턴은 오류를 일으킵니다. 더 복잡한 매크로는 여러 개의 팔을 가질 수 있습니다.

매크로 정의에서 유효한 패턴 문법은 19장에서 다루는 패턴 문법과 다릅니다. 매크로 패턴은 값이 아닌 Rust 코드 구조와 매칭되기 때문입니다. Listing 20-29의 패턴 조각이 의미하는 바를 살펴보고, 전체 매크로 패턴 문법은 Rust Reference를 참조하십시오.

첫째, 괄호를 사용하여 전체 패턴을 감쌉니다. 달러 기호($)를 사용하여 매크로 시스템에서 패턴과 일치하는 Rust 코드를 포함할 변수를 선언합니다. 달러 기호는 이것이 일반 Rust 변수가 아닌 매크로 변수임을 명확히 합니다. 다음으로, 대체 코드에서 사용하기 위해 괄호 안의 패턴과 일치하는 값을 캡처하는 괄호가 있습니다. $() 안에는 $x:expr가 있으며, 이는 어떤 Rust 표현식과도 일치하고 해당 표현식에 $x이라는 이름을 부여합니다.

$() 뒤에 오는 쉼표는 $()의 코드와 일치하는 각 인스턴스 사이에 문자 그대로의 쉼표 구분 문자가 나타나야 함을 나타냅니다. *는 패턴이 * 앞에 있는 항목과 0회 이상 일치하도록 지정합니다.

vec![1, 2, 3];를 사용하여 이 매크로를 호출하면 $x 패턴이 1, 2, 3의 세 식과 세 번 일치합니다.

이제 이 팔(arm)에 해당하는 코드 본문의 패턴을 살펴 보겠습니다. temp_vec.push() 내부의 $()*은 패턴이 $()와 0회 이상 일치하는 각 부분에 대해 생성됩니다. $x은 일치하는 각 식으로 대체됩니다. vec![1, 2, 3];로 이 매크로를 호출하면, 이 매크로 호출을 대체하는 생성된 코드는 다음과 같습니다.

{
    let mut temp_vec = Vec::new();
    temp_vec.push(1);
    temp_vec.push(2);
    temp_vec.push(3);
    temp_vec
}

모든 유형의 인수를 아무 개수나 받을 수 있고, 지정된 요소가 포함된 벡터를 생성하는 코드를 생성할 수 있는 매크로를 정의했습니다.

매크로를 작성하는 방법에 대해 더 자세히 알고 싶다면 온라인 문서나 Daniel Keep이 시작하고 Lukas Wirth가 이어간 “The Little Book of Rust Macros” 같은 다른 자료를 참고하십시오.

속성으로부터 코드를 생성하는 절차적 매크로

매크로의 두 번째 형태는 절차적 매크로(procedural macro)입니다. 절차적 매크로는 함수처럼 동작하며, 절차(procedure)의 한 유형입니다. 절차적 매크로는 선언적 매크로가 패턴과 일치시켜 코드를 다른 코드로 대체하는 방식과 달리, 코드를 입력으로 받아 해당 코드에 작업을 수행한 뒤 코드를 출력으로 생성합니다. 절차적 매크로는 사용자 정의 derive, 속성(attribute) 유사, 함수 유사라는 세 가지 종류가 있으며, 모두 유사한 방식으로 동작합니다.

절차적 매크로를 생성할 때, 정의는 특별한 크레이트 타입을 가진 별도의 크레이트에 위치해야 합니다. 이는 향후 제거하기를 희망하는 복잡한 기술적 이유 때문입니다. Listing 20-36에서는 some_attribute가 특정 매크로 종류를 사용하는 자리 표시자임을 전제로, 절차적 매크로를 정의하는 방법을 보여줍니다.

TokenStream. 이 함수는 또한 우리가 만들고 있는 절차 매크로의 종류를 지정하는 속성이 있습니다. 우리는 같은 크레이트에 절차 매크로의 여러 종류를 가질 수 있습니다.

다양한 종류의 절차적 매크로를 살펴보겠습니다. 먼저 사용자 정의 derive 매크로로 시작하여, 다른 형태를 구별하는 미묘한 차이점을 설명하겠습니다.

사용자 정의 derive 매크로

hello_macro이라는 이름의 크레이트를 만들어 HelloMacro이라는 트레이트를 정의하겠습니다. 이 트레이트에는 hello_macro이라는 연관 함수가 하나 있습니다. 사용자가 각 타입마다 HelloMacro 트레이트를 직접 구현하도록 하지 않고, 절차 매크로를 제공하여 사용자가 자신의 타입에 #[derive(HelloMacro)]라고 주석을 달기만 하면 hello_macro 함수의 기본 구현을 자동으로 받을 수 있게 하겠습니다. 이 기본 구현은 Hello, Macro! 코드를 두 함수로 나눈 점에 주목하세요. hello_macro_derive 함수는 TokenStream를 파싱하고, impl_hello_macro 함수는 구문 트리를 변환합니다. 이렇게 나누면 절차적 매크로를 더 편리하게 작성할 수 있습니다. 바깥 함수(이 예제에서는 hello_macro_derive)의 코드는 여러분이 접하거나 만드는 거의 모든 절차적 매크로 크레이트에서 동일합니다. 안쪽 함수(이 예제에서는 impl_hello_macro)의 본문은 절차적 매크로의 목적에 따라 달라집니다.

proc_macro, syn, quote라는 세 가지 새로운 크레이트를 소개했습니다. proc_macro 크레이트는 Rust와 함께 제공되므로 Cargo.toml의 종속성에 추가할 필요가 없습니다. proc_macro 크레이트는 Rust 코드를 읽고 조작할 수 있도록 해주는 컴파일러의 API입니다.

syn 크레이트는 Rust 코드를 문자열에서 조작할 수 있는 데이터 구조로 파싱합니다. quote 크레이트는 syn 데이터 구조를 다시 Rust 코드로 변환합니다. 이 크레이트들은 처리하고자 하는 모든 종류의 Rust 코드를 파싱하는 과정을 훨씬 더 간단하게 만들어 줍니다. Rust 코드에 대한 완전한 파서를 작성하는 것은 쉬운 일이 아니기 때문입니다.

hello_macro_derive 함수는 라이브러리 사용자가 형식에 #[derive(HelloMacro)]를 지정할 때 호출됩니다. 이는 hello_macro_derive 함수에 proc_macro_derive 프로시저 매크로 속성을 붙이고, 트레이트 이름과 일치하는 HelloMacro라는 이름을 지정했기 때문에 가능합니다. 대부분의 절차적 매크로가 이 관례를 따릅니다.

hello_macro_derive 함수는 먼저 input을 TokenStream에서 해석하고 작업을 수행할 수 있는 데이터 구조로 변환합니다. 여기에서 syn이 역할을 합니다. syn의 parse 함수는 TokenStream을 받아 파싱된 Rust 코드를 나타내는 DeriveInput 구조체를 반환합니다. 목록 20-41은 struct Pancakes; 문자열을 파싱하여 얻는 DeriveInput 구조체의 관련 부분을 보여줍니다.

이 구조체의 필드는 우리가 파싱한 러스트 코드가 unit 구조체라는 것을 보여줍니다. ident (식별자이름의 의미) Pancakes. 이 구조체에는 모든 종류의 러스트 코드를 설명하기 위한 더 많은 필드들이 있습니다. syn 관련 문서 DeriveInput 더 많은 정보.

곧 impl_hello_macro 함수를 정의할 것입니다. 이 함수는 우리가 포함시키고 싶은 새로운 Rust 코드를 생성하는 곳입니다. 하지만 그 전에, derive 매크로의 출력도 derive 임을 알아두세요. 반환된 TokenStream 은 크레이트 사용자가 작성한 코드에 추가되므로, 사용자가 자신의 크레이트를 컴파일할 때 수정된 TokenStream 에서 우리가 제공하는 추가 기능을 얻게 됩니다. TokenStream

여기서 unwrap을 호출하여 hello_macro_derive 함수가 syn::parse 함수 호출에 실패할 경우 패닉하도록 만드는 것을 눈치챘을 수도 있습니다. 절차 매크로가 오류 발생 시 패닉해야 하는 이유는, 절차 매크로 API를 준수하기 위해 proc_macro_derive 함수가 TokenStream 대신 Result을 반환해야 하기 때문입니다. 이 예제에서는 unwrap을 사용하여 단순화했습니다. 프로덕션 코드에서는 panic! 또는 expect을 사용하여 무엇이 잘못되었는지에 대해 보다 구체적인 오류 메시지를 제공해야 합니다.

이제 주석이 붙은 Rust 코드를 TokenStream에서 DeriveInput 인스턴스로 변환하는 코드를 갖추었으므로, Listing 20-42에 나와 있듯이 주석이 붙은 타입에 HelloMacro 트레잇을 구현하는 코드를 생성해 보겠습니다.

우리는 얻을 Ident 주석이 달린 형식의 이름(식별자)을 포함하는 struct 인스턴스 ast.ident. Listing 20-41의 struct는 우리가 impl_hello_macro Listing 20-37의 코드에 대한 함수, ident 우리는 얻을 것이다 ident 값을 가진 필드 "Pancakes". 따라서, name Listing 20-42의 변수는 Ident struct 인스턴스는, 출력될 때, 문자열이 될 것이다. "Pancakes"Listing 20-37에 있는 구조체의 이름입니다.

quote! 매크로는 반환하려는 Rust 코드를 정의할 수 있게 합니다. 컴파일러는 quote! 매크로 실행의 직접적인 결과와 다른 것을 기대하므로, TokenStream로 변환해야 합니다. 이를 위해 이 중간 표현을 소비하고 필요한 TokenStream 타입의 값을 반환하는 into 메서드를 호출합니다.

quote! 매크로는 매우 멋진 템플팅 메커니즘도 제공합니다. #name을 입력하면 quote!가 이를 변수 name의 값으로 대체합니다. 일반 매크로가 작동하는 방식과 유사하게 반복도 수행할 수 있습니다. 자세한 소개는 quote 크레이트의 문서를 확인하십시오.

우리는 절차적 매크로가 사용자가 주석을 달고 있는 타입에 대해 HelloMacro 트레잇의 구현을 생성하기를 원합니다. #name을(를) 사용하면 해당 타입을 가져올 수 있습니다. 이 트레잇 구현에는 hello_macro 함수 하나만 있으며, 이 함수의 본문에는 우리가 제공하고자 하는 기능이 포함되어 있습니다. 즉, Hello, Macro! My name is을 출력한 다음 주석이 달린 타입의 이름을 출력하는 것입니다.

여기서 사용하는 stringify! 매크로는 Rust에 내장되어 있습니다. 이 매크로는 1 + 2과 같은 Rust 표현식을 받아서, 컴파일 시점에 "1 + 2"과 같은 문자열 리터럴로 변환합니다. 이는 표현식을 평가한 후 그 결과를 String로 변환하는 format! 또는 println! 매크로와 다릅니다. #name 입력이 그대로 출력할 표현식일 가능성이 있으므로, 우리는 stringify!을 사용합니다. stringify!을 사용하면 컴파일 시점에 #name를 문자열 리터럴로 변환함으로써 할당을 하나 절약할 수 있습니다.

Listing 20-37의 코드에 이 크레이트들을 연결하여 절차적 매크로가 실제로 동작하는 모습을 확인해 보겠습니다. 프로젝트 디렉터리에서 cargo new pancakes 명령을 사용하여 새로운 바이너리 프로젝트를 생성합니다. hello_macro과 hello_macro_derive을 pancakes 크레이트의 카고.toml 파일에 의존성으로 추가해야 합니다. hello_macro과 hello_macro_derive의 버전을 크레이트.io에 게시하는 경우라면 일반적인 의존성이 되지만, 그렇지 않다면 다음과 같이 경로 의존성으로 지정할 수 있습니다. path

속성과 같은 매크로

속성과 같은 매크로는 사용자 정의와 유사합니다. derive 매크로,하지만 대신 코드를 생성 derive attribute를 사용하면 새로운 attribute를 만들 수 있습니다. 또한 더 유연합니다. derive structs와 enums에 대해서만 작동합니다. 속성은 함수와 같은 다른 항목에도 적용될 수 있습니다. 여기에 속성과 같은 매크로를 사용하는 예가 있습니다. 이름에 속성이 있다고 가정 해 봅시다. route 웹 애플리케이션 프레임워크를 사용할 때 다음 함수에 주석을 달 수 있습니다.

#[route(GET, "/")]
fn index() {

이 #[route] 속성은 프레임워크에서 절차형 매크로로 정의됩니다. 매크로 정의 함수의 서명은 다음과 같습니다.

#[proc_macro_attribute]
pub fn route(attr: TokenStream, item: TokenStream) -> TokenStream {

여기서 TokenStream 유형의 두 가지 매개변수가 있습니다. 첫 번째는 속성의 내용, 즉 GET, "/" 부분을 나타냅니다. 두 번째는 속성이 붙은 항목의 본문으로, 이 경우 fn index() {} 및 나머지 함수 본문입니다.

그 외에는 속성형 매크로가 사용자 지정 derive 매크로와 동일한 방식으로 작동합니다. proc-macro 크레이트 유형으로 크레이트를 만들고 원하는 코드를 생성하는 함수를 구현하면 됩니다!

함수형 매크로

함수형 매크로는 함수 호출처럼 보이는 매크로를 정의합니다. macro_rules! 매크로와 마찬가지로 함수보다 더 유연하며, 예를 들어 알 수 없는 수의 인수를 받을 수 있습니다. 그러나 macro_rules! 매크로는 앞서 “일반 메타프로그래밍을 위한 선언적 매크로”일반 메타프로그래밍을 위한 macro_rules! 선언형 매크로 섹션에서 다룬 매칭 유사 구문을 사용하여만 정의할 수 있습니다. 함수형 매크로는 TokenStream 매개변수를 받으며, 그 정의는 다른 두 종류의 절차 매크로처럼 Rust 코드를 사용하여 해당 TokenStream를 조작합니다. 함수형 매크로의 예로, 다음과 같이 호출할 수 있는 sql! 매크로가 있습니다.

let sql = sql!(SELECT * FROM posts WHERE id=1);

이 매크로는 내부의 SQL 문을 구문 분석하여 문법적으로 올바른지 확인합니다. 이는 macro_rules! 매크로가 수행할 수 있는 것보다 훨씬 복잡한 처리입니다. sql! 매크로는 다음과 같이 정의됩니다:

#[proc_macro]
pub fn sql(input: TokenStream) -> TokenStream {

이 정의는 사용자 지정 derive 매크로의 서명과 유사합니다. 괄호 안에 있는 토큰을 받고 생성하고자 하는 코드를 반환합니다.
