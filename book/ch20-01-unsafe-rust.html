The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

안전 하지 않은 녹

지금까지 논의한 모든 코드에는 러스트의 메모리 안전 보장이 컴파일 시간에 적용되었습니다. 그러나 러스트에는 이러한 메모리 안전 보장을 적용하지 않는 두 번째 언어가 숨겨져 있습니다. 그것은 안전하지 않은 러스트라고 불리며 일반 러스트와 마찬가지로 작동하지만 우리에게 여분의 초능력을줍니다.

Unsafe 러스트는 본질적으로 정적 분석이 보수적이기 때문에 존재합니다. 컴파일러가 코드가 보증을 준수하는지 여부를 결정하려고 할 때, 유효하지 않은 프로그램을 수락하는 것보다 유효한 프로그램을 거부하는 것이 더 좋습니다. 코드가 괜찮을 수도 있지만, 러스트 컴파일러가 확신 할 수있는 정보가 충분하지 않으면 코드를 거부합니다. 이러한 경우, null 코드를 사용하여 컴파일러에게 "신뢰할 수 없습니다. 안전하지 않은 것을 알고 있습니다.

러스트가 안전하지 않은 대안을 가진 또 다른 이유는 기본 컴퓨터 하드웨어가 본질적으로 안전하지 않다는 것입니다. 러스트가 안전하지 않은 작업을 수행하도록 허용하지 않으면 특정 작업을 수행 할 수 없습니다. 러스트는 운영 체제와 직접 상호 작용하거나 자체 운영 체제를 작성하는 것과 같은 저수준 시스템 프로그래밍을 수행 할 수 있도록해야합니다. 저수준 시스템 프로그래밍을 사용하는 것이 언어의 목표 중 하나입니다. 안전하지 않은 러스트로 할 수있는 일과 그것을 수행하는 방법을 살펴 보겠습니다.

안전하지 않은 초강대국 Unsafe Superpowers

안전하지 않은 러스트로 전환하려면 unsafe 키워드를 사용하고 안전하지 않은 코드를 포함하는 새로운 블록을 시작하십시오. 안전하지 않은 러스트에서 안전하지 않은 초강대국이라고 부르는 5 가지 작업을 수행 할 수 있습니다. 이러한 초강대국에는 다음 기능이 포함됩니다.

  1. 원시 포인터를 역참조합니다.
  2. 안전하지 않은 함수 또는 메서드를 호출합니다.
  3. 가변 정적 변수에 액세스하거나 수정합니다.
  4. 안전하지 않은 특성을 구현합니다.
  5. union의 액세스 필드.

unsafe가 빌림 검사기를 끄거나 러스트의 다른 안전 검사를 비활성화하지 않는다는 것을 이해하는 것이 중요합니다. 안전하지 않은 코드에서 참조를 사용하는 경우 여전히 확인됩니다. unsafe 키워드는 컴파일러가 메모리 안전을 검사하지 않는 다섯 가지 기능에만 액세스 할 수 있습니다. 여전히 안전하지 않은 블록 내에서 어느 정도의 안전을 얻을 수 있습니다.

또한 unsafe는 블록 내부의 코드가 반드시 위험하거나 메모리 안전 문제가 있음을 의미하지 않습니다. 프로그래머로서 unsafe 블록 내부의 코드가 유효한 방식으로 메모리에 액세스하도록 보장합니다.

사람들은 실수를 할 수 있지만 unsafe로 주석이 달린 블록 안에이 다섯 가지 안전하지 않은 작업을 요구함으로써 메모리 안전과 관련된 모든 오류가 unsafe 블록 내에 있어야한다는 것을 알게 될 것입니다. unsafe 블록을 작게 유지하십시오. 나중에 메모리 버그를 조사 할 때 감사 할 것입니다.

안전하지 않은 코드를 가능한 한 격리하려면 안전한 추상화 내에서 이러한 코드를 동봉하고 안전한 API를 제공하는 것이 가장 좋습니다. 이 API는 안전하지 않은 함수 및 메서드를 검사할 때 나중에 장에서 논의할 것입니다. 표준 라이브러리의 일부는 감사 된 안전하지 않은 코드보다 안전한 추상화로 구현됩니다. 안전한 추상화로 안전하지 않은 코드를 감싸는 것은 사용을 방지합니다. unsafe 당신이나 당신의 사용자가 구현 된 기능을 사용하고자 할 수도있는 모든 장소로 유출에서 unsafe 안전한 추상화를 사용하는 것이 안전하기 때문입니다.

안전하지 않은 다섯 가지 초강대국을 차례로 살펴 보겠습니다. 안전하지 않은 코드에 대한 안전한 인터페이스를 제공하는 추상화도 살펴 보겠습니다.

원시 포인터 삭제Dereferencing a Raw Pointer

4 장에서 “거친 참조 문헌” 섹션에서 컴파일러가 참조가 항상 유효한지 확인했습니다. 안전하지 않은 러스트에는 참조와 유사한 원시 포인터라는 두 가지 새로운 유형이 있습니다. 참조와 마찬가지로 원시 포인터는 불변 또는 변경이 가능하며 *const T 및 *mut T로 직접 기록됩니다. 별표는 역참조 연산자가 아닙니다.

참조 및 스마트 포인터, 원시 포인터와 다른 :

  • 불변 및 가변 포인터 또는 동일한 위치에 대한 다중 가변 포인터를 모두 사용하여 차입 규칙을 무시할 수 있습니다.
  • 유효한 메모리를 가리킬 수 없습니다.
  • null 이 될 수 있습니다.
  • 자동 정리를 구현하지 마십시오.

러스트가 이러한 보증을 시행하지 않도록 선택함으로써, 여러분은 더 높은 성능 또는 러스트의 보증이 적용되지 않는 다른 언어 또는 하드웨어와 인터페이스할 수 있는 능력에 대한 대가로 보장된 안전성을 포기할 수 있습니다.

안전하지 않은 함수 또는 메서드 호출

안전하지 않은 블록에서 수행할 수 있는 두 번째 유형의 작업은 안전하지 않은 함수를 호출하는 것입니다. 안전하지 않은 함수 및 메서드는 일반 함수 및 메서드와 똑같이 보이지만 추가 기능이 있습니다. unsafe 정의의 나머지 전에. unsafe 이 문맥에서 keyword는 함수가 이 함수를 호출할 때 유지해야 하는 요구사항을 가지고 있음을 나타냅니다. 러스트는 우리가 이러한 요구사항을 충족했음을 보장할 수 없기 때문입니다. 안전하지 않은 함수를 호출함으로써 unsafe 블록, 우리는 우리가이 함수의 문서를 읽고 우리는 함수의 계약을 유지에 대 한 책임을가지고 말하는 거 야.

안전하지 않은 코드에 대한 안전한 추상화 만들기

러스트의 빌림 검사기는 우리가 슬라이스의 다른 부분을 빌리고 있다는 것을 이해할 수 없습니다. 그것은 단지 우리가 같은 슬라이스에서 두 번 빌리고 있다는 것을 알고 있을 뿐입니다. 슬라이스의 다른 부분을 빌리는 것은 기본적으로 괜찮습니다. 두 슬라이스가 겹치지 않기 때문입니다. 하지만 러스트는 이것을 알만큼 똑똑하지 않습니다. 코드가 괜찮다는 것을 알 때, 러스트는 안전하지 않은 코드에 접근할 때입니다.

Miri는 안전하지 않은 코드를 작성할 때 잘못 될 수있는 모든 것을 포착하지 않습니다. Miri는 동적 분석 도구이므로 실제로 실행되는 코드의 문제 만 파악합니다. 즉, 작성한 안전하지 않은 코드에 대한 자신감을 높이기 위해 좋은 테스트 기술과 함께 사용해야합니다. Miri는 또한 코드가 소리가 나지 않을 수있는 모든 방법을 다루지 않습니다.

안전하지 않은 코드를 올바르게 사용

사용 unsafe 방금 논의 된 다섯 가지 초강대국 중 하나를 사용하는 것이 잘못되었거나 심지어 눈살을 찌푸리지는 않지만 얻는 것이 더 까다 롭습니다. unsafe 컴파일러가 메모리 안전을 유지할 수 없기 때문에 코드가 정확합니다. 사용할 이유가있을 때 unsafe 코드, 당신은 그렇게 할 수 있고, 명시적 unsafe 주석을 사용하면 문제가 발생할 때 문제의 원인을 쉽게 추적할 수 있습니다. 안전하지 않은 코드를 작성할 때마다 Miri를 사용하여 작성한 코드가 러스트의 규칙을 준수한다는 확신을 가질 수 있습니다.

안전하지 않은 러스트로 효과적으로 작업하는 방법에 대해 더 자세히 알아보려면, unsafe, 루스토노미콘은에 대한 러스트의 공식 가이드를 읽어보십시오.
