Lifetimes로 참조 검증

Lifetimes는 우리가 이미 사용해온 또 다른 종류의 제네릭입니다. 어떤 타입이 우리가 원하는 행동을 하도록 보장하는 대신, lifetimes는 우리가 필요로 하는 한 참조가 유효한지 확인합니다.

4장의 “추천 과 차용” 섹션에서 논의하지 않은 한 가지 세부 사항은 러스트의 모든 참조에는 평생이 있다는 것입니다. 이는 해당 참조가 유효한 범위입니다. 대부분의 경우, 라이프타임은 암시적이며 추론되며, 대부분의 경우와 마찬가지로 타입은 유추됩니다. 우리는 여러 타입이 가능할 때만 타입에 주석을 달도록 요구받습니다. 비슷한 방식으로, 우리는 라이프타임에 대해 다른 라이프타임을 요구할 수 있습니다.

수명에 주석을 다는 것은 대부분의 다른 프로그래밍 언어들이 가지고 있는 개념조차 아니기 때문에, 익숙하지 않을 것입니다. 이 장에서는 수명에 대해 완전히 다루지는 않겠지만, 평생 문법을 접할 수 있는 일반적인 방법에 대해 논의하여 이 개념에 익숙해질 수 있도록 할 것입니다.

평생 주석 문법

평생 주석은 참조가 얼마나 오래 지속되는지 변경하지 않습니다. 오히려, 그들은 수명에 영향을 미치지 않고 서로에 대한 여러 참조의 수명 간의 관계를 설명합니다. 서명이 일반 유형 매개 변수를 지정할 때 함수가 모든 유형을 수락하는 것처럼, 함수는 일반 수명 매개 변수를 지정하여 평생 참조를 수락 할 수 있습니다.

평생 주석에는 약간 특이한 구문이 있습니다. 평생 매개 변수의 이름은 아포스트로피 (')로 시작해야하며 일반적으로 일반 유형과 같이 소문자와 매우 짧습니다. 대부분의 사람들은 첫 번째 평생 주석에 'a 이름을 사용합니다. 우리는 참조 유형과 주석을 분리하기 위해 공간을 사용하여 참조의 & 다음에 평생 매개 변수 주석을 배치합니다.

다음은 몇 가지 예입니다.Here are some examples. i32 평생 매개 변수가 없는 경우 참조 i32 이름있는 평생 매개 변수를 가지고 있습니다 'a상기 가변 참조는, A mutable reference, i32 이 또한 일생일대의 'a:

&i32        // a reference
&'a i32     // a reference with an explicit lifetime
&'a mut i32 // a mutable reference with an explicit lifetime

하나의 평생 주석은 그 자체로 의미가 없습니다. 왜냐하면 주석은 여러 참조의 일반적인 평생 매개 변수가 서로 어떻게 관련되어 있는지 러스트에게 알려주기 때문입니다. 평생 주석이 longest 함수의 컨텍스트에서 서로 어떻게 관련되어 있는지 살펴 보겠습니다.

평생 Elision

모든 레퍼런스는 라이프타임이 있으며 레퍼런스를 사용하는 함수나 구조체에 대한 라이프타임 파라미터를 지정해야 한다는 것을 배웠습니다. 하지만, 우리는 Listing 4-9에서 라이프타임 주석 없이 컴파일된 라이프타임을 가진 Listing 10-25에 다시 나타난 함수를 가지고 있었습니다.

이 함수가 평생 주석 없이 컴파일되는 이유는 역사적입니다. 러스트의 초기 버전 (pre-1.0)에서는 모든 참조가 명시적인 평생을 필요로 하기 때문에 이 코드가 컴파일되지 않았을 것입니다. 그때, 함수 서명은 다음과 같이 작성되었을 것입니다:

많은 러스트 코드를 작성한 후 러스트 팀은 러스트 프로그래머가 특정 상황에서 동일한 평생 주석을 반복해서 입력하고 있음을 발견했습니다. 이러한 상황은 예측할 수 있었고 몇 가지 결정론적 패턴을 따랐습니다. 개발자는 이러한 패턴을 컴파일러의 코드에 프로그래밍하여 차용 검사기가 이러한 상황에서 수명을 추론 할 수 있고 명시적인 주석이 필요하지 않도록했습니다.

라이프타임이 있는 구조체에 메소드를 구현할 때, 우리는 Listing 10-11과 같이 제네릭 타입 파라미터와 같은 문법을 사용합니다. 라이프타임 파라미터를 선언하고 사용하는 것은 구조체 필드나 메소드 파라미터 및 반환 값과 관련이 있는지에 달려 있습니다.

struct 필드의 평생 이름은 항상 impl 키워드 뒤에 선언한 다음 struct의 이름 뒤에 사용해야 합니다.

impl 블록 내의 메소드 서명에서, 참조는 struct의 필드에서 참조의 수명과 연관되거나 독립적일 수 있습니다. 또한, 수명 제거 규칙은 종종 메소드 서명에서 수명 주석이 필요하지 않도록 만듭니다. Listing 10-24에서 정의한 ImportantExcerpt라는 구조체를 사용하여 몇 가지 예제를 살펴 보겠습니다.

먼저, level라는 메서드를 사용할 것입니다. self에 대한 참조가 유일한 매개 변수이고 반환 값이 i32이며 아무 것도 참조하지 않습니다.

struct ImportantExcerpt<'a> {
    part: &'a str,
}

impl<'a> ImportantExcerpt<'a> {
    fn level(&self) -> i32 {
        3
    }
}

impl<'a> ImportantExcerpt<'a> {
    fn announce_and_return_part(&self, announcement: &str) -> &str {
        println!("Attention please: {announcement}");
        self.part
    }
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().unwrap();
    let i = ImportantExcerpt {
        part: first_sentence,
    };
}
