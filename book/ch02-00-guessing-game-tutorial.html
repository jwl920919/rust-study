The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

추측 게임 프로그래밍하기

함께 손으로 직접 프로젝트를 진행하면서 Rust에 바로 입문해 보겠습니다! 이 장에서는 실제 프로그램에서 Rust의 몇 가지 일반적인 개념을 사용하는 방법을 보여줌으로써 여러분에게 소개합니다. let, match, 메서드, 연관 함수, 외부 크레이트 등에 대해 배우게 될 것입니다! 다음 장에서는 이러한 개념을 더 자세히 살펴보겠습니다. 이 장에서는 기본 사항을 연습하는 데 집중합니다.

고전적인 초보자 프로그래밍 문제인 추측 게임을 구현해 보겠습니다. 작동 방식은 다음과 같습니다. 프로그램은 1부터 100 사이의 임의의 정수를 생성합니다. 그런 다음 플레이어에게 추측 값을 입력하도록 요청합니다. 추측 값이 입력되면, 프로그램은 해당 값이 너무 낮거나 너무 높은지 알려줍니다. 추측 값이 정답이면, 게임은 축하 메시지를 출력하고 종료됩니다.

새 프로젝트 설정하기

새 프로젝트를 설정하려면 1장에서 만든 프로젝트 디렉토리로 이동하여 다음과 같이 Cargo를 사용해 새 프로젝트를 생성합니다.

$ cargo new guessing_game
$ cd guessing_game

첫 번째 명령인 cargo new는 프로젝트 이름(guessing_game)을 첫 번째 인수로 받습니다. 두 번째 명령은 새 프로젝트의 디렉토리로 이동합니다.

생성된 Cargo.toml 파일을 살펴보겠습니다.

파일명: Cargo.toml

[package]
name = "guessing_game"
version = "0.1.0"

[dependencies]

파일 이름: src/main.rs

fn main() {

}

이제 cargo run 명령을 사용하여 이 “Hello, world!” 프로그램을 컴파일하고 실행해 보겠습니다.

추측 처리하기

추측 게임 프로그램의 첫 번째 부분은 사용자 입력을 요청하고, 해당 입력을 처리하며, 입력이 예상된 형식인지 확인합니다. 시작하기 위해, 플레이어가 추측을 입력할 수 있도록 Listing 2-1의 코드를 src/main.rs에 입력해 보세요.

이 코드에는 많은 정보가 포함되어 있으므로 한 줄씩 살펴보겠습니다. 사용자 입력을 받아 결과를 출력하려면 io 입력/출력 라이브러리를 스코프에 포함해야 합니다. io 라이브러리는 std로 알려진 표준 라이브러리에 포함되어 있습니다.

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

기본적으로 Rust는 표준 라이브러리에 정의된 항목 집합을 모든 프로그램의 스코프에 포함합니다. 이 집합을 프렐류드(prelude)라고 하며, 표준 라이브러리 문서에서 해당 항목을 모두 확인할 수 있습니다.

사용하려는 타입이 프렐류드에 없는 경우, use 문을 사용하여 해당 타입을 명시적으로 스코프에 포함해야 합니다. std::io 라이브러리를 사용하면 사용자 입력을 받는 기능을 포함하여 여러 가지 유용한 기능을 사용할 수 있습니다.

1장에서 보았듯이, main 함수는 프로그램의 진입점입니다:

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

fn 구문은 새로운 함수를 선언합니다. 괄호 ()는 매개변수가 없음을 나타내며, 중괄호 {는 함수 본문의 시작을 나타냅니다.

1장에서 배웠듯이, println!는 화면에 문자열을 출력하는 매크로입니다:

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

이 코드는 게임이 무엇인지 설명하는 프롬프트를 출력하고 사용자에게 입력을 요청합니다.

변수로 값 저장

다음으로, 다음과 같이 사용자 입력을 저장할 변수를 만듭니다.

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

이제 프로그램이 흥미로워지고 있습니다! 이 한 줄에 많은 내용이 담겨 있습니다. let 문을 사용하여 변수를 생성합니다. 다른 예시를 하나 더 살펴보겠습니다.

let apples = 5;

이 라인은 새로운 변수를 만듭니다. apples 그리고 그것을 가치에 묶는다. 5. 러스트에서, 변수는 기본적으로 불변입니다. 즉, 변수에 값을 부여하면, 그 값은 변하지 않습니다. 우리는 이 개념에 대해 자세히 논의할 것입니다. “변수 와 돌연변이” 무시 3 장의 섹션. 가변 가변을 만들기 위해, 우리는 추가 mut 변수 이름 앞에:

let apples = 5; // immutable
let mut bananas = 5; // mutable

참고: // 구문은 줄의 끝까지 이어지는 주석을 시작합니다. Rust는 주석 안의 모든 내용을 무시합니다. 주석에 대해서는 3장에서 더 자세히 다룹니다.

추측 게임 프로그램으로 돌아가면, 당신은 이제 let mut guess 변수 이름 바꾸기 guess. 등호 (=)는 러스트에게 변수에 무언가를 바인드하고 싶다고 말합니다. 등호의 오른쪽에는 다음과 같은 값이 있습니다. guess ⁇ 은 ⁇ 이며, ⁇ 은 ⁇ 의 ⁇ 이다. String::new새 인스턴스를 반환하는 함수입니다.A function returns a new instance. String. String 무시 텍스트의 growable, UTF-8로 인코딩된 비트인 표준 라이브러리에서 제공하는 문자열 유형입니다.

::의 ::new 줄에 있는 new 구문은 String가 String 타입의 연관 함수임을 나타냅니다. 연관 함수는 특정 타입에 구현된 함수를 의미하며, 여기서는 String 타입에 구현되어 있습니다. 이 new 함수는 새로운 빈 문자열을 생성합니다. 어떤 종류의 새로운 값을 만드는 함수에 new라는 이름을 붙이는 것이 일반적이기 때문에, 많은 타입에서 이 함수를 찾을 수 있습니다.

전체적으로 let mut guess = String::new(); 줄은 현재 String의 새롭고 빈 인스턴스에 바인딩된 가변 변수를 생성했습니다.

사용자 입력 받기

프로그램의 첫 번째 줄에 use std::io;을 사용하여 표준 라이브러리의 입력/출력 기능을 포함시켰음을 기억하십시오. 이제 io 모듈의 stdin 함수를 호출하여 사용자 입력을 처리하겠습니다: io

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

프로그램 시작 부분에 io을 사용하여 use std::io; 모듈을 가져오지 않았다면, 이 함수 호출을 std::io::stdin로 작성하여 여전히 해당 함수를 사용할 수 있습니다. stdin 함수는 std::io::Stdin 인스턴스를 반환합니다. 이 타입은 터미널의 표준 입력에 대한 핸들을 나타냅니다.

다음으로, .read_line(&mut guess) 줄은 표준 입력 핸들의 read_line 메서드를 호출하여 사용자로부터 입력을 받습니다. 또한 &mut guess를 read_line의 인수로 전달하여 사용자 입력을 저장할 문자열을 지정합니다. read_line의 역할은 사용자가 표준 입력으로 입력한 내용을 기존 문자열의 내용을 덮어쓰지 않고 뒤에 추가하는 것입니다. 따라서 해당 문자열을 인수로 전달합니다. 이 문자열 인수는 메서드가 문자열 내용을 변경할 수 있도록 변경 가능해야 합니다.

&은 이 인수가 참조임을 나타냅니다. 참조를 사용하면 데이터를 메모리에 여러 번 복사하지 않고도 코드의 여러 부분이 같은 데이터에 접근할 수 있습니다. 참조는 복잡한 기능이지만, 참조를 안전하고 쉽게 사용할 수 있다는 점은 Rust의 큰 장점입니다. 이 프로그램을 완성하기 위해 세부 사항을 모두 알 필요는 없습니다. 지금은 변수와 마찬가지로 참조도 기본적으로 불변이라는 점만 기억하세요. 값을 변경할 수 있게 하려면 &mut guess 대신 &guess라고 써야 합니다. (참조는 4장에서 자세히 설명합니다.)

잠재적 실패를 Result로 처리하기 Result

아직 이 코드 줄을 작업하고 있습니다. 이제 세 번째 텍스트 줄을 다루고 있지만, 이는 여전히 단일 논리적 코드 줄의 일부라는 점에 유의하십시오. 다음 부분은 이 메서드입니다:

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

이 코드를 다음과 같이 작성할 수도 있습니다:

io::stdin().read_line(&mut guess).expect("Failed to read line");

그러나 한 줄이 너무 길면 읽기 어렵기 때문에 나누는 것이 좋습니다. .method_name() 구문을 사용하여 메서드를 호출할 때 긴 줄을 끊기 위해 줄바꿈과 다른 공백을 도입하는 것이 종종 현명합니다. 이제 이 줄이 하는 일을 논의해 보겠습니다.

앞에서 언급했듯이 read_line는 사용자가 입력하는 모든 문자열을 입력하지만 Result 값도 반환합니다. Result는 종종 enum이라고하는 열거이며 여러 가지 가능한 상태 중 하나에있을 수있는 유형입니다. 우리는 각 가능한 상태를 변형이라고 부릅니다.

6장에서는 열거형을 더 자세히 다룹니다. 이러한 Result 유형의 목적은 오류 처리 정보를 인코딩하는 것입니다.

Result의 변형은 Ok과 Err입니다. Ok 변형은 작업이 성공했음을 나타내며, 성공적으로 생성된 값을 포함합니다. Err 변형은 작업이 실패했음을 의미하며, 작업이 어떻게 또는 왜 실패했는지에 대한 정보를 포함합니다.

Result 타입의 값은 다른 모든 타입의 값과 마찬가지로 메서드가 정의되어 있습니다. Result의 인스턴스에는 호출할 수 있는 expect 메서드가 있습니다. 이 Result 인스턴스가 Err 값인 경우, expect은 프로그램이 충돌하도록 하고 expect에 인수로 전달한 메시지를 표시합니다. read_line 메서드가 Err을 반환하는 경우, 이는 일반적으로 기반 운영체제에서 발생한 오류의 결과일 것입니다. 이 Result 인스턴스가 Ok 값인 경우, expect은 Ok이 가지고 있는 반환 값을 가져와서 해당 값만 반환하므로 이를 사용할 수 있습니다. 이 경우, 해당 값은 사용자의 입력 바이트 수입니다.

expect를 호출하지 않으면 프로그램은 컴파일되지만 경고가 표시됩니다.

경고를 억제하는 올바른 방법은 실제로 오류 처리 코드를 작성하는 것입니다. 하지만 이 경우 문제가 발생하면 프로그램을 중단시키면 되므로 expect를 사용할 수 있습니다. 제9장에서 오류 복구 방법에 대해 배울 것입니다.

와 인쇄 값 println! 위치 지정자

마지막 중괄호를 제외하면, 지금까지 작성한 코드에서 논의할 줄이 하나 더 있습니다:

use std::io;

fn main() {
    println!("Guess the number!");

    println!("Please input your guess.");

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    println!("You guessed: {guess}");
}

이 줄은 이제 사용자의 입력을 포함하는 문자열을 출력합니다. {} 중괄호는 자리 표시자입니다. {} 중괄호를 값의 위치를 잡아주는 작은 집게발처럼 생각할 수 있습니다. 변수의 값을 출력할 때는 변수 이름을 중괄호 안에 넣을 수 있습니다. 식을 평가한 결과를 출력할 때는 형식 문자열에 빈 중괄호를 넣고, 형식 문자열 뒤에 쉼표로 구분된 식 목록을 나열합니다. 이때 각 식은 빈 중괄호 자리 표시자의 순서대로 출력됩니다. 한 번의 println! 호출로 변수와 식의 결과를 함께 출력하는 예는 다음과 같습니다: println!

#![allow(unused)]
fn main() {
let x = 5;
let y = 10;

println!("x = {x} and y + 2 = {}", y + 2);
}

이 코드는 x = 5 and y + 2 = 12를 출력합니다.

비밀 번호 생성

다음으로, 사용자가 추측할 비밀 번호를 생성해야 합니다. 게임을 여러 번 재미있게 플레이할 수 있도록 비밀 번호는 매번 달라야 합니다. 게임이 너무 어렵지 않도록 1에서 100 사이의 난수를 사용하겠습니다. Rust는 아직 표준 라이브러리에 난수 기능을 포함하지 않습니다. 하지만 Rust 팀은 해당 기능을 제공하는 rand 크레이트를 제공합니다.

크레이트를 활용한 기능 확장

크레이트는 Rust 소스 코드 파일들의 모음입니다. 우리가 만들어 온 프로젝트는 실행 파일인 바이너리 크레이트입니다. rand 크레이트는 라이브러리 크레이트로, 다른 프로그램에서 사용되도록 작성된 코드를 포함하며 단독으로 실행할 수 없습니다.

Cargo가 외부 크레이트를 조정하는 부분은 Cargo의 진정한 강점입니다. rand를 사용하는 코드를 작성하기 전에, Cargo.toml 파일을 수정하여 rand 크레이트를 의존성으로 포함해야 합니다. 지금 해당 파일을 열고, Cargo가 만들어 놓은 [dependencies] 섹션 헤더 아래에 다음 줄을 추가하세요. 반드시 여기와 동일하게 [dependencies]와 이 버전 번호를 지정해야 합니다. 그렇지 않으면 이 튜토리얼의 코드 예제가 작동하지 않을 수 있습니다: rand

파일명: Cargo.toml

[dependencies]
rand = "0.10.1"

다음에서 카고.toml file, 헤더를 따르는 모든 것은 다른 섹션이 시작될 때까지 계속되는 해당 섹션의 일부입니다. [dependencies], 당신은 당신의 프로젝트가에 달려있는 외부 크레이트와 당신이 요구하는 그 크레이트의 버전을 화물에게 말한다. 이 경우에, 우리는 rand 시맨틱 버전 지정자를 가진 크레이트 0.10.1. 화물은 이해합니다 시맨틱 버전 무시 (가끔 전화) SemVer에서), 이는 버전 번호를 작성하는 표준입니다. 0.10.1 사실 짧게는 ^0.10.1즉, 최소 0.10.1이지만 0.11.0 미만인 모든 버전을 의미합니다.

Cargo는 이러한 버전들이 0.10.1 버전과 호환되는 공개 API를 가진다고 간주합니다. 이 지정자는 이 장의 코드로 컴파일되는 최신 패치 릴리스를 받을 수 있도록 보장합니다. 0.11.0 이상의 버전은 다음 예제에서 사용하는 것과 동일한 API를 제공한다고 보장되지 않습니다.

이제 코드를 변경하지 않은 상태에서 Listing 2-2와 같이 프로젝트를 빌드해 보겠습니다.

SemVer 덕분에 모든 버전이 코드와 호환되므로, 다른 버전 번호를 볼 수 있습니다. 운영 체제에 따라 출력되는 줄이 다를 수 있으며, 줄의 순서도 다를 수 있습니다.

외부 종속성을 포함하면 Cargo는 한국어 (ko)의 데이터 복사본인 레지스트리에서 종속성이 필요로 하는 모든 최신 버전을 가져옵니다. 크레이트.io는 러스트 생태계의 사람들이 다른 사람들이 사용할 수 있도록 오픈 소스 러스트 프로젝트를 게시하는 곳입니다.

레지스트리를 업데이트한 후, Cargo는 [dependencies] 섹션을 확인하고 아직 다운로드되지 않은 크레이트를 다운로드합니다. 이 경우 우리는 종속성으로 rand만 나열했지만, Cargo는 rand가 동작하는 데 의존하는 다른 크레이트도 함께 가져왔습니다. 크레이트 다운로드가 완료되면 Rust는 이들을 컴파일한 다음, 사용 가능한 종속성을 포함하여 프로젝트를 컴파일합니다.

cargo build를 변경하지 않고 즉시 Finished을 실행하면 Finished 라인을 제외하고는 아무 출력도 표시되지 않습니다. Cargo는 이미 종속성을 다운로드하고 컴파일한 상태이며, Cargo.toml 파일에서 해당 종속성에 대해 아무것도 변경하지 않았다는 것을 알고 있습니다. 또한 코드에도 변경 사항이 없으므로 이를 다시 컴파일하지 않습니다. 할 일이 없으므로 단순히 종료합니다.

src/main.rs 파일을 열고 사소한 변경을 한 뒤 저장하고 다시 빌드하면, 두 줄의 출력만 표시됩니다.

$ cargo build
   Compiling guessing_game v0.1.0 (file:///projects/guessing_game)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.13s

이 출력은 Cargo가 src/main.rs 파일의 사소한 변경 사항만 반영하여 빌드를 업데이트했음을 보여줍니다. 종속성이 변경되지 않았으므로, Cargo는 이미 다운로드하고 컴파일한 종속성을 재사용할 수 있음을 알고 있습니다.

재현 가능한 빌드 보장

Cargo는 여러분이나 다른 사람이 코드를 빌드할 때마다 동일한 아티팩트를 다시 만들 수 있도록 보장하는 메커니즘을 제공합니다. Cargo는 여러분이 달리 지시할 때까지 지정한 종속성의 버전만 사용합니다. 예를 들어, 다음 주에 rand 크레이트의 0.10.2 버전이 출시된다고 가정해 보겠습니다. 이 버전에는 중요한 버그 수정이 포함되어 있지만, 여러분의 코드를 깨뜨릴 수 있는 회귀 문제도 포함되어 있습니다. 이러한 문제를 방지하기 위해 Rust는 cargo build를 처음 실행할 때 cargo build 파일을 생성합니다. 따라서 이제 guessing_game 디렉토리에 이 파일이 존재합니다.

프로젝트를 처음 빌드할 때, Cargo는 기준에 맞는 종속성 버전들을 모두 파악한 다음 Cargo.lock 파일에 기록합니다. 이후 프로젝트를 빌드할 때, Cargo는 Cargo.lock 파일이 존재하는 것을 확인하고 버전 파악 작업을 다시 수행하는 대신 해당 파일에 지정된 버전을 사용합니다. 이를 통해 자동으로 재현 가능한 빌드를 할 수 있습니다. 즉, Cargo.lock 파일 덕분에 명시적으로 업그레이드할 때까지 프로젝트는 0.10.1 버전을 유지합니다. 재현 가능한 빌드에 중요한 역할을 하는 Cargo.lock 파일은 프로젝트의 나머지 코드와 함께 소스 제어에 커밋하는 것이 일반적입니다.

크레이트를 업데이트하여 새 버전 가져오기

크레이트를 업데이트하고 싶다면 Cargo의 update 명령을 사용할 수 있습니다. 이 명령은 Cargo.lock을 무시하고 Cargo.toml의 요구 조건에 맞는 최신 버전을 찾은 뒤, 해당 버전을 Cargo.lock에 기록합니다. 기본적으로 Cargo는 지정한 버전 요구 조건에 맞는 범위 안에서만 업데이트합니다. 예를 들어 rand 크레이트에 새 버전 0.10.2와 0.999.0이 올라왔다면, cargo update를 실행한 결과는 다음과 같습니다:

$ cargo update
    Updating crates.io index
     Locking 1 package to latest Rust 1.96.0 compatible version
    Updating rand v0.10.1 -> v0.10.2 (available: v0.999.0)

Cargo는 0.999.0 릴리스를 무시합니다. 이 시점에서 Cargo.lock 파일이 변경되었음을 확인할 수 있으며, 현재 사용하고 있는 randrandrand 크레이트의 버전이 0.10.2임을 명시하고 있습니다. 0.999.0 버전 또는 0.999.x 시리즈의 어떤 버전을 사용하려면, Cargo.toml 파일을 다음과 같이 수정해야 합니다(다음 예제는 0.10을 사용한다고 가정하므로 실제로 이 변경을 하지 마세요): rand

[dependencies]
rand = "0.999.0"

다음에 cargo build를 실행하면, Cargo는 사용 가능한 크레이트 레지스트리를 업데이트하고 지정된 새 버전에 따라 rand 요구 사항을 재평가합니다.

화물와 우리의 Ecosystem에 대해서는 14 장에서 논의 할 것이지만 지금은 알아야 할 것이 전부입니다.화물을 사용하면 라이브러리를 재사용하기가 매우 쉬워서 러스트aceans는 여러 패키지에서 조립 된 작은 프로젝트를 작성할 수 있습니다.

난수 생성

rand를 사용하여 추측할 숫자를 생성해 보겠습니다. 다음 단계는 Listing 2-3과 같이 src/main.rs를 업데이트하는 것입니다.

먼저 use rand::prelude::*; 라인을 추가합니다. prelude 모듈에는 rand 크레이트에서 가장 자주 사용하는 항목들이 포함되어 있으며, use을 사용하면 이러한 항목을 프로그램의 스코프에서 사용할 수 있습니다.

다음으로, 중간에 두 줄을 추가합니다. 첫 번째 줄에서는 사용할 특정 난수 생성기를 반환하는 rand::rng 함수를 호출합니다. 이 난수 생성기는 현재 실행 스레드에 로컬로 존재하며 운영체제에 의해 시드됩니다. 그런 다음 난수 생성기에서 random_range 메서드를 호출합니다. 이 메서드는 RngExt 트레이트에 의해 정의되며, rand::prelude 모듈의 일부입니다. use rand::prelude::*; 문장을 통해 이 모듈을 스코프에 가져왔습니다. random_range 메서드는 범위 표현식을 인수로 받아 해당 범위 내에서 난수를 생성합니다. 여기서 사용하는 범위 표현식은 start..=end 형태를 가지며 하한과 상한을 모두 포함하므로, 1부터 100 사이의 숫자를 요청하려면 1..=100을 지정해야 합니다.

추측한 값과 비밀 번호 비교

이제 사용자 입력과 난수가 있으므로 비교할 수 있습니다. 이 단계는 Listing 2-4에 나와 있습니다. 나중에 설명하겠지만, 이 코드는 아직 컴파일되지 않습니다.

먼저, 표준 라이브러리에서 use이라는 타입을 스코프에 가져오는 또 다른 std::cmp::Ordering 구문을 추가합니다. Ordering 타입은 또 다른 열거형(enum)이며, Less, Greater, Equal라는 변형(variant)을 가집니다. 이 세 가지는 두 값을 비교할 때 나올 수 있는 세 가지 결과입니다.

다음으로, Ordering 타입을 사용하는 다섯 줄의 코드를 하단에 추가합니다. cmp 메서드는 두 값을 비교하며, 비교할 수 있는 모든 객체에서 호출할 수 있습니다. 이 메서드는 비교 대상에 대한 참조를 인자로 받습니다. 여기서는 guess와 secret_number를 비교합니다. 그런 다음, Ordering 열거형의 변형을 반환합니다. 이 열거형은 앞서 use 구문으로 스코프에 가져온 것입니다. match 표현식을 사용하여, Ordering 호출에서 반환된 cmp 변형에 따라 다음에 수행할 작업을 결정합니다. 이때 비교되는 값은 guess과 secret_number입니다.

match 표현식은 팔(arm)로 구성됩니다. 각 팔은 매칭할 패턴과, match에 주어진 값이 해당 팔의 패턴에 일치할 경우 실행되어야 하는 코드로 이루어집니다. Rust는 match에 주어진 값을 받아 각 팔의 패턴을 차례대로 확인합니다. 패턴과 match 구조는 Rust의 강력한 기능으로, 코드가 마주할 수 있는 다양한 상황을 표현하고 모든 상황을 처리하도록 보장합니다. 이 기능들은 각각 6장과 19장에서 자세히 다룹니다.

여기서 사용하는 match 표현식을 예로 들어 보겠습니다. 사용자가 50을 추측했고, 이번 무작위로 생성된 비밀 번호가 38이라고 가정해 보겠습니다.

코드가 50과 38을 비교할 때, cmp 메서드는 50이 38보다 크기 때문에 Ordering::Greater을 반환합니다. match 식은 Ordering::Greater 값을 받아서 각 팔(arm)의 패턴을 검사하기 시작합니다. 첫 번째 팔의 패턴인 Ordering::Less을 확인한 결과, Ordering::Greater 값은 Ordering::Less과 일치하지 않으므로 해당 팔의 코드를 무시하고 다음 팔로 이동합니다. 다음 팔의 패턴은 Ordering::Greater이며, 이는 Ordering::Greater과 일치합니다! 해당 팔의 코드가 실행되어 Too big!이 화면에 출력됩니다. match 식은 첫 번째 성공적인 일치 이후에 종료되므로, 이 시나리오에서는 마지막 팔을 확인하지 않습니다.

오류의 핵심은 타입이 일치하지 않는다는 것입니다. Rust는 강력하고 정적인 타입 시스템을 갖추고 있습니다. 하지만 타입 추론 기능도 제공합니다. let mut guess = String::new()를 작성했을 때, Rust는 guess이 String이어야 한다고 추론하여 타입을 명시적으로 작성하지 않아도 되었습니다. 반면에 secret_number은 숫자 타입입니다. Rust의 숫자 타입 중에는 1에서 100 사이의 값을 가질 수 있는 것이 몇 가지 있습니다. i32인 32비트 숫자, u32인 부호 없는 32비트 숫자, i64인 64비트 숫자 등이 있습니다. 별도로 지정하지 않는 한, Rust는 기본적으로 i32를 사용합니다. 이는 다른 곳에서 타입 정보를 추가하여 Rust가 다른 숫자 타입을 추론하도록 하지 않는 한, secret_number의 타입이기도 합니다. 이 오류가 발생하는 이유는 Rust가 문자열과 숫자 타입을 비교할 수 없기 때문입니다.

궁극적으로, 프로그램이 입력으로 읽는 String 문자열을 숫자 유형으로 변환하여 비밀 번호와 수치적으로 비교할 수 있도록 해야 합니다. 이를 위해 main 함수 본문에 다음 줄을 추가합니다.

파일 이름: src/main.rs

use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    println!("The secret number is: {secret_number}");

    println!("Please input your guess.");

    // --snip--

    let mut guess = String::new();

    io::stdin()
        .read_line(&mut guess)
        .expect("Failed to read line");

    let guess: u32 = guess.trim().parse().expect("Please type a number!");

    println!("You guessed: {guess}");

    match guess.cmp(&secret_number) {
        Ordering::Less => println!("Too small!"),
        Ordering::Greater => println!("Too big!"),
        Ordering::Equal => println!("You win!"),
    }
}

해당 줄은 다음과 같습니다:

let guess: u32 = guess.trim().parse().expect("Please type a number!");

guess이라는 이름의 변수를 만듭니다. 하지만 잠깐, 프로그램에 이미 guess이라는 이름의 변수가 있지 않나요? 실제로 그렇지만, Rust는 친절하게도 guess의 이전 값을 새로운 값으로 가려서 사용할 수 있게 해줍니다. 섀도잉을 사용하면 guess라는 변수 이름을 다시 사용할 수 있으므로, guess_str과 guess처럼 두 개의 고유한 변수를 만들어야 하는 불편함이 없습니다. 이 주제는 제 3 장에서 더 자세히 다루겠지만, 지금은 이 기능이 한 타입의 값을 다른 타입으로 변환할 때 자주 사용된다는 점만 알아두면 됩니다.

이 새로운 변수를 식 guess.trim().parse()에 바인딩합니다. 식 안의 guess은 입력을 문자열로 포함하고 있는 원래의 guess 변수를 가리킵니다. trim 메서드는 String 인스턴스에서 시작과 끝의 공백을 제거합니다. 이는 문자열을 숫자 데이터만 포함할 수 있는 u32로 변환하기 전에 수행해야 하는 작업입니다. 사용자는 enter 키를 눌러 read_line을 만족시키고 추측 값을 입력해야 하며, 이 과정에서 문자열에 줄바꿈 문자가 추가됩니다. 예를 들어, 사용자가 5를 입력하고 enter 키를 누르면, guess은 다음과 같이 보입니다: 5\n. 여기서 \n은 “줄바꿈”을 나타냅니다. (Windows에서는 enter 키를 누르면 캐리지 리턴과 줄바꿈, 즉 \r\n이 생성됩니다.) trim 메서드는 \n 또는 \r\n을 제거하여 결과적으로 단순히 5만 남게 합니다.

문자열의 parse 메서드는 문자열을 다른 타입으로 변환합니다. 여기서는 문자열을 숫자로 변환하는 데 사용합니다. 원하는 숫자 타입을 정확히 지정하려면 let guess: u32처럼 작성하면 됩니다. 변수 이름 guess 뒤에 :를 붙이면 변수의 타입을 명시한다는 뜻입니다. Rust에는 몇 가지 내장 숫자 타입이 있습니다. 여기서 사용한 u32은 부호 없는 32비트 정수로, 작은 양수를 나타낼 때 적절한 기본 선택입니다. 다른 숫자 타입은 3장에서 살펴봅니다.

또한 이 예제 프로그램의 u32 주석과 secret_number과의 비교를 통해 Rust는 secret_number도 u32이어야 한다고 추론합니다. 따라서 이제 비교는 동일한 타입의 두 값 사이에서 이루어집니다!

parse 메서드는 숫자로 바꿀 수 있는 문자열에서만 동작하므로 오류가 발생할 수 있습니다. 예를 들어 문자열에 A👍%이 들어 있으면 숫자로 변환할 수 없습니다. 실패 가능성이 있으므로 parse 메서드는 Result 타입을 반환합니다. 이는 앞서 다룬 read_line 메서드의 반환값(“Result로 오류 가능성 처리하기”)과 비슷합니다. 여기서도 Result 값을 expect 메서드로 처리합니다. parse가 문자열을 숫자로 변환하지 못하면 Err Result 변형을 반환합니다. 이때 expect 호출은 게임을 중단시키고 지정한 메시지를 출력합니다. 반대로 parse가 변환에 성공하면 Ok Result 변형을 반환하고, expect은 Ok 값에서 원하는 숫자를 돌려줍니다.

루프를 사용한 여러 번의 추측 허용

loop 키워드는 무한 루프를 생성합니다. 사용자가 숫자를 추측할 수 있는 기회를 더 많이 제공하기 위해 루프를 추가하겠습니다.

올바른 추측 후 종료

사용자가 이겼을 때 게임을 종료하도록 break 문을 추가하여 프로그램을 수정해 보겠습니다:

파일 이름: src/main.rs

use std::cmp::Ordering;
use std::io;

use rand::prelude::*;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    println!("The secret number is: {secret_number}");

    loop {
        println!("Please input your guess.");

        let mut guess = String::new();

        io::stdin()
            .read_line(&mut guess)
            .expect("Failed to read line");

        let guess: u32 = guess.trim().parse().expect("Please type a number!");

        println!("You guessed: {guess}");

        // --snip--

        match guess.cmp(&secret_number) {
            Ordering::Less => println!("Too small!"),
            Ordering::Greater => println!("Too big!"),
            Ordering::Equal => {
                println!("You win!");
                break;
            }
        }
    }
}

사용자가 비밀 번호를 올바르게 추측했을 때 break 뒤에 You win! 라인을 추가하면 프로그램이 루프를 종료합니다. 루프가 main의 마지막 부분이므로, 루프를 종료하는 것은 곧 프로그램을 종료하는 것을 의미합니다.

잘못된 입력 처리

게임의 동작을 더 세밀하게 조정하기 위해, 사용자가 숫자가 아닌 값을 입력했을 때 프로그램이 충돌하지 않고 해당 값을 무시하도록 합시다. 그러면 사용자가 추측을 계속할 수 있습니다. Listing 2-5에 나와 있듯이, guess가 String에서 u32로 변환되는 라인을 수정하여 이를 구현할 수 있습니다.

expect 호출을 match 식으로 바꾸어, 오류 발생 시 프로그램이 충돌하는 대신 오류를 처리하도록 변경합니다. parse는 Result 타입을 반환하며, Result는 Ok와 Err 변형을 가진 열거형(enum)입니다. 여기서는 match 식을 사용하는데, 이는 Ordering 메서드의 cmp 결과를 처리할 때 사용한 방식과 같습니다.

parse가 문자열을 숫자로 성공적으로 변환할 수 있다면, 변환된 숫자를 포함하는 Ok 값을 반환합니다. 이 Ok 값은 첫 번째 팔(arm)의 패턴과 일치하며, match 식은 num이 생성하여 parse 값 안에 넣은 Ok 값을 그대로 반환합니다. 이 숫자는 우리가 생성하는 새로운 guess 변수에 저장됩니다.

parse이 not 문자열을 숫자로 변환할 수 없다면, 오류에 대한 더 많은 정보를 포함하는 Err 값을 반환합니다. Err 값은 첫 번째 match 팔의 Ok(num) 패턴과 일치하지 않지만, 두 번째 팔의 Err(_) 패턴과 일치합니다. 밑줄, _,은 모든 것을 포괄하는 값입니다. 이 예제에서는 내부에 어떤 정보가 있든 상관없이 모든 Err 값과 일치하기를 원한다고 말하는 것입니다. 따라서 프로그램은 두 번째 팔의 코드, continue,를 실행하여 loop의 다음 반복으로 이동하고 다른 추측을 요청합니다. 즉, 사실상 프로그램은 parse가 겪을 수 있는 모든 오류를 무시합니다!

요약

이 프로젝트는 let, match, 함수, 외부 크레이트 사용 등 다양한 새로운 Rust 개념을 직접 다루며 학습할 수 있는 좋은 기회였습니다. 다음 몇 장에서는 이러한 개념을 더 자세히 배웁니다. 3장에서는 변수, 데이터 타입, 함수와 같이 대부분의 프로그래밍 언어에 존재하는 개념을 다루고, Rust에서 이를 사용하는 방법을 보여줍니다. 4장에서는 Rust를 다른 언어와 차별화하는 특징인 소유권(ownership)을 탐구합니다. 5장에서는 구조체(struct)와 메서드 문법을 논의하고, 6장에서는 열거형(enum)의 작동 방식을 설명합니다.
