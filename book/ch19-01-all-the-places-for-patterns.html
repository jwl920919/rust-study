The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

패턴을 사용할 수 있는 모든 위치

Rust에서는 여러 곳에서 패턴을 사용할 수 있으며, 여러분은 깨닫지 못한 채로 이미 패턴을 많이 사용해 왔습니다! 이 섹션에서는 패턴이 유효한 모든 위치에 대해 설명합니다.

match 암(arm)

6장에서 논의한 바와 같이, match 표현식의 암(arm)에서 패턴을 사용합니다. 공식적으로 match 표현식은 match 키워드, 일치할 값, 그리고 패턴과 해당 패턴과 일치할 경우 실행할 표현식으로 구성된 하나 이상의 match 암으로 정의됩니다. 예를 들어 다음과 같습니다:

match VALUE {
    PATTERN => EXPRESSION,
    PATTERN => EXPRESSION,
    PATTERN => EXPRESSION,
}

예를 들어, Listing 6-5의 match 표현식은 변수 Option<i32>에 저장된 x 값과 일치합니다:

match x {
    None => None,
    Some(i) => Some(i + 1),
}

이 match 식에서 화살표 왼쪽에 있는 None과 Some(i)가 패턴입니다.

match 표현식에 대한 한 가지 요구 사항은 포괄적(exhaustive)이어야 한다는 것입니다. 즉, match 표현식의 값이 가질 수 있는 모든 가능성을 고려해야 합니다. 모든 가능성을 다루는 한 가지 방법은 마지막 암에 모든 값을 포괄하는 패턴을 사용하는 것입니다. 예를 들어, 어떤 값이든 일치하는 변수 이름은 결코 실패할 수 없으므로 나머지 모든 경우를 포함합니다.

특정 패턴 _은 어떤 값이든 일치하지만 변수에 바인딩하지 않으므로, 마지막 match 암에서 자주 사용됩니다. 예를 들어, 지정되지 않은 값을 무시하고 싶을 때 _ 패턴이 유용할 수 있습니다. 이 장 후반부의 “패턴에서 값 무시하기” 섹션에서 _ 패턴에 대해 자세히 다루겠습니다. 패턴에서 값 무시하기

let 성명

이 장에 이르기까지 우리는 match 및 if let에서 패턴을 사용하는 것에 대해 명시적으로 논의해 왔습니다. 하지만 실제로는 let 문과 같은 다른 곳에서도 패턴을 사용해 왔습니다. 예를 들어, let를 사용한 다음 간단한 변수 할당을 살펴보세요.

#![allow(unused)]
fn main() {
let x = 5;
}

이처럼 let 문을 사용할 때마다 우리는 패턴을 사용해 왔습니다. 다만, 그 사실을 인지하지 못했을 뿐입니다! 좀 더 공식적으로 표현하면, let 문은 다음과 같은 형태를 가집니다.

let PATTERN = EXPRESSION;

다음과 같은 문장에서 let x = 5; PATTERN 슬롯에 변수 이름이 있는 경우, 변수 이름은 패턴의 특히 단순한 형태입니다. 러스트는 이 표현식을 패턴과 비교하고 찾은 이름을 할당합니다. 따라서, let x = 5; 예를 들어, x 이 패턴은 "여기서 변수와 일치하는 것을 결합하십시오"를 의미합니다. x. 이름 때문에 x 이 패턴이 전체 패턴이라면, 이 패턴은 효과적으로 "모든 것을 변수에 바인딩"하는 것을 의미한다. x“가치가 무엇이든 간에.”

let의 패턴 매칭 측면을 더 명확하게 이해하려면, let 패턴을 사용하여 튜플을 구조 분해하는 Listing 19-1을 살펴보세요.

여기서는 튜플을 패턴과 대조합니다. Rust는 값 (1, 2, 3)과 패턴 (x, y, z)를 비교해 일치한다고 판단합니다. 두 튜플의 원소 개수가 같기 때문입니다. 이때 1은 x에, 2는 y에, 3은 z에 바인딩됩니다. 이 튜플 패턴은 개별 변수 패턴 세 개를 중첩한 것으로 볼 수 있습니다.

패턴의 요소 수가 튜플의 요소 수와 일치하지 않으면 전체 타입이 일치하지 않아 컴파일러 오류가 발생합니다. 예를 들어, Listing 19-2는 세 개의 요소를 가진 튜플을 두 개의 변수로 구조 분해하려는 시도를 보여주지만, 이는 작동하지 않습니다.

이 코드를 컴파일하면 다음과 같은 타입 오류가 발생합니다.

$ cargo run
   Compiling patterns v0.1.0 (file:///projects/patterns)
error[E0308]: mismatched types
 --> src/main.rs:2:9
  |
2 |     let (x, y) = (1, 2, 3);
  |         ^^^^^^   --------- this expression has type `({integer}, {integer}, {integer})`
  |         |
  |         expected a tuple with 3 elements, found one with 2 elements
  |
  = note: expected tuple `({integer}, {integer}, {integer})`
             found tuple `(_, _)`

For more information about this error, try `rustc --explain E0308`.
error: could not compile `patterns` (bin "patterns") due to 1 previous error

오류를 수정하려면 _ 또는 ..을 사용하여 튜플의 값 중 하나 이상을 무시할 수 있습니다. 이 방법은 패턴에서 값 무시하기 섹션에서 자세히 다루겠습니다. 만약 패턴에 변수가 너무 많아서 문제가 발생했다면, 변수의 수가 튜플의 요소 수와 같아지도록 변수를 제거하여 타입을 일치시키는 것이 해결책입니다.

조건부 if let 표현식

6장에서 if let 표현식은 주로 하나의 경우만 일치하는 match과 동등한 코드를 더 간결하게 작성하는 방법으로 사용한다고 설명했습니다. 선택적으로, if let에 else이 일치하지 않을 경우 실행할 코드를 포함하는 if let을 사용할 수도 있습니다.

목록 19-3은 if let, else if, 그리고 else if let 표현식을 혼합하여 사용할 수도 있음을 보여줍니다. 이렇게 하면 패턴과 비교할 수 있는 값이 하나만 있는 match 표현식보다 더 유연합니다. 또한, Rust는 if let, else if, 그리고 else if let 연쇄 구조의 각 조건이 서로 관련이 있어야 한다고 요구하지 않습니다.

목록 19-3의 코드는 여러 조건에 대한 일련의 검사를 기반으로 배경색을 결정합니다. 이 예제에서는 실제 프로그램이 사용자 입력으로 받을 수 있는 값을 하드코딩하여 변수를 생성했습니다.

사용자가 좋아하는 색상을 지정하면 해당 색상이 배경으로 사용됩니다. 좋아하는 색상을 지정하지 않았고 오늘이 화요일인 경우 배경 색상은 녹색입니다. 그렇지 않으면 사용자가 나이를 문자열로 지정했고 이를 숫자로 성공적으로 파싱할 수 있다면, 숫자의 값에 따라 색상이 보라색 또는 주황색이 됩니다. 이 조건들 중 어느 것도 해당하지 않으면 배경 색상은 파란색입니다.

이 조건부 구조를 사용하면 복잡한 요구 사항을 지원할 수 있습니다. 여기에서 하드코딩된 값을 사용하면 이 예제는 Using purple as the background color를 출력합니다.

if let 문법도 match 문법처럼 기존 변수를 가리는 새로운 변수를 도입할 수 있습니다. if let Ok(age) = age 줄은 age 변형 안에 포함된 값을 가진 새로운 Ok 변수를 도입하여, 기존에 있던 age 변수를 가립니다. 따라서 if age > 30 조건은 해당 블록 내부에 배치해야 합니다. 이 두 조건을 if let Ok(age) = age && age > 30 형태로 결합할 수 없습니다. 30과 비교하려는 새로운 age 변수는 중괄호로 시작하는 새로운 스코프가 시작될 때까지 유효하지 않기 때문입니다.

if let 표현식을 사용하는 단점은 컴파일러가 완전성을 검사하지 않는다는 점입니다. 반면 match 표현식의 경우 완전성을 검사합니다. 마지막 else 블록을 생략하여 일부 경우를 처리하지 못했다면, 컴파일러는 잠재적인 논리 버그에 대해 우리에게 경고하지 않을 것입니다.

for 루프에서 키워드 for 바로 뒤에 오는 값은 패턴입니다. 예를 들어, for x in y에서 x가 패턴입니다. Listing 19-5에서는 for 루프에서 패턴을 사용하여 for 루프의 일부로 튜플을 구조 분해(destructure)하거나 분리하는 방법을 보여 줍니다.
