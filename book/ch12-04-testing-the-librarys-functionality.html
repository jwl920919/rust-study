The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

Test-Driven 개발을 통한 기능 추가

이제 src/lib.rs의 검색 로직을 main 함수와 분리했기 때문에 코드의 핵심 기능에 대한 테스트를 작성하는 것이 훨씬 쉬워졌습니다. 다양한 인수로 직접 함수를 호출하고 명령줄에서 바이너리를 호출하지 않고도 반환 값을 확인할 수 있습니다.

이 섹션에서는 다음 단계와 함께 테스트 중심 개발(TDD) 프로세스를 사용하여 minigrep 프로그램에 검색 로직을 추가합니다.

  1. 실패하는 테스트를 작성하고 예상한 이유로 실패했는지 확인합니다.
  2. 새 테스트 패스를 만들기에 충분한 코드를 작성하거나 수정합니다.
  3. 방금 추가하거나 변경한 코드를 리팩토링하고 테스트가 계속 통과되는지 확인합니다.
  4. 1 단계에서 반복하십시오!

소프트웨어를 작성하는 여러 가지 방법 중 하나 일 뿐이지만 TDD는 코드 설계를 유도하는 데 도움이 될 수 있습니다. 테스트 패스를 만드는 코드를 작성하기 전에 테스트를 작성하면 프로세스 전반에 걸쳐 높은 테스트 범위를 유지하는 데 도움이됩니다.

우리는 실제로 파일 내용에서 쿼리 문자열을 검색하는 기능을 테스트하고 쿼리와 일치하는 줄 목록을 생성합니다. search라는 함수에이 기능을 추가 할 것입니다.

실패한 테스트 만들기Create a failing test

에서 src/lib.rs 파일에서우리는 추가 할 것이다. a tests 테스트 함수를 가진 모듈, 우리가했던 것처럼 제 11 장 무시 . 테스트 함수는 우리가 원하는 동작을 지정합니다. search function to have: 쿼리와 텍스트를 검색에 가져오고 쿼리를 포함하는 텍스트의 줄만 반환합니다. Listing 12-15는 이 테스트를 보여줍니다.

이 테스트는 문자열 "duct"를 검색합니다. 우리가 찾고 있는 텍스트는 세 줄이며, 그 중 하나만 "duct"를 포함합니다 (개방된 이중 따옴표 이후의 백슬래시는 러스트에게 이 문자열 리터럴의 내용의 시작 부분에 줄바꿈 문자를 넣지 말 것을 지시합니다). 우리는 search 함수에서 반환된 값이 우리가 예상하는 줄만 포함한다고 주장합니다.

이 테스트를 실행하면 현재 실패합니다. unimplemented! "not implemented"라는 메시지와 함께 매크로 패닉. TDD 원칙에 따라 함수를 정의하여 함수를 호출 할 때 테스트를 패닉하지 않도록 충분한 코드를 추가하는 작은 단계를 취할 것입니다. search 함수는 항상 빈 벡터를 반환합니다. Listing 12-16과 같습니다. 그런 다음 빈 벡터가 라인을 포함하는 벡터와 일치하지 않기 때문에 테스트를 컴파일하고 실패해야 합니다. "safe, fast, productive.".

이제 왜 우리가 명백한 평생을 정의해야하는지 논의 해 봅시다. 'a 상기 서명하는 단계는, In the signature, search [중고] 그 시절을 활용하라 contents 인수 및 반환 값입니다. 제 10 장 무시 lifetime 매개 변수는 반환 값의 수명과 연결된 인수 수명을 지정합니다. 이 경우 반환 된 벡터에는 인수의 슬라이스를 참조하는 문자열 조각이 포함되어야 함을 나타냅니다. contents (논란이 아닌 경우) query).

다시 말해, 러스트는 러스트에 의해 반환된 데이터를 말합니다. search 이 함수는 데이터가 전달되는 동안 search 에서의 기능 contents 인수. 이것은 중요합니다! 참조 된 데이터 에 의해 참조가 유효하려면 슬라이스가 유효해야 합니다; 컴파일러가 우리가 문자열 슬라이스를 만들고 있다고 가정하면 query 보다는 contents즉, 보안 검사를 잘못 수행 할 것입니다.

우리가 평생 주석을 잊어 버리고이 함수를 컴파일하려고하면, 우리는이 오류를 얻을 것이다 :

러스트는 출력에 필요한 두 매개 변수 중 어느 것을 알 수 없으므로 명시 적으로 알려야합니다. 도움말 텍스트는 모든 매개 변수와 출력 유형에 대해 동일한 평생 매개 변수를 지정할 것을 제안합니다. 잘못된 것입니다! contents는 모든 텍스트를 포함하는 매개 변수이며 일치하는 텍스트의 일부를 반환하려는 것이므로 contents는 평생 동안 연결해야하는 유일한 매개 변수입니다.

다른 프로그래밍 언어에서는 서명에서 값을 반환하기 위해 인수를 연결할 필요가 없지만이 연습은 시간이 지남에 따라 더 쉬워집니다. 이 예제를 10 장의 “평생 참고할 만한 것 들” 섹션의 예제와 비교할 수 있습니다.

테스트를 통과하기 위한 코드 작성

현재 테스트가 실패하는 이유는 항상 빈 벡터를 반환하기 때문입니다. 이를 수정하고 search를 구현하려면 프로그램은 다음 단계를 따라야 합니다.

  1. 내용의 각 줄을 반복합니다.
  2. 줄에 쿼리 문자열이 포함되어 있는지 확인합니다.
  3. 만약 그렇다면, 우리가 반환하는 값의 목록에 추가하세요.
  4. 만약 그렇지 않다면, 아무것도 하지 마세요.
  5. 일치하는 결과 목록을 반환합니다.Return the list of results that match.

각 단계를 통해 작동 하자, 라인을 통해 반복 시작.

상기 라인들은 The lines with lines 메서드

러스트는 Listing 12-17과 같이 편리하게 lines라는 이름의 문자열을 line-by-line 반복 처리하는데 도움이 됩니다. 이것은 아직 컴파일되지 않습니다.

lines 메서드는 반복자를 반환합니다. 제 13 장에서 반복자에 대해 자세히 설명하겠습니다. 그러나 목록 3-5에서 반복자를 사용하는이 방법을 보았다는 것을 기억하십시오. 여기서 for 루프를 반복기와 함께 사용하여 컬렉션의 각 항목에 대한 코드를 실행합니다.

쿼리에 대한 각 줄 검색

다음으로 현재 줄에 쿼리 문자열이 포함되어 있는지 확인합니다. 다행히도 문자열에는 contains라는 유용한 메서드가 있습니다! 목록 12-18에 표시된 것처럼 contains 함수에서 search 메소드에 대한 호출을 추가하십시오. 아직 컴파일되지 않습니다.

현재 우리는 기능을 구축하고 있습니다. 코드를 컴파일하려면 함수 서명에서 표시된대로 본문에서 값을 반환해야합니다.

일치하는 줄 저장

이 함수를 완료하려면, 반환하고자 하는 일치하는 라인을 저장하는 방법이 필요합니다. 이를 위해, 우리는 for 루프 전에 가변 벡터를 만들고 push 메소드를 호출하여 line를 벡터에 저장합니다. for 루프 후에, Listing 12-19와 같이 벡터를 반환합니다.
