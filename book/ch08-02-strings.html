문자열이 얼마나 긴지 묻는다면, 12라고 말할 수 있습니다. 사실, 러스트의 대답은 24입니다: 그것이 UTF-8에서 “ ⁇ ”를 인코딩하는 데 걸리는 바이트 수입니다. 왜냐하면 그 문자열의 각 유니코드 스칼라 값은 2바이트의 저장 공간을 차지하기 때문입니다. 그러므로, 문자열의 바이트에 대한 인덱스는 항상 유효한 유니코드 스칼라 값과 관련이 있는 것은 아닙니다. 증명을 위해, 이 유효하지 않은 러스트 코드를 고려하십시오:

let hello = "Здравствуйте";
let answer = &hello[0];

이미 알고 계시죠 answer 없을 것이다. З, 첫 번째 문자. 여기에 6 개의 char 값이 있지만, 네 번째와 여섯 번째 문자는 문자가 아닙니다. 그들은 스스로 의미가없는 발음 부호입니다. 마지막으로, 우리가 grapheme 클러스터로 본다면, 우리는 사람이 힌디어 단어를 구성하는 네 글자를 얻을 것입니다.

["न", "म", "स्", "ते"]

러스트는 컴퓨터가 저장하는 원시 문자열 데이터를 해석하는 다양한 방법을 제공하므로 각 프로그램은 데이터가 어떤 인간 언어에 있든 필요한 해석을 선택할 수 있습니다.

러스트가 캐릭터를 얻기 위해 String로 인덱스를 만들 수 없는 마지막 이유는 인덱싱 작업은 항상 일정한 시간(O(1))이 걸릴 것으로 예상되기 때문입니다. 하지만 String로 성능을 보장할 수는 없습니다. 왜냐하면 러스트는 처음부터 인덱스까지 얼마나 많은 유효한 캐릭터가 있었는지를 결정하기 위해 컨텐츠를 통과해야 하기 때문입니다.

슬라이싱 문자열

문자열로 인덱싱하는 것은 종종 좋지 않은 생각입니다. 왜냐하면 문자열 인덱싱 작업의 반환 타입이 어떤 것인지 분명하지 않기 때문입니다: 바이트 값, 문자, grapheme cluster, 또는 문자열 슬라이스. 문자열 슬라이스를 만들기 위해 인덱스를 사용해야 한다면, 러스트는 여러분이 좀 더 구체적이기를 요청합니다.

[]를 단일 숫자로 인덱싱하는 대신, []를 범위와 함께 사용하여 특정 바이트를 포함하는 문자열 슬라이스를 생성할 수 있습니다.

#![allow(unused)]
fn main() {
let hello = "Здравствуйте";

let s = &hello[0..4];
}

여기서 s는 문자열의 첫 번째 4 바이트를 포함하는 &str입니다. 앞서 우리는이 문자들 각각이 2 바이트라고 언급했는데, 이는 s가 Зд임을 의미합니다.

만약 우리가 &hello[0..1]와 같은 문자 바이트의 일부만 슬라이스하려고 한다면, 러스트는 마치 벡터에서 유효하지 않은 인덱스에 접근한 것과 같은 방식으로 런타임에 패닉을 일으킬 것입니다:

$ cargo run
   Compiling collections v0.1.0 (file:///projects/collections)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.43s
     Running `target/debug/collections`

thread 'main' (6017738) panicked at src/main.rs:4:19:
end byte index 1 is not a char boundary; it is inside 'З' (bytes 0..2 of string)
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace

범위를 가진 문자열 슬라이스를 만들 때 주의해야 합니다, 그렇게 하면 프로그램이 충돌할 수 있기 때문입니다.

문자열 반복

문자열 조각으로 작업하는 가장 좋은 방법은 문자 또는 바이트를 원하는지 여부를 명시하는 것입니다. 개별 유니코드 스칼라 값의 경우 chars 메서드를 사용하십시오. “ ⁇ ”에서 chars를 호출하면 분리되어 두 가지 유형의 char 값을 반환하고 결과를 반복하여 각 요소에 액세스 할 수 있습니다.

#![allow(unused)]
fn main() {
for c in "Зд".chars() {
    println!("{c}");
}
}

이 코드는 다음을 출력합니다:

З
д

또는 bytes 메서드가 각 원시 바이트를 반환하므로 도메인에 적합할 수 있습니다.

#![allow(unused)]
fn main() {
for b in "Зд".bytes() {
    println!("{b}");
}
}

이 코드는 이 문자열을 구성하는 4 바이트를 인쇄합니다:

208
151
208
180

그러나 유효한 유니코드 스칼라 값은 1 바이트 이상으로 구성 될 수 있음을 기억하십시오.

Devanagari 스크립트와 마찬가지로 문자열에서 grapheme 클러스터를 가져 오는 것은 복잡하므로이 기능은 표준 라이브러리에서 제공하지 않습니다. 이것이 필요한 기능이라면 크레이트.io에서 크레이트를 사용할 수 있습니다.

끈 의 복잡성 을 다루는 일

요약하자면, 문자열은 복잡합니다. 다른 프로그래밍 언어들은 이 복잡성을 프로그래머에게 제시하는 방법에 대해 다른 선택을 합니다. 러스트는 String 데이터의 올바른 처리를 모든 러스트 프로그램의 기본 동작으로 만들기로 선택했습니다. 즉, 프로그래머는 UTF-8 데이터를 처리하기 위해 더 많은 생각을 해야 합니다. 이 트레이드오프는 다른 프로그래밍 언어에서 보이는 것보다 문자열의 복잡성을 더 많이 드러내지만, 나중에는 CI와 관련된 오류를 처리하지 못하게 합니다.

좋은 소식은 표준 라이브러리가 이러한 복잡한 상황을 올바르게 처리하는 데 도움이되는 String 및 &str 유형을 기반으로하는 많은 기능을 제공한다는 것입니다. contains와 같은 유용한 방법에 대한 설명서를 체크 아웃하십시오. 문자열의 일부를 다른 문자열로 대체하기위한 replace.
