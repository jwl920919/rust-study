The Rust Programming Language

한국어 기계 번역 초안입니다. Rust 코드와 인라인 코드 예제는 공식 최신 원문 그대로 보존했습니다. 번역 용어와 세부 문장은 계속 검토합니다.

변수와 가변성

'변수로 값 저장하기' 섹션에서 언급했듯이, 기본적으로 변수는 불변입니다. 이는 Rust가 제공하는 안전성과 쉬운 동시성을 활용하여 코드를 작성하도록 Rust가 주는 여러 가지 유도 중 하나입니다. 하지만 여전히 변수를 가변적으로 만들 수 있습니다. Rust가 왜 불변성을 선호하도록 권장하는지, 그리고 왜 때로는 가변성을 선택하고 싶은지를 살펴보겠습니다.

변수가 불변인 경우, 값이 이름에 바인딩된 후에는 그 값을 변경할 수 없습니다. 이를 설명하기 위해 cargo new variables를 사용하여 프로젝트 디렉토리에 variables라는 새 프로젝트를 생성합니다.

그런 다음, 새로 생성한 variables 디렉토리에서 src/main.rs 파일을 열고 코드를 아직 컴파일되지 않는 다음 코드로 교체합니다:

파일 이름: src/main.rs

fn main() {
    let x = 5;
    println!("The value of x is: {x}");
    x = 6;
    println!("The value of x is: {x}");
}

cargo run를 사용하여 프로그램을 저장하고 실행합니다. 다음 출력과 같이 불변성 오류에 대한 오류 메시지를 받게 됩니다:

$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
error[E0384]: cannot assign twice to immutable variable `x`
 --> src/main.rs:4:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
3 |     println!("The value of x is: {x}");
4 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++

For more information about this error, try `rustc --explain E0384`.
error: could not compile `variables` (bin "variables") due to 1 previous error

이 예제는 컴파일러가 프로그램의 오류를 찾는 데 어떻게 도움이 되는지 보여줍니다. 컴파일러 오류는 좌절감을 줄 수 있지만, 실제로는 프로그램이 아직 원하는 대로 안전하게 동작하지 못하고 있다는 의미일 뿐입니다. 이것이 여러분이 좋은 프로그래머가 아니라는 뜻은 아닙니다! 숙련된 Rustacean들도 여전히 컴파일러 오류를 경험합니다.

불변 변수인 cannot assign twice to immutable variable `x`에 두 번째 값을 할당하려고 했기 때문에 'cannot assign twice to immutable variable `x`'라는 오류 메시지를 받았습니다. x

변경 불가능으로 지정된 값을 변경하려고 할 때 컴파일 타임 오류가 발생해야 하는 이유는, 이러한 상황이 버그로 이어질 수 있기 때문입니다. 코드의 한 부분이 값이 절대 변하지 않는다고 가정하고 작동하는 동안 다른 부분이 그 값을 변경하면, 첫 번째 부분은 원래 의도한 대로 작동하지 않을 수 있습니다. 특히 두 번째 코드가 값을 일부 상황에서만 변경하는 경우, 이러한 버그의 원인을 사후에 추적하기가 매우 어렵습니다. Rust 컴파일러는 값이 변하지 않는다고 선언하면 실제로 변하지 않는다고 보장하므로, 스스로 이를 추적할 필요가 없습니다. 따라서 코드를 이해하고 추론하기가 더 쉬워집니다.

그러나 가변성은 매우 유용하고 코드를 작성하는 것이 더 편리 할 수 있습니다. 변수는 기본적으로 변경할 수 없지만 mut에서했던 것처럼 변수 이름 앞에 제 2 장를 추가하여 변경할 수 있습니다. mut를 추가하면 코드의 다른 부분이이 변수의 값을 변경한다는 것을 나타내어 미래의 코드 독자에게 의도를 전달할 수 있습니다.

예를 들어, src/main.rs를 다음과 같이 변경해 보겠습니다.

파일 이름: src/main.rs

fn main() {
    let mut x = 5;
    println!("The value of x is: {x}");
    x = 6;
    println!("The value of x is: {x}");
}

이제 프로그램을 실행하면 다음과 같은 결과가 나옵니다.

$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.30s
     Running `target/debug/variables`
The value of x is: 5
The value of x is: 6

mut이 사용될 때 x에 바인딩된 값을 5에서 6로 변경하는 것이 허용됩니다. 결국 가변성을 사용할지 여부는 여러분에게 달려 있으며, 해당 상황에서 가장 명확하다고 판단하는지에 따라 결정됩니다.

상수 선언하기

변경 불가능한 변수와 마찬가지로 상수는 이름에 바인딩된 값이며 변경이 허용되지 않지만, 상수와 변수 사이에는 몇 가지 차이점이 있습니다.

첫째, 사용할 수 없습니다. mut constants를 사용합니다. Constants는 기본적으로 불변일 뿐만 아니라 항상 불변입니다. const 키워드 대신 let keyword, 그리고 값의 타입 필수 주석을 달겠습니다. 다음 섹션에서는 타입과 타입 주석을 다룰 것입니다. “데이터 유형” 무시 , 그래서 지금 세부 사항에 대해 걱정하지 마십시오. 항상 유형에 주석을 추가해야한다는 것을 알고 있습니다.

상수는 전역 범위를 포함하여 모든 범위에서 선언할 수 있습니다. 이는 코드의 여러 부분이 알아야 하는 값에 상수를 사용하는 데 유용합니다.

마지막 차이점은 상수가 상수 표현식으로만 설정될 수 있다는 점입니다. 런타임에 계산되어야 하는 값의 결과는 사용할 수 없습니다.

다음은 상수 선언의 예입니다.

#![allow(unused)]
fn main() {
const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3;
}

상수의 이름은 THREE_HOURS_IN_SECONDS이며, 그 값은 60(1분에 포함된 초 수)에 60(1시간에 포함된 분 수)을 곱한 값에 3(이 프로그램에서 계산하려는 시간 수)을 곱한 결과로 설정됩니다. Rust의 상수 명명 규칙은 모든 대문자를 사용하고 단어 사이에 밑줄을 넣는 것입니다. 컴파일러는 컴파일 시점에 제한된 연산 집합을 평가할 수 있으므로, 이 상수의 값을 10,800으로 직접 설정하는 대신 이해하고 검증하기 쉬운 방식으로 값을 작성할 수 있습니다. 상수를 선언할 때 사용할 수 있는 연산에 대한 자세한 내용은 Rust Reference의 상수 평가 섹션을 참고하세요. Rust Reference의 상수 평가 설명

상수는 프로그램이 실행되는 동안 선언된 범위 내에서 항상 유효합니다. 이 특성 덕분에 상수는 게임에서 플레이어가 얻을 수 있는 최대 점수나 빛의 속도처럼, 프로그램의 여러 부분이 알아야 할 애플리케이션 도메인의 값에 유용합니다.

프로그램 전체에서 사용되는 하드코딩된 값을 상수로 명명하면, 해당 값의 의미를 향후 코드 유지보수자에게 전달하는 데 도움이 됩니다. 또한 나중에 하드코딩된 값을 업데이트해야 하는 경우, 코드의 한 곳만 변경하면 되므로 유지보수가 용이해집니다.

섀도잉

2장에서 다룬 추측 게임 튜토리얼에서 보았듯이, 이전 변수와 동일한 이름으로 새로운 변수를 선언할 수 있습니다. Rustacean들은 이를 첫 번째 변수가 두 번째 변수에 의해 그림자 처리(shadowed)되었다고 표현합니다. 즉, 변수 이름을 사용할 때 컴파일러가 두 번째 변수를 인식한다는 뜻입니다. 결과적으로 두 번째 변수는 첫 번째 변수를 가리고, 두 번째 변수가 다시 그림자 처리되거나 스코프가 끝날 때까지 해당 변수 이름의 모든 사용처를 자신에게 귀속시킵니다. 다음과 같이 let 키워드를 반복 사용하면서 동일한 변수 이름을 사용하여 변수를 그림자 처리할 수 있습니다: 2장let

파일 이름: src/main.rs

fn main() {
    let x = 5;

    let x = x + 1;

    {
        let x = x * 2;
        println!("The value of x in the inner scope is: {x}");
    }

    println!("The value of x is: {x}");
}

이 프로그램은 먼저 x에 값 5를 바인딩합니다. x5xlet x =1x6 그런 다음, 중괄호로 생성된 내부 스코프 내에서 세 번째 let 문도 x를 그림자 처리하여 새로운 변수를 생성합니다. 이때 이전 값에 2를 곱하여 x의 값을 12로 만듭니다. letx2x12 그 스코프가 끝나면 내부 그림자 처리가 종료되고 x는 다시 6이 됩니다. x6 이 프로그램을 실행하면 다음과 같이 출력됩니다:

$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.31s
     Running `target/debug/variables`
The value of x in the inner scope is: 12
The value of x is: 6

그림자 처리(shadowing)는 변수를 mut로 표시하는 것과 다릅니다. mutlet 키워드를 사용하지 않고 실수로 이 변수에 재할당을 시도하면 컴파일 타임 오류가 발생합니다. let를 사용하면 값에 대해 몇 가지 변환을 수행하되, 변환이 완료된 후에는 변수를 불변(immutable)으로 유지할 수 있습니다.

mut와 그림자 처리(shadowing)의 또 다른 차이점은 let 키워드를 다시 사용할 때 사실상 새로운 변수를 생성하기 때문에, 값의 타입을 변경하더라도 동일한 이름을 재사용할 수 있다는 것입니다. 예를 들어, 프로그램이 사용자에게 텍스트 사이에 원하는 공백 수를 공백 문자로 입력하도록 요청하고, 그 입력을 숫자로 저장하려고 한다고 가정해 보겠습니다: mutlet

fn main() {
    let spaces = "   ";
    let spaces = spaces.len();
}

첫 번째 spaces 변수는 문자열 타입이고, 두 번째 spaces 변수는 숫자 타입입니다. spacesspaces 따라서 그림자 처리(shadowing)를 사용하면 spaces_str이나 spaces_num과 같이 다른 이름을 발명할 필요가 없습니다. spaces_strspaces_num 대신, 더 간단한 spaces 이름을 재사용할 수 있습니다. spaces 그러나 여기에서 보여준 것처럼 mut를 사용하려고 하면 컴파일 타임 오류가 발생합니다: mut

fn main() {
    let mut spaces = "   ";
    spaces = spaces.len();
}

이 오류는 변수의 타입을 변경하는 것이 허용되지 않는다고 알려 줍니다:

$ cargo run
   Compiling variables v0.1.0 (file:///projects/variables)
error[E0308]: mismatched types
 --> src/main.rs:3:14
  |
2 |     let mut spaces = "   ";
  |                      ----- expected due to this value
3 |     spaces = spaces.len();
  |              ^^^^^^^^^^^^ expected `&str`, found `usize`

For more information about this error, try `rustc --explain E0308`.
error: could not compile `variables` (bin "variables") due to 1 previous error

이제 변수가 어떻게 작동하는지 살펴봤으므로, 변수가 가질 수 있는 더 많은 데이터 타입을 살펴보겠습니다.
