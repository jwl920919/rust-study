부록 M. Rust에서 AI 모델 활용하기

Rust 프로그램에서 AI 모델을 활용한다는 말은 한 가지 기술만을 뜻하지 않습니다. 다른 서버가 제공하는 모델 API를 호출하거나, 모델을 내 컴퓨터나 서비스 안에서 직접 추론하거나, 신경망을 학습하는 방법이 있습니다. 대부분의 애플리케이션은 처음부터 모델을 학습하기보다 이미 학습된 모델을 호출해 필요한 작업을 처리합니다.

API 방식은 Rust 코드에서 reqwest로 HTTP 통신을 하고 serde로 JSON 요청과 응답을 표현하는 식으로 시작할 수 있습니다. 여러 모델 공급자의 차이를 추상화하려면 Rig 같은 Rust LLM 애플리케이션 라이브러리를 살펴볼 수 있습니다. 자체 추론에서는 Candle이 Rust의 텐서 연산과 모델 실행 기반을 제공하며, Burn은 모델 구성부터 학습과 추론까지 다루는 Rust 딥러닝 프레임워크입니다. 모델을 직접 학습하는 일은 API를 한 번 호출하는 것보다 데이터·실험 관리가 더 많이 필요합니다.

예제: 로컬 Ollama 모델에 질문 보내기

아래 예제는 Ollama의 OpenAI 호환 채팅 API에 요청을 보내고 응답 텍스트를 출력합니다. 모델과 Ollama 서버는 로컬 컴퓨터에서 실행되며 외부 모델 API 키가 필요하지 않습니다. 먼저 Ollama를 설치하고 터미널에서 모델을 내려받아 서버를 실행하세요. 예제의 기본 모델 이름이 설치한 모델과 다르면 OLLAMA_MODEL 환경 변수에 실제 이름을 지정합니다.

ollama pull llama3.2
export OLLAMA_MODEL=llama3.2

Windows PowerShell에서는 환경 변수를 $env:OLLAMA_MODEL="llama3.2"로 지정합니다. Ollama 앱이나 서비스가 실행 중인지 확인하세요.

Cargo.toml에 HTTP 클라이언트, JSON 직렬화, 비동기 런타임 의존성을 추가합니다. Reqwest의 버전과 기능은 프로젝트에서 사용하는 Rust 버전에 맞춰 선택하세요.

[dependencies]
reqwest = { version = "0.13", features = ["json"] }
serde = { version = "1", features = ["derive"] }
tokio = { version = "1", features = ["macros", "rt-multi-thread"] }

다음 코드는 로컬 서버에 한 번 요청하고, HTTP 오류와 JSON 형식 오류를 Result로 전파합니다. 전체 JSON을 임의 값으로 처리하는 대신 이 응답에서 필요한 필드만 구조체로 표현했습니다.

use serde::{Deserialize, Serialize};
use std::{env, error::Error, time::Duration};

#[derive(Serialize)]
struct Message {
    role: String,
    content: String,
}

#[derive(Serialize)]
struct ChatRequest {
    model: String,
    messages: Vec<Message>,
    stream: bool,
}

#[derive(Deserialize)]
struct ChatResponse {
    choices: Vec<Choice>,
}

#[derive(Deserialize)]
struct Choice {
    message: MessageContent,
}

#[derive(Deserialize)]
struct MessageContent {
    content: String,
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn Error>> {
    let model = env::var("OLLAMA_MODEL").unwrap_or_else(|_| "llama3.2".to_owned());
    let request = ChatRequest {
        model,
        messages: vec![Message {
            role: "user".to_owned(),
            content: "Rust의 소유권을 한 문장으로 설명해 줘.".to_owned(),
        }],
        stream: false,
    };

    let response = reqwest::Client::builder()
        .timeout(Duration::from_secs(60))
        .build()?
        .post("http://localhost:11434/v1/chat/completions")
        .json(&request)
        .send()
        .await?
        .error_for_status()?
        .json::<ChatResponse>()
        .await?;

    let answer = response
        .choices
        .first()
        .ok_or("모델이 응답 선택지를 반환하지 않았습니다")?;
    println!("{}", answer.message.content);
    Ok(())
}

이 코드는 서버가 같은 컴퓨터의 기본 주소와 포트에서 실행 중이라는 가정이 있습니다. 연결이 거부되면 Ollama가 실행 중인지, 포트와 모델 이름이 맞는지 확인하세요. 응답 내용은 모델과 버전에 따라 달라지고 사실과 다를 수 있습니다. 서비스를 만들 때는 빈 응답, 시간 초과, 서버 오류, 토큰·요청 한도 등을 사용자에게 적절히 처리하고 모델 출력을 검증해야 합니다.

이 예제는 네트워크를 사용하는 실행 코드이므로 책 페이지의 Rust Playground 실험실에서는 실행할 수 없습니다. 로컬 Rust 프로젝트를 만들고 Cargo 의존성을 설치한 뒤 Ollama 서버와 내려받은 모델을 준비해야 합니다. 로컬 모델도 파일 크기가 크고 메모리·GPU 자원을 사용할 수 있으며, 모델별 이용 조건은 해당 모델의 라이선스를 확인하세요.

임베딩, RAG와 도구 호출

생성형 모델은 학습 데이터에 없는 최신 문서나 사내 데이터에 자동으로 접근하지 않습니다. 임베딩(embedding)은 텍스트를 의미적 유사도를 계산할 수 있는 숫자 벡터로 바꾸는 방법입니다. 문서 검색 시스템은 문서를 작은 단위로 나누고 임베딩을 계산해 벡터 저장소에 보관한 다음, 질문과 가까운 문서 조각을 찾아 모델 입력에 포함합니다. 이처럼 검색 결과를 생성 단계에 제공하는 흐름을 검색 증강 생성(RAG)이라고 합니다. Rust 애플리케이션은 텍스트 분할, 저장소 질의, 권한 확인, 출처 표시를 조정하고 임베딩·생성은 외부 API나 로컬 모델에 맡길 수 있습니다.

도구 호출(tool calling)은 모델이 정해진 형식의 동작 요청을 반환하고 애플리케이션이 그 요청을 해석해 함수를 실행하는 방식입니다. 모델이 코드를 생성했다고 해서 그 코드를 자동 실행하지 마세요. 도구 이름과 인자를 구조체로 역직렬화하고, 허용 목록과 타입·범위·권한을 검증한 뒤 실제 동작을 수행합니다. 파일 삭제, 결제, 계정 변경처럼 영향이 큰 작업은 별도의 사용자 승인과 감사 기록을 두어야 합니다.

실제 서비스에서 점검할 항목

  • 호스팅 API 키는 서버 환경 변수나 비밀 관리 시스템에서 읽고 저장소, 브라우저 코드, 공개 Playground 코드에 넣지 않습니다. 요청에 개인 정보나 비밀이 포함되는지도 확인합니다.
  • 모델에 보내는 입력과 반환되는 텍스트는 신뢰된 프로그램 코드가 아닙니다. 출력 형식, 길이, 업무 규칙을 애플리케이션에서 검증합니다.
  • 타임아웃과 재시도 정책을 세우고, 요청을 재시도하면 중복 과금이나 중복 작업이 생기는지 살핍니다. 비동기 요청을 무제한으로 쌓지 말고 동시성과 입력 크기를 제한합니다.
  • 모델 이름·버전, 프롬프트, 라이브러리 기능은 바뀔 수 있습니다. 재현이 필요한 작업은 설정을 기록하고 대표 입력에 대한 평가를 지속적으로 수행합니다.
  • 외부 제공자의 데이터 보관·학습 정책과 모델 가중치의 라이선스는 각각 확인합니다. 오픈 가중치라는 표현만으로 모든 상업적 사용이 허용되는 것은 아닙니다.

선택한 도구의 API와 버전별 기능은 Rig 저장소, Candle 저장소, Burn 문서, Ollama API 호환성 안내에서 확인하세요. 프레임워크는 빠르게 변하므로 이 부록은 접근 방식과 설계 원칙을 중심으로 읽고, 구체적인 버전과 모델 이용 조건은 실제 도입 시점에 다시 점검하세요.
